# 参考手册

本手册讲"整套系统怎么用"：怎么起、怎么注册、怎么调、返回怎么读、文件与超时怎么算、出问题怎么查。
**具体业务操作（建库、画图、仿真……）的每个参数在《业务包说明书》里**，本文不重复。

## 1. 系统长什么样

一句话：**把你对 Virtuoso 的操作变成一次 HTTP 请求**。

系统分两个面，各自监听一个端口：

| 面 | 默认端口 | 做什么 | 谁用 |
|---|---|---|---|
| 控制面 | `127.0.0.1:8124` | 注册、用户管理、全局配置、业务进程管理 | 人（浏览器）与运维 |
| 业务面 | `127.0.0.1:8127` | 执行具体业务操作 | 程序调用 |

两个面可以同进程（`--single-process`）也可以分成父子进程（默认），后者在业务崩溃时不影响控制面。

### 1.1 操作在哪台机器上执行

注册时会为这几类操作分别指定目标机器（不指定就都用同一台）：

| 角色 | 执行什么 |
|---|---|
| GUI 主机 | Virtuoso 的 CIW 与窗口（截屏、发按键） |
| daemon 主机 | Skill 执行（在 Virtuoso 进程里） |
| command 主机 | 普通 shell 命令（`basic.command.run`） |
| file 主机 | 文件上传/下载的落点 |
| Spectre 主机 | 独立 Spectre 仿真命令 |

对你的影响只有一个：**路径和工具要在对应那台机器上存在**。调用方（本机）与目标机器是两套文件系统。

## 2. 环境要求

| 位置 | 要求 |
|---|---|
| 调用方 | Python ≥ 3.9（只走 HTTP 的话，任何语言都行） |
| 目标机器 | 能免密 SSH 登录；跑 daemon 需要 Python 2.7+ 或 3.6.8+ |
| Virtuoso | 已在目标机器上运行（要用 Skill/画图才需要） |
| Spectre / Calibre | 在目标机器 PATH 里（要跑仿真/验证才需要） |

## 3. 安装、启动与停止

### 3.1 安装（一次性）

```bash
uv venv .venv && uv pip install -e .
```

### 3.2 启动（标准形态：一条命令起双面）

```bash
python -m server.supervisor --control-port 8124 --business-port 8127 --work-dir <工作目录>
```

可选参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--control-host` / `--control-port` | `127.0.0.1` / `8124` | 控制面监听地址与端口 |
| `--business-host` / `--business-port` | `127.0.0.1` / `8127` | 业务面监听地址与端口 |
| `--work-dir` | 平台默认配置目录 | 注册表与配置文件的存放目录 |
| `--single-process` | 关 | 两个面跑在同一进程（`restart` 不可用，返回 501） |

### 3.3 其它启动方式

```bash
# 只要注册页（控制面），业务面另起
python -m register.server --host 127.0.0.1 --port 8124 --work-dir <工作目录>

# 单独起业务面（需要 registry.json 已经在工作目录里）
python -m server.api_server --host 127.0.0.1 --port 8127 --work-dir <工作目录>
```

> 安装后还有一个命令行入口 `virtuoso-bridge`，它等价于 `python -m register.server`（**只起控制面**，
> 不带业务面）。要一条命令起双面，用 §3.2 的 `server.supervisor`。

> 单独起的业务面**不会**自动重新加载注册表；注册了新用户后要么用 supervisor 形态，
> 要么调 `POST /api/process/reload`，要么重启业务面。

### 3.4 停止

在启动终端按 `Ctrl+C`。父子形态下，管理进程退出会带停业务子进程。

## 4. 注册与用户

### 4.1 六步注册

| 步 | 谁做 | 内容 | 失败后 |
|---|---|---|---|
| ① 申请 apply | 用户填 | 用户名、模式（本地/远程）、主机与 SSH 凭据、token（可留空） | 改参数重新申请 |
| ② 本地校验 validate | 程序 | 查重名、端口占用、凭据占用 | 原样重试；要改参数先 `cancel` |
| ③ 探测 probe | 程序 | 逐角色探测 SSH、目录可写、工具可用，并把根目录写成绝对路径 | 原样重试 |
| ④ 部署 deploy | 程序 | 部署 bridge 文件，产出 `setup_path` | 覆盖式重试 |
| ⑤ 连通性 verify | 用户 + 程序 | **用户在 CIW 里 `load(setup_path)`**，然后页面测连通与 token | 可原地重试 |
| ⑥ 写注册表 commit | 用户确认 | 唯一写盘点；token 从此生效 | 可原地重试 |

- 前五步不落盘；`cancel` 可以随时放弃这次注册（候选只在内存里）。
- 第 4→5 步之间需要**人工**在 CIW 里执行那行 `load(...)`，这一步不占超时。
- token 由用户指定或服务端生成，规则：`^[A-Za-z0-9._-]{1,64}$`；终生有效，**轮换 = 删除该用户重新注册**。
- 授权的本质是"目视确认"：部署时 token 被写进 setup 文件，用户 `load` 时 CIW 会打印 token，对得上才算授权。

### 4.2 用户条目

每条用户记录包含：token、模式、各角色主机/凭据/根目录、运行参数（线程预算等）、日志参数、注册时间。
注册页可以查看（token 会脱敏）。读取与修改有两条路径：**管理员**（管理权限）与**本人自助**（personal token）：

| 操作 | 端点 | 权限 |
|---|---|---|
| 查用户列表 | `GET /api/users` | 管理权限 |
| 查单个条目 | `GET /api/user/<user>` | 管理权限；或**本人 personal token**（读本人、剔除保密字段；读他人 403） |
| 改条目 | `POST /api/user/<user>/update` | 管理权限；或**本人 personal token**（除 `token`/`registered_at` 外可改；"只读"字段需再带管理员 token 作 `enhanced_token`；"保密"字段仅管理权限） |
| 删除条目 | `DELETE /api/user/<user>` | 仅管理权限 |

> **本机删除 ≠ 远端吊销**：删除只解除本机登记，远端 daemon 仍接受原 token，直到在 CIW 里
> `RBStop()` 并清理部署文件。

### 4.3 管理权限

**token 怎么带**：个人 token 与管理员 token 都放请求头 `Authorization: Bearer <token>`
（例外：`/api/bug` 的个人 token 仍放请求体）。管理类端点（用户列表、删除用户、全局配置、业务进程管理）需要管理员 token：

```
Authorization: Bearer <管理员 token>
```

服务端只保存其哈希；管理操作会留下审计记录（不含凭据）。

## 5. 调用接口（业务面）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/operation` | 执行一个业务操作 |
| GET | `/health` | 存活与在途统计 |
| GET | `/help` | 给人看的上手（quickstart）文本 |
| GET | `/help/operations` | 操作清单 / 单个操作的详情（见 §5.2） |

控制面同样提供 `GET /help`：返回**注册流程说明**文本（同 quickstart 性质）。帮助端点**都不需要鉴权**，
也不会回显主机名、绝对路径或注册表内容。

### 5.2 帮助端点：`/help/operations`

帮助分三档，都返回统一壳 `{ok, data, error}`：

| 档 | 请求 | `data` 内容 |
|---|---|---|
| 上手文本（人） | `GET /help`（两面各一份） | 业务面：quickstart；控制面：注册流程说明 |
| 操作清单（人+机） | `GET /help/operations` | `{count, groups}`：按包分组，每个操作给 `{name, summary}`（`summary` 取自手册标题 `—` 后的短标题） |
| 操作详情（人+机） | `GET /help/operations?name=<操作名>` | `{name, package, method, required_fields, request_schema, doc, content_format, common_ref, common, content}`；`request_schema` 是该操作的 JSON schema，`content`/`common` 是手册原文 |

可选参数与行为：

| 项 | 说明 |
|---|---|
| `group=<包名>` | 清单只返回该包的操作 |
| `common=0` | 详情里省略公共约定段（`common`） |
| 未知操作名 | `404`（只报未知，不给近邻候选） |
| 手册不可用 | **降级**：仍返回 schema 与 `doc` 定位，`content` 省略并附 `content_unavailable` 原因，不报错 |
| 兼容 | 业务面早期版本返回的 `operations` 清单字段保留在 `data` 内，新增字段是增量 |

请求体：

```json
{"operation": "<业务操作名>", "token": "<个人 token>", "……": "该操作的业务字段"}
```

`Content-Type` 用 `application/json`；`operation` 与 `token` 必填，其余字段按各操作的要求给。

### 5.1 状态码：只表达"请求能不能被受理"

| HTTP | 含义 | 响应体 |
|---|---|---|
| 200 | 请求被受理（**业务可能成功也可能失败**，看 `ok`） | 正常响应壳 |
| 400 | JSON 非法、缺 `operation`/`token`、字段类型/取值错 | `ok=false`，`data=null` |
| 404 | 未知操作名（或未知路径） | `ok=false` |
| 405 | 对已定义路径用了不支持的方法 | `ok=false` + `Allow` |
| 413 | 请求体过大（**控制面与业务面都是 16 MiB 上限**） | `ok=false` |
| 429 | 服务在途请求超上限，**不排队**，带 `Retry-After: 1` | `ok=false` |
| 5xx | 未预期异常（单请求失败不影响其他请求） | `ok=false`，不带调用栈 |

## 6. 返回与错误

### 6.1 响应壳

```json
{"ok": true, "data": {"ok": true, "error": null, "value": {}}, "error": null}
```

- 外层 `ok`：与 HTTP 状态码一致地表达"受理 + 业务是否成功"。
- `data`：业务结果本体；业务失败时 `data.ok=false`、`error` 是摘要，并保留 `steps` 过程痕迹。
- **`steps` 默认不出现**：只有请求里带 `step_details: true`，或者操作失败（`data.ok=false`）时才返回。
  出现时每项是 `{"name", "ok", "detail"}`；`detail` 是排查的第一手材料（命令的 `stdout/stderr/returncode/kind`、SKILL 返回等）。

### 6.1.1 每次调用都支持的公共可选参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `timeout` | 数字 | `30` | 端到端超时（秒） |
| `step_details` | bool | `false` | 成功响应里是否也带 `steps` |
| `log_level` | str | 注册表默认 | 本次调用的 CDS.log 采集级别（`off`/`all`/`warn`/`error`）；只对执行 SKILL 的操作有效 |
| `log_max_bytes` | int | 注册表默认 | 本次调用的 CDS.log 长度上限（字节） |

### 6.2 结果放在哪个字段

| 情况 | 位置 |
|---|---|
| 多数业务包（cellview / schematic / symbol / layout / maestro / verilog / veriloga / spectre / calibre） | `data.value` |
| `basic.*`（直连底层） | `data.result`（其中 SKILL 结果的日志键是 `CDSlog`） |
| 截屏（schematic / gui） | `data.local_path` |
| 截屏（symbol / layout） | `data.value.local_path` |
| `virtuoso.skillref.*` | `data.results` / `data.plain_text` 等专用字段 |

### 6.3 命令类结果的 `kind`

命令类（`basic.command.run`、文件传输、`basic.gui.run`、`basic.spectre.run`）的结果里有 `kind`，
它比 `returncode` 更可靠——只有 `kind=command` 时 `returncode` 才是命令自己的退出码：

| kind | 含义 | 保留码 |
|---|---|---|
| `command` | 真实命令执行完毕 | 命令自身退出码 |
| `timeout` | 超时 | 124 |
| `transport` | 建连/断连等传输失败 | 255 |
| `path` | 路径不可见/类型不符（`stderr` 含 `VB-PATH-NOT-VISIBLE:`） | ≠0 |
| `unknown-effect` | 结果未知，**可能已产生副作用** | 255 |
| `rejected` | 容量拒绝（线程/通道/角色会话数超限） | 1 |
| `checksum` | 文件校验和不一致（`sha256 mismatch`） | 1 |
| `invalid-token` | token 不认识 | 1 |

### 6.4 超时与"结果未知"

- 每次调用只有**一条**端到端预算（`timeout` 不给就是 30 秒）；内部阶段只消耗剩余预算。
- **Skill 超时对外一律视为"结果未知"**：不提供"是否已投递"的观察字段。
- 本地 shell 读到 EOF（远端会话异常结束）同样按"结果未知"返回，不要当成空结果；
  目标 daemon 正忙时返回的是"**确认未投递**"（可安全重试），按返回里的 `kind`/`error` 文本区分。
- 写操作超时后**不要直接重发**：先读现状（`read` / `status` / `read_history`），再决定补一步还是重来。
- 可以安全重试的情况：`rejected`（容量拒绝）、明确的 `transport` 失败（连接还没建立）、HTTP 429。

## 7. 文件与路径

- `local_path`：**调用方**（你本机）的路径。
- 其它路径（`remote_path`、网表、GDS、日志……）：**目标机器**上的路径，Linux 风格。
- 相对路径：按对应角色的根目录解析（注册时探测出的绝对路径）；**绝对路径原样使用**。
- 上传/下载：`basic.file.upload` / `basic.file.download`；单文件默认，目录要 `recursive=true`。
- 落盘保证：先写临时文件 → 校验 SHA-256 → 原子替换；校验失败会删除临时文件、目标不变；目标已存在则覆盖。
- 符号链接按"跟随内容"处理；目录传输不做逐文件校验。
- 根目录**不是沙箱**：有权限就能访问其它路径，隔离靠操作系统账号。

常见错误：`VB-PATH-NOT-VISIBLE:`（路径在目标机器上不存在或类型不符）。

## 8. 超时、并发与容量

| 预算 | 默认 | 说明 |
|---|---|---|
| 单次调用超时 | 30 s | 每个接口一次调用一条预算，可用 `timeout` 覆盖 |
| 连接建立 | 15 s | 上面 30 s **之内**的子预算 |
| 每用户线程预算 | 32 | 同一用户的并发请求上限，超出直接拒绝 |
| 每用户通道预算 | 10 | 同一用户的并行通道（一次性命令、文件传输）上限 |
| 单角色最大会话 | 10 | 每个角色可同时使用的连接数 |
| 业务面在途上限 | 1024 | 服务整体上限，可经 `/api/config` 调整 |

- 同一个 CIW 的 Skill 请求**串行**执行；不同用户/不同 CIW 可以并行。
- `basic.command.run` 的 `parallel=true`、`spectre.run` 的 `max_workers`、文件传输天然并行。
- 容量不够时的表现：命令类结果 `kind=rejected`，`stderr` 指明是线程/通道/角色哪一种超限；服务整体超限则是 HTTP 429。

## 9. 日志

- Skill 调用的结果里带 **`CDSlog`** 字段：本次调用产生的 CDS.log 增量（按级别和长度裁剪）。
- 默认：`log_level=all`、`log_max_bytes=65536`；在注册条目里配置（`cdslog.log_level` / `cdslog.log_max_bytes`）。
- 单次调用可以临时覆盖：请求里带 `log_level` / `log_max_bytes`（只对执行 SKILL 的操作有效）。
- `log_level=off` 表示不采集该次 Skill 的日志（结果仍然返回）。
- 服务端自身运行日志在工作目录的 `log/` 下；报障时会随请求体一起归档（见 §10）。

## 10. 常见运维任务

| 任务 | 做法 |
|---|---|
| 看服务活着没 / 在看什么 | `GET /health`（业务面）、`GET /health`（控制面） |
| 看业务进程状态 | `GET /api/process/status`（管理权限） |
| 改全局并发上限 | `PUT /api/config`，请求体 `{"business_thread_pool_size": N}` |
| 改了用户配置要生效 | `POST /api/process/reload`（重新导入注册表与配置，关闭旧缓存连接） |
| 业务卡住/要复位 | `POST /api/process/restart`（拒绝新请求→等在途完成，上限 30 秒→重拉） |
| 报障 | `POST /api/bug`（控制面，带个人 token）：服务端会剥离凭据后存档请求体、提交人、时间与近期日志 |

## 11. 速查

### 11.1 端口

| 端口 | 用途 |
|---|---|
| 8124 | 控制面（注册页、管理端点） |
| 8127 | 业务面（`/api/operation`）——启动参数可改 |
| 8125 | 前端 Mock 演示页（只做界面演示，不连真实环境） |
| 8123 | SKILL 函数文档离线查询页 |

### 11.2 工作目录内容

| 文件/目录 | 内容 |
|---|---|
| `registry.json` | 用户注册表 |
| `config.json` | 全局配置（当前主要是业务面并发上限） |
| `log/` | 服务端日志、报障归档 |
| `temp/`、`artifact/` | 临时与产物目录 |

### 11.3 常用请求

```bash
# 有哪些操作
curl -s http://127.0.0.1:8127/help                       # 业务面 quickstart 文本
curl -s http://127.0.0.1:8127/help/operations            # 操作清单（按包分组）
curl -s "http://127.0.0.1:8127/help/operations?name=spectre.run"   # 单操作详情

# 跑一句 SKILL
curl -s http://127.0.0.1:8127/api/operation -H "Content-Type: application/json" \
  -d '{"operation":"basic.skill.execute","token":"TOKEN","skill_code":"1+2"}'
```

## 12. 术语表

| 词 | 含义 |
|---|---|
| 控制面 | 注册与管理用的 HTTP 服务（默认 8124） |
| 业务面 | 执行业务操作用的 HTTP 服务（默认 8127） |
| 业务操作 | 一个 `operation` 名 + 一组参数，例如 `virtuoso.schematic.write` |
| 业务包 | 一组相关业务操作的集合（schematic / layout / maestro……） |
| token | 每次调用必带的凭据，同时决定请求路由到哪个用户 |
| CIW | Virtuoso 的命令窗口，Skill 的执行环境 |
| daemon | Virtuoso 进程里常驻的桥接进程，接收并执行 Skill |
| 角色（role） | gui / daemon / command / file / spectre 五类目标机器 |
| 根目录（root） | 某个角色的默认工作目录，相对路径基于它解析 |
| 工作目录（work-dir） | 服务端存放注册表、配置与日志的目录 |
| 结果未知 | 超时或连接中断导致"是否已执行"无法确定，需人工/程序核实 |
