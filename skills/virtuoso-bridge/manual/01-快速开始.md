# 快速开始

目标：**用最短的路径**把服务跑起来、注册完成、发出第一个成功的请求。
全程只需要一条启动命令 + 一次网页注册。

## 0. 开始之前，先确认三件事

| 检查项 | 怎么确认 | 不满足怎么办 |
|---|---|---|
| 目标机器上 Virtuoso 已经在运行 | 在那台机器上能看到 Virtuoso 的 CIW 窗口 | 先启动 Virtuoso |
| 本机能免密 SSH 到那台机器 | 本机执行 `ssh <主机名> echo ok` 能直接返回 | 先配好 SSH 密钥（`~/.ssh/config` 里起个别名最省事） |
| 本机 Python ≥ 3.9 | `python --version` | 升级 Python 或换一个 ≥3.9 的解释器 |

> 上面三条是全部前提。Virtuoso 和 Spectre 是两件独立的事：只用 Spectre 跑仿真不需要 Virtuoso；
> 只用 Virtuoso 不跑仿真也不需要 Spectre。

## 1. 安装（一次性）

```bash
uv venv .venv
uv pip install -e .
```

Windows 上激活虚拟环境用 `.venv\Scripts\activate`，Linux/macOS 用 `source .venv/bin/activate`。
后面的命令默认都在这个虚拟环境里执行。

## 2. 启动服务（一条命令）

```bash
python -m server.supervisor --control-port 8124 --business-port 8127 --work-dir <工作目录>
```

- `--work-dir`：放注册表和工作文件的目录，随便指定一个你有写权限的路径；不指定会落到系统默认配置目录。
- 这条命令会同时起两个面：**控制面**（`http://127.0.0.1:8124`，注册页）和**业务面**（`http://127.0.0.1:8127`，干活用）。
- 端口可以改，改了就按改后的用；后面所有示例都按 8124 / 8127 写。
- 停止服务：在终端按 `Ctrl+C`。

验证一下：

```bash
curl -s http://127.0.0.1:8124/health
curl -s http://127.0.0.1:8127/health
```

两个都能返回 JSON 就说明服务起来了。

## 3. 注册（网页一次，五分钟）

浏览器打开 `http://127.0.0.1:8124/`，按页面提示填：

| 步骤 | 做什么 | 失败时 |
|---|---|---|
| ① 申请 | 填用户名、本地还是远程、目标主机、SSH 凭据、token（可留空自动生成） | 按提示改参数重新申请 |
| ② 本地校验 | 页面自动检查重名、端口占用、凭据是否已被别人登记 | 按提示换端口或换凭据 |
| ③ 探测 | 页面自动探测各主机是否可达、目录是否可写、工具是否在 | 按提示修 SSH / 目录权限 |
| ④ 部署 | 页面自动把必要文件部署到目标机器，并给出一行 `load("...")` | 按提示检查目录权限 |
| ⑤ 连通性 | **你要做动作**：把第 4 步那行 `load(...)` 粘到 Virtuoso 的 CIW 里执行，然后回到页面点测试 | 见下面"第 5 步过不去" |
| ⑥ 保存 | 点确认，写入注册表。**token 在此时生效** | 可原地重试 |

第 4 步打印的那行形如：

```
load("/home/<user>/.virtuoso-bridge/<用户名>/setup/virtuoso_setup.il")
```

CIW 里执行后，会在 Virtuoso 进程里拉起 bridge 的常驻进程；页面的连通性测试会同时验证
"能连上"和"token 对得上"。

**把 token 记下来**：注册时你填的（或页面生成的）那串就是后续每次调用要带的 token。
忘了可以在注册页的用户列表里查。

### 第 5 步过不去怎么办

| 页面提示 | 原因 | 处理 |
|---|---|---|
| 连不上 daemon | CIW 里那行 `load(...)` 没执行，或执行报错 | 回 Virtuoso 看 CIW 的报错；重新执行那行 |
| token 不匹配 | 加载的是别的用户/旧的 setup 文件 | 用页面给的那行重新加载 |
| 主机指纹不匹配 | 目标机器重装或换机 | 确认机器无误后，让管理员更新登记信息再测 |
| 命令/Skill 冒烟失败 | 目标机器上环境不完整 | 按页面提示检查命令可用性、CIW 是否能执行 SKILL |

## 4. 第一个请求

```bash
curl -s http://127.0.0.1:8127/api/operation \
  -H "Content-Type: application/json" \
  -d '{"operation":"basic.skill.execute","token":"<你的TOKEN>","skill_code":"1+2"}'
```

返回 `"ok": true` 且 `data.result.output` 是 `"3"`，就说明全链路通了。

Python 版本（只用标准库）：

```python
import json, urllib.request

BASE = "http://127.0.0.1:8127"
TOKEN = "<你的TOKEN>"

def call(operation, **fields):
    body = json.dumps({"operation": operation, "token": TOKEN, **fields}).encode()
    req = urllib.request.Request(
        BASE + "/api/operation", data=body,
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req) as resp:
        return json.loads(resp.read())

r = call("basic.skill.execute", skill_code="1+2")
print(r["ok"], r["data"]["result"]["output"])
```

## 5. 看看这台服务能干什么

```bash

```

返回里 `operations` 是这台服务当前可用的全部操作名（`data` 里的完整清单见《业务包说明书》）。

## 7. 卡住了先看这几条

| 现象 | 先检查 |
|---|---|
| `invalid token` | token 抄错了？这个用户注册过吗（注册页能看） |
| `unknown operation: xxx` | 名字拼错，用 `GET /help` 对一遍 |
| 写视图报 `locked` | 这个视图正在 Virtuoso 里被打开，让操作的人关掉窗口 |
| 路径报错 | 你给的是**本机**路径还是**目标机器**的路径？本机文件要先上传 |
| 超时 | 不要直接重发写操作；先读取现状（详见《参考手册》"超时与未知结果"） |
| 接口 400 / 404 / 429 | 分别对应"参数写错 / 操作名不存在 / 服务太忙"，见《参考手册》状态码表 |
