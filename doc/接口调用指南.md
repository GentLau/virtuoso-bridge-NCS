# 接口调用指南

> 版本：v1（2026-09-10）
> 适用：virtuoso-bridge-NCS 重构后的中层/底层代码（`src/`）
> 关联：`spec/design-concepts/总览/三层整体架构设计.md`、`spec/protocol-v1.md`、`spec/design-concepts/底层与中层/多用户设计.md`

上层调用方只依赖本文件描述的接口与返回模型；不需要了解 host、端口、SSH、隧道、daemon 位置或注册表内部结构。

---

## 1. 分层与调用边界

```text
上层（业务封装） ──三接口──► 中层（BusinessServer，本地/SSH 投送） ──Skill──► 底层（Virtuoso daemon）
```

- **上层**：把原理图、版图、TB、仿真等复杂操作封装成业务能力；
- **中层**：向上层提供三个接口，把指令投送到正确位置；本地模式与 SSH 模式对上层完全无感；
- **底层**：Virtuoso CIW 中的常驻 daemon，只执行 SKILL。

上层代码唯一需要知道的就是：有一个“业务服务器”，调用三个接口并传入 `token`。

---

## 2. 前置：用户注册（六步流程）

使用前必须完成一次注册。注册的**唯一落盘点**是把一条经过验证的配置写入 `<本地工作目录>/registry.json`；运行时中层一次性读入内存，只按 `token` 路由。

**推荐：通过注册页面**

```bash
# 在项目根目录，src 需要加入 PYTHONPATH
$env:PYTHONPATH='src'
python -m server.registration_server --host 127.0.0.1 --port 8124
```

浏览器打开 `http://127.0.0.1:8124/`，按页面六步引导完成：

```text
1 申请（提交必选参数，token 缺省自动生成）
2 本地校验（用户名/端口与注册表查重）
3 探测（SSH 可达、host key 指纹、hostname、daemon 用户、部署根可写、python 版本、端口空闲）
4 部署（上传 daemon/il/setup，页面给出 load("...") 与 token）
5 连通性（用户 load 后：daemon 可达 + token 比对 + echo vb-ok + 1+1==2 + banner 主机名）
6 写入注册表（前五步全部成功才落盘）
```

页面接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | 注册表单页 |
| POST | `/api/register` | 提交申请 → 执行第 2/3/4 步，返回 `stage/token/setup_path/errors` |
| POST | `/api/register/<user>/verify` | 用户已 load → 执行第 5/6 步，成功后 `stage=committed` |
| GET | `/api/register/<user>` | 查询当前注册状态 |

**也可用代码注册**（脚本化）：

```python
from transport.runtime_paths import set_working_dir
from transport.registry import load_registry
from transport.register import RegistrationFlow, RegistrationRequest

set_working_dir("/path/to/workdir")
registry = load_registry()

flow = RegistrationFlow(registry)
state = flow.apply(RegistrationRequest(
    user="alice",
    host="server-a",          # 远程模式必填
    ssh_user="jtliu",         # 远程模式必填
    scratch_root="~/.virtuoso-bridge",
))
# state.stage == "deployed" 时，把 state.setup_path 交给用户 load，并目视确认 state.token
state = flow.verify()          # 用户在 CIW load 之后调用；成功即 stage == "committed"
```

远程模式缺 `host`/`ssh_user`、端口越界、非法 token 字符会在申请阶段直接报错，不进入探测。

## 3. 三个接口（唯一调用口）

### 3.1 接口签名

`token` 是**必填关键字参数**，漏传会在调用处直接 `TypeError`。

```python
# 1. Skill：在 Virtuoso CIW 中执行 SKILL
execute_skill(skill_code, timeout=None, *, token) -> VirtuosoResult

# 2. RunCommand：在业务服务器上执行命令行
run_command(cmd, timeout=None, *, token, parallel=False) -> CommandResult

# 3. File：调用方本地与业务服务器之间传输文件
upload_file(local_path, remote_path, timeout=None, *, token) -> CommandResult
download_file(remote_path, local_path, timeout=None, recursive=False, *, token) -> CommandResult
```

### 3.2 入口对象

```python
from transport.middle import BusinessServer

server = BusinessServer(work_dir=None)   # work_dir 缺省用平台配置目录
```

`BusinessServer` 启动时**只读一次注册表**；之后的每次调用都是内存路由。注册、部署、连通性测试等设置期操作不属于运行时门面（见 `transport/register` 包）。

---

## 4. 返回模型

### 4.1 `VirtuosoResult`（Skill）

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | `success/failure/partial/error` | `ok` 属性等价于 `status == success` |
| `output` | `str` | SKILL 求值结果（字符串化） |
| `errors` | `list[str]` | 错误文本 |
| `warnings` | `list[str]` | 警告文本 |
| `execution_time` | `float | None` | 执行耗时 |
| `metadata` | `dict` | 扩展字段 |
| `log` | `str` | 本次调用产生的 CDS.log **增量**（已按级别过滤与限长） |

`log` 是底层 daemon 在**远端本地读取**并过滤后的增量，不把完整 CDS.log 拉过 TCP。分级配置：

| `cdslog.log_level` | 返回内容 |
|---|---|
| `off` | 不返回 |
| `error` | 仅 `\e`（error）行 + 调用区间标记 |
| `warn` | `\w`/`\e` 行 + 调用区间标记 |
| `all` | 全部行 + 调用区间标记 |

超长自动降级：`all`/`warn` 超过 `cdslog.log_max_bytes` 时只保留 error 行，并附 `[log truncated: error-only ...]`；error 本身仍超长时保留头尾各 100 行。

### 4.2 `CommandResult`（RunCommand / File）

```python
CommandResult(returncode, stdout, stderr)
```

- `returncode == 0` 表示传输/执行成功；
- 非零退出码是远端命令或传输工具的结构化结果；
- 超时、路径不可见、连接失败通过 `stderr` 中的分类文本 + 非零返回码表达，不与普通非零退出码混同。

---

## 5. 参数语义

### 5.1 `token`

- 每次调用必填；是“寻址键 + 授权票”，不是绑定会话对象；
- 中层按 token 查注册表路由；底层 daemon 校验 token，**不匹配直接 NAK，SKILL 零接触**；
- token 不进入 SKILL 执行帧，也不回显给上层。

### 5.2 `parallel`（仅 RunCommand）

- `False`（默认）：同一 token 的 persistent shell 串行执行，保证先后顺序；
- `True`：中层为该次调用开独立通道，与其他命令并行，**不保证完成顺序**，只用于互相独立的命令；
- `parallel` 是 RunCommand 的显式参数，不是第四个接口。

### 5.3 文件路径命名空间

- `local_path` 属于**调用方**；`remote_path` 属于**业务服务器**；
- 单文件上传/下载带 sha256 双向校验；`recursive=True` 走 tar 打包下载；
- 两个命名空间不可混用：需要共享文件时由中层确认目标位置可见，不可见时报错，不悄悄改路径。

### 5.4 超时

- `timeout` 是单次调用的端到端时间预算；缺省使用注册表中的运行策略。

---

## 6. 错误语义（上层应区分）

| 情况 | 表现 |
|---|---|
| token 未注册 | `VirtuosoResult(ERROR, ["unknown token"])` / `CommandResult(1, "", "unknown token")` |
| 线程池满 | `ERROR "thread pool exceeded"` / `rc=1 stderr="thread pool exceeded"` |
| SSH channel 预算满 | `rc=1 stderr="channel budget exceeded"` |
| daemon 未 load | Skill `ERROR`，提示 CIW `load(...)` |
| token 不匹配 | Skill `ERROR "invalid token"`（daemon 未接触 SKILL） |
| 远端命令非零退出 | `CommandResult(returncode≠0, stdout, stderr)`，returncode 是命令真实退出码 |

## 7. 示例

```python
from pathlib import Path
from transport.middle import BusinessServer

server = BusinessServer()   # 已注册并验证的前提下

# Skill
r = server.execute_skill("1+2", token="a3f9c2…")
if r.ok:
    print(r.output)          # "3"
print(r.log)                 # 本次调用的 CDS.log 增量

# RunCommand（串行）
c = server.run_command("spectre netlist.scs", token="a3f9c2…")

# RunCommand（显式并行，两条互相独立）
import threading
outs = {}
def run(i):
    outs[i] = server.run_command(f"sleep 2 && echo job-{i}", token="a3f9c2…", parallel=True)
ts = [threading.Thread(target=run, args=(i,)) for i in range(2)]
for t in ts: t.start()
for t in ts: t.join()

# File
server.upload_file(Path("local.scs"), "/home/user/run/local.scs", token="a3f9c2…")
server.download_file("/home/user/run/out.psf", Path("out.psf"), token="a3f9c2…")
server.download_file("/home/user/run/psf_dir", Path("psf_dir"), recursive=True, token="a3f9c2…")
```
