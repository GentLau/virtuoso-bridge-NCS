# 接口调用指南

> 版本：v3（2026-09-16）
> 适用：virtuoso-bridge-NCS 最新四层实现（`src/`）
> 接口唯一基线：`spec/design-concepts/总览/1-四层整体架构与接口.md` §4
> 字段与默认值：`spec/design-concepts/中层/add-中层配置文档.md`
> 日志语义：`spec/design-concepts/底层/6-日志返回设计标准.md`

上层只依赖五接口和 `token`，不接触 SSH、隧道、daemon 端口或注册表内部结构。本指南只说明调用方式；发生冲突时以 Normative spec 为准。

## 1. 五接口

```python
middle.execute_skill(skill_code, timeout=None, *, token) -> VirtuosoResult
# 伴随只读查询（非第六接口）：middle.query(token) -> QueryResult
middle.run_command(cmd, timeout=None, *, token, parallel=False) -> CommandResult
middle.upload_file(local_path, remote_path, timeout=None, *, token, recursive=False) -> CommandResult
middle.download_file(remote_path, local_path, timeout=None, *, token, recursive=False) -> CommandResult
middle.run_gui_command(cmd, timeout=None, *, token) -> CommandResult
middle.run_spectre_command(cmd, timeout=None, *, token) -> CommandResult
```

- 逻辑接口是 5 个：Skill / RunCommand / File（upload+download 两个方向）/ GUI command / Spectre command。
- `token` 每次调用必填；它只用于路由和校验，不做会话绑定，也不进入 SKILL 求值文本。
- `timeout=None` 表示默认 30s 端到端 deadline；连接建立等内部阶段只消耗剩余预算，不重置 deadline。
- `parallel` 和 `recursive` 是可选参数，默认 `False`，不是新接口。

### 1.1 只读伴随查询 query

除五个业务接口外，中层另提供一个**只读**查询（spec §4.2），供上层拼相对路径、
挑选已探测的可执行文件；它不是第六个业务接口，不承担任何投送/执行语义：

```python
middle.query(token) -> QueryResult
```

```python
result = middle.query("alice-token-1")
if result.status == "success":
    root = result.roles["file"].root        # 该 token 的文件根
    spectre = result.roles["spectre"].bin   # 已探测到的 spectre（可能为 None）
else:
    ...                                      # result.errors == ["invalid token"]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | `success` / `error` | 查询结果；未知 token 返回 `error` + `errors=["invalid token"]`，**不抛异常** |
| `roles` | `dict[str, RoleQuery]` | 固定五个键：`gui` / `daemon` / `command` / `file` / `spectre` |
| `roles[x].root` | `str | None` | 该 role 的相对路径解析基准 |
| `roles[x].bin` | `str | None` | 仅 `spectre` 有值（其余为 `None`） |

约定：

- **可查询范围只有 `root` 与 `bin`**：不返回 `mode/host/user/jump/proxy`，上层不得据此
  判断拓扑或 local/remote；
- 只读：读注册表内存快照，不建连、无副作用、不写注册表、不缓存，
  **不占三类预算、不进投递队列**；
- 按 token 隔离；`root`/`bin` 只用于拼接口参数与文件规划，不得当作业务语义。

## 1.2 顶层 HTTP 入口（业务操作调度）

顶层就是业务服务本身（不是测试工具）：`python -m server.api_server` 进程里装配一个
`Middle`，按**显式注册表**把请求派发给上层业务包。

```powershell
$env:PYTHONPATH='src'
python -m server.api_server --host 127.0.0.1 --port 8126 --work-dir <含 registry.json 的目录>
```

- 默认端口 **8126**（8123 是文档工具、8124 是注册页、8125 是压力 TB 的控制服务）；
- **顶层整体线程池**：同时在处理的任务上限 `DEFAULT_MAX_INFLIGHT = 1024`（本版为常量，
  后续作为配置项；可用 `--max-inflight N` 临时覆盖）。超过上限**不排队**，直接返回
  `429` + `Retry-After: 1`，响应体 `ok=false`、`error="server thread pool exceeded
  (max 1024 in-flight), please retry"`；`GET /api/operations` 会回报当前 `max_inflight`；
- `--work-dir` 只在**进程装配**时用于加载 `registry.json`，请求链路上不读文件；
- `GET /api/operations` 返回本进程已登记的业务操作与加载失败的包。

请求（`POST /`，JSON）：

```json
{"operation": "demo.pipeline.run", "token": "vb-vb11",
 "local_input": "in.scs", "remote_input": "/home/u/proj/in.scs",
 "skill_code": "1+1", "command": "echo ok",
 "remote_output": "/home/u/proj/in.scs", "local_output": "out.scs", "timeout": 60}
```

响应壳（成功/业务失败都是 HTTP 200，只有“能否受理”用 4xx/5xx）：

```json
{"ok": true,  "data": {"ok": true, "steps": [{"name": "upload", "ok": true, "detail": {}}], "error": null}, "error": null}
{"ok": false, "data": {"ok": false, "steps": [...], "error": "..."}, "error": "..."}
```

| 情形 | HTTP | 说明 |
|---|---|---|
| JSON 非法 / 缺 `operation` / 缺 `token` | 400 | `ok=false`，`data=null` |
| 未知 `operation` | 404 | 只列出已登记的操作 |
| Request 结构校验失败（类型/必填/范围） | 400 | 由业务包的 Request/领域校验抛出 |
| 业务运行期失败 | 200 | `ok=false`，`data` 保留步骤痕迹 |
| 未预期异常 | 500 | 不带调用栈；单请求失败不影响其它请求 |
| 顶层线程池已满 | 429 | 不排队、立即拒绝：`error` 含 `thread pool exceeded ... please retry`，带 `Retry-After: 1` |

已随包登记的业务操作（两个业务包，共 9 个操作）：

| 业务包 | 业务操作 | 说明 |
|---|---|---|
| `basic` | `basic.skill.execute` | 直通中层 `execute_skill` |
| | `basic.command.run` | 直通 `run_command`（`parallel` 可选） |
| | `basic.file.upload` | 直通 `upload_file`（`recursive` 可选） |
| | `basic.file.download` | 直通 `download_file`（`recursive` 可选） |
| | `basic.gui.run` | 直通 `run_gui_command`（一次性） |
| | `basic.spectre.run` | 直通 `run_spectre_command`（一次性） |
| `demo` | `demo.pipeline.run` | 上传 → Skill → 命令 → 下载（组合示例） |
| | `demo.parallel.probe` | 并发命令/上传探针 |
| | `virtuoso.netlist.import` | 网表导入参考实现 |

`basic` 六个操作就是中层六方法的直通：参数结构校验在 Request 完成，运行结果原样放进
`data`（含 `steps` 步骤痕迹），便于调用方拿到与中层一致的信息。

加包 = 新增 `pyapi/packages/<包>.py`（导出 `Package` + `OPERATIONS`）+ 在
`server/api_server.py` 的 `PACKAGES` 表登记一行。

```bash
curl -s http://127.0.0.1:8126/api/operations
curl -s -X POST http://127.0.0.1:8126/ -H 'Content-Type: application/json' \
  -d '{"operation":"demo.parallel.probe","token":"vb-vb11","commands":["hostname"]}'
```

## 2. 注册前置

运行期只消费一份本地 `registry.json`；启动时载入内存一次，业务路径不再读注册表文件。注册分六步：

```text
1 申请 -> 2 本地校验 -> 3 探测 -> 4 部署 -> 5 连通性 -> 6 写注册表
```

前五步只产生内存候选和远端部署文件；第六步是唯一 registry 写盘点。失败或取消不留下 reservation 文件。

### 2.1 注册页面

```bash
$env:PYTHONPATH='src'
python -m server.registration_server --host 127.0.0.1 --port 8124 --work-dir /path/to/workdir
```

打开 `http://127.0.0.1:8124/`。页面支持申请、逐步执行、查询状态、更新参数和删除用户。

### 2.2 HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 注册页面 |
| GET | `/api/users` | 列出已注册用户 |
| GET | `/api/user/<user>` | 查看用户条目 |
| POST | `/api/register/apply` | 第 1 步：提交申请 |
| POST | `/api/register/<user>/validate` | 第 2 步 |
| POST | `/api/register/<user>/probe` | 第 3 步 |
| POST | `/api/register/<user>/deploy` | 第 4 步 |
| POST | `/api/register/<user>/verify` | 第 5+6 步；只在成功后提交 |
| POST | `/api/user/<user>/update` | 更新白名单配置（不可改 token） |
| DELETE | `/api/user/<user>` | 删除用户条目并关闭本机缓存映射 |

### 2.3 脚本化注册

```python
from transport.runtime_paths import set_working_dir
from transport.registry import load_registry
from transport.register import RegistrationFlow, RegistrationRequest

set_working_dir("/path/to/workdir")
registry = load_registry()

flow = RegistrationFlow(registry)
state = flow.apply(RegistrationRequest(
    user="alice",
    token="alice-token-1",
    mode={"default": "remote"},
    ssh={"default": {"host": "server-a", "user": "ssh-user"}},
    roles={"daemon": {"daemon_port": 65081}},
))
# state.stage == "deployed"：把 state.setup_path 给用户在 CIW 中 load
state = flow.verify()          # 用户 load 并拉起 daemon 之后调用
assert state.stage == "committed"
```

`role.<name>.mode=local` 时禁止提交该 role 的 host/user/jump/proxy；未知字段和空串处理规则以配置文档 §5 为准。

## 3. 返回模型

### 3.1 VirtuosoResult

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | `success` / `error` | Skill 结果 |
| `output` | `str` | SKILL 求值结果 |
| `errors` | `list[str]` | 错误文本 |
| `warnings` | `list[str]` | 警告文本 |
| `execution_time` | `float | None` | 秒 |
| `metadata` | `dict` | 扩展信息；Skill 超时不暴露投递状态 |
| `log` | `str` | 本次调用的 CDS.log 增量 |

**Skill 超时对外统一为结果未知**：`status=error`、`errors=["SKILL execution timed out"]`；调用方不得自动重试。投递前排队超时是否可撤回只是中层内部事实，不提供可观察字段。

### 3.2 QueryResult（`query`）

```python
QueryResult(status: "success" | "error", roles: dict[str, RoleQuery], errors: list[str])
```

- `status="success"`：`roles` 含五个 role，每项只有 `root` / `bin`（见 §1.1）；
- `status="error"`、`errors=["invalid token"]`：token 不在注册表内，调用方无需捕获异常。

### 3.3 CommandResult

```python
CommandResult(returncode: int, stdout: str, stderr: str, kind: str)
```

`kind` 枚举：

| kind | 含义 |
|---|---|
| `command` | 真实命令退出码，只有此 kind 下 `returncode` 是业务命令退出码 |
| `timeout` | 超时，保留码 124 |
| `transport` | 建连/断连等传输失败，保留码 255 |
| `path` | 路径不可见、对象类型不符等；`stderr` 含 `VB-PATH-NOT-VISIBLE:` |
| `unknown-effect` | 结果未知，可能已产生副作用；不得盲目重试 |
| `rejected` | 线程/通道/endpoint 容量拒绝，可重试 |
| `checksum` | 单文件 SHA-256 不一致 |
| `invalid-token` | 未知 token |

容量拒绝文本分别是：

```text
thread pool exceeded
channel budget exceeded
role max_sessions exceeded
```

## 4. 参数语义

### 4.1 token

- 按 token 路由到唯一用户；跨 token 不共享连接、隧道、常驻 shell 或预算。
- daemon 绑定 token 并做校验；不匹配直接 NAK，SKILL 零接触。
- token 只用于算法和校验；用户可读的远端路径使用唯一用户名。

### 4.2 parallel（RunCommand）

- 默认 `False`：按 token 串行排队，投递到命令 role 的常驻 shell。
- `True`：一次性 exec 通道，可与其它调用并行，不保证完成顺序。
- 常驻 shell、Skill 隧道和一次性通道都计入每 token 通道预算。

### 4.3 recursive（File）

- `False`：单个常规文件；完成后做 SHA-256。
- `True`：目录树；上传/下载都不做逐文件 SHA-256。
- 对象类型与 `recursive` 不符返回 `kind=path`。
- 单文件先写临时位置，校验成功后原子替换；目录整体替换。

### 4.4 路径

- `local_path` 在调用方文件系统；`remote_path` 在目标 role 文件系统。
- `remote_path` 绝对路径原样使用；相对路径按该 role 的 `root` 解析。
- role root 是默认工作目录，不是安全沙箱；`..` 和绝对路径按目标 OS 语义处理。

## 5. 三种并发预算

| 预算 | 默认 | 作用域 | 超限 |
|---|---:|---|---|
| `runtime.thread_pool_size` | 32 | 每 token 在途请求 | `thread pool exceeded` |
| `runtime.channel_budget` | 10 | 每 token 所有 endpoint 已打开通道 | `channel budget exceeded` |
| `role.<name>.max_sessions` | 10 | 每个 endpoint 通道数（多 role 同 endpoint 取最小值） | `role max_sessions exceeded` |

Skill 与默认 RunCommand 在投递前按 token 排队；文件、`parallel=True`、GUI、Spectre 直接开通道。容量拒绝不排队等待，上层可以选择对幂等操作重试。

## 6. CDS.log 返回

- `result.log` 只包含本次 Skill 调用产生的 `[start,end)` 增量。
- 级别：`off` / `all` / `warn` / `error`。
- `off` 是源头关闭：IL 不 flush/fileLength、daemon 不读文件、不回第二帧。
- 超长按标准降级为 error-only；error 仍超长时截断并追加固定说明行。
- 不在 CDS.log 注入 ANY marker；bridge 只读日志。
- 日志读不到时 Skill 结果照常返回，`warnings` 含 `CDS.log unavailable: <reason>`。

完整算法见 `spec/design-concepts/底层/6-日志返回设计标准.md`。

## 7. 示例

```python
from pathlib import Path
from transport.middle import BusinessServer

server = BusinessServer("/path/to/workdir")
try:
    skill = server.execute_skill("1+2", token="alice-token-1")
    if skill.ok:
        print(skill.output, skill.log)

    cmd = server.run_command("spectre netlist.scs", token="alice-token-1")
    if cmd.kind != "command" or cmd.returncode != 0:
        print(cmd.kind, cmd.stderr)

    server.upload_file(Path("netlist.scs"), "run/netlist.scs", token="alice-token-1")
    server.download_file("run/out.psf", Path("out.psf"), token="alice-token-1")

    server.run_gui_command("xdotool search --name Virtuoso", token="alice-token-1")
    server.run_spectre_command("/opt/spectre/bin/spectre run/netlist.scs", token="alice-token-1")
finally:
    server.close()
```
