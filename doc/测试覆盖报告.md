> 版本：v9（2026-09-17）

## 1. 结果

- 离线测试：**456 collected，全部通过**（1 个按环境跳过）。

- TB 先红后绿：本轮 6 个缺陷全部由 TB 先复现（红）再修复（绿），证据见
  [TB 增强轮：缺陷与证据](report/TB增强轮-缺陷与证据.md)。
- 真机五接口 TB：Skill / 命令 / 文件 / GUI / Spectre 全部通过，证据 `test/tb/artifacts/reg-vb11/cov-remote-real-evidence.json`。
- 真机注册 TB：远端 1–4 步 `deployed` 且 `registry` 零落盘；本地六步走完
  `committed`（步骤 6 唯一落盘）并验证读回、更新、删除、乱序拒绝。
- HTTP 混合压力 TB：Windows 客户端与 WSL 客户端各 **72/72** 请求一一应答，
  覆盖五接口 + 组合服务（`upload→skill→command→download`）。

## 3. 未覆盖项说明

1. **Python 2.7 真运行**：`wsl-gent` 无 python2 解释器。`ramic_bridge_daemon_27.py`
   以“同协议矩阵在 py3 下双跑”的方式做 parity（`log-protocol.json` 中每个用例
   都有 `py27:` 结果），真 py2 运行列为环境未覆盖并标注 PENDING。
2. **OpenSSH 后端的 ControlMaster/端口转发失败分支**：部分需要 OS 特定 socket 行为；
   单元测试覆盖协议与回退，真机矩阵默认使用 paramiko。
3. **Paramiko jump/proxy 与多跳高并发组合**：endpoint key、配置与单跳回退已覆盖；
   多跳高压矩阵不作为本轮准出条件（环境为单跳）。
4. **真机日志分级/降级/轮转**：Cadence 的日志落盘是异步的，真机侧只稳定断言
   “增量字节一致 / off 不返回 / 桥零注入”；分级、降级降级提示、轮转、读不到、
   第二帧超时由 `daemon_log_protocol_tb.py` 在 daemon 真实代码路径上确定性覆盖。
5. **split-host CDS.log**：spec 明确不实现，不计入覆盖缺口。
6. **跨机 daemon 启动、Spectre 高层仿真编排、GUI 图形化业务封装**：spec 明确不做。
7. **真实 100 个 Virtuoso**：规模测试使用 100 个协议级 fake daemon；真实 Virtuoso
   使用多实例功能矩阵（`vb01–vb06`、`vb11`、`vblog`）。

## 4. 覆盖率判定

本报告不以“行覆盖率接近 100%”替代行为验证。对送审而言：

- 五接口、注册、日志、并发预算与资源回收的**主路径**同时有离线契约与真机证据；
- 容量拒绝、token 隔离、off 源头关闭、崩溃安全等关键分支有专门 TB 与红→绿证据；
- 未覆盖行集中在 spec 明确不做、OS 特定回退、或需要真实多跳/多实例环境的组合路径，
  已在第 3 节逐条说明替代证据或 PENDING 状态。
