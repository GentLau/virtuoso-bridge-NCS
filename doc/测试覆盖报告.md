## 3. 关键业务场景覆盖（对应 spec）

### 3.1 六步注册（多用户设计 §3.2）

- 申请参数校验：远程模式 host/ssh_user 必填、端口 1–65535、token 字符集、user 非空；
- 第二步本地校验：user 查重 + daemon/local 端口查重（单测 + 页面 400 路径）；
- 第三步探测：SSH 可达、host key 指纹（known_hosts 优先 + `ssh -G` 别名解析 + `ssh-keyscan` 回退）、hostname、daemon 用户存在性、python 选型、端口空闲/分配、部署根可写；**每个失败分支都有单测，且不落盘**；
- 第四步部署：python 2/3 选 `_27/_3`，setup IL 注入 token 并**每次 load 打印 token**（新增 `printf("[RAMIC] token=%L\n" RBDToken)`，有单测 + 真机 load 验证）；
- 第五步连通：命令冒烟 + Skill 冒烟 + token 比对 + banner 主机名漂移 WARNING（短名/FQDN 兼容），失败重试不落盘；
- 第六步唯一写盘：`verify()` 成功才 `registry.register()`；**verify 幂等**（重复调用保持 committed）；注册表写盘先 `tmp+replace` 成功再提交内存，失败回滚。

### 3.2 token 机制

- 三接口 token 均为必填 keyword-only，漏传 `TypeError`（四个接口全覆盖）；
- 未知 token 结构化失败且不构造远端连接；
- daemon 无 token 启动即退出；请求 token 缺失/null/不匹配 → `15 invalid token 1e`，且**不向 Virtuoso 管道写入任何字节**（假管道断言 `written == b""`）；
- 单行/多行 SKILL 帧中不含 token 明文（断言 sent 字节）。

### 3.3 注册表

- `user` 为键、token 唯一、`mode ∈ {local,remote}`、端口/线程池/channel/超时/log 配置全部带约束校验；
- `load()` 一次进内存；运行时零探测、零写盘；
- 原子替换、落盘失败内存回滚、`.json.tmp` 不残留；
- 模型 dump 不包含 `status/authorized` 等运行态字段。

### 3.4 CDS.log 增量返回

- 两个 daemon 用**同一组 fixture 做 parity**：`off/all/warn/error` 分级、未知前缀按 info、超长降级 error-only、error-only 头尾 100 行、UTF-8 按字节计数；
- `_read_delta` cursor：增量推进、路径切换重置、文件轮转从 0 重读、`end<start`/`end>size` 夹紧（本次修复了负长度读取崩溃）；
- 真机 E2E 断言 `execute_skill` 返回非空 `log`。

### 3.5 并行机制

- 本地与真机均验证：`parallel=True` 两条命令的**时间区间重叠**（E2E 用远程时间戳区间，不依赖易抖动的墙钟阈值）；
- 线程池超限、channel 预算超限均返回结构化错误。

### 3.6 文件传输

- tar/text 上传计划、目录下载计划、staging、原子安装、失败回滚旧文件（覆盖目录替换/文件替换/异常回滚）；
- 上传/下载**对称**：`recursive=False` 单文件 + sha256 校验，`recursive=True` 目录 tar（本地 `copytree`/`copy2` 镜像），目录误用/单文件误用均有错误分支；
- 真机 OpenSSH 上传/下载往返校验；Paramiko 上传文本 + `cat` 校验。

## 4. 双 subagent 审查 → 已落地修复

两个只读审查代理给出了缺口清单与可疑逻辑。本轮已落地的修复：

1. `middle.py` 线程池信号量在 `_acquire→_remote` 之间被覆盖导致 `Semaphore released too many times`（真实并发记账 bug）；
2. `skill_client.py` `socket.timeout`（OSError 子类）先于 `except OSError` 捕获，原先超时被误报为 Socket error；
3. `ssh.py test_connection` 依赖 ControlMaster，Windows 陈旧 mux 使注册探测误判不可达 → 改为无 CM 探测；
4. `ssh.py` Windows 隧道 stderr 文件句柄父进程未关闭 → 已关闭；
5. `probe.host_key_fingerprint` 只支持 DNS 直连 `ssh-keyscan` → 改为 known_hosts 优先 + `ssh -G` 别名解析 + keyscan 回退；
6. `daemon_27.py` 混用 `chr()+bytes` 在 Python 3 下无法执行 → 统一 bytes 帧（保留 Python 2.7 兼容）；
7. `daemon_3.py` 的 3.7+ 注解语法在 Cadence 自带 Python 3.6 上 SyntaxError → 全部改为 3.6 兼容写法；
8. `_read_delta` 恶意/异常 meta 可触发负长度读取或 cursor 越过 EOF → 已夹紧 `[0,size]`；
9. `registry.register/remove` 原先先改内存后写盘，落盘失败产生分叉 → 改为先持久化成功再提交内存；
10. 注册/注册表字段约束缺失（mode 枚举、端口范围、token 字符集、log_level 枚举、正数约束）→ 已在模型层统一校验；
11. `setup.il` 未打印 token，目视确认授权流程缺失 → 已加入每次 load 打印；
12. `verify()` 重复调用会把 committed 翻成 failed → 已幂等。

## 5. 未覆盖的 23%：构成与原因（不隐瞒）

### 5.1 `transport/ssh.py`（67%）

未覆盖主要是：
- **POSIX 专属持久 shell 生命周期细节**（`ensure_persistent_shell` 的旧进程重建、kill/wait 超时、reader join 边界）：开发机是 Windows，persistent shell 在 Windows 上按策略禁用，走不了真实路径；已用 mock 覆盖协议状态机主体；
- **tar 管道双进程编排的完整失败矩阵**（stdout/stderr drain 线程、communicate 超时清理）：plan 与安装层已覆盖，进程编排部分依赖真机，真机只验证了成功路径；
- **Windows 专属 `start_port_forward` 失败分支的 settle 30s/10s 下限与临时文件删除**：只覆盖成功路径。

### 5.2 `transport/paramiko_backend.py`（63%）

未覆盖主要是 connect 链路的深层编排：
- `_connect_client`/`ensure_connected` 的跳板 `direct-tcpip`、SOCKS 握手、host-key-alias socket、失败清理顺序——需要 mock 或真实跳板/SOCKS 拓扑；
- SFTP/tar 的真实慢速传输、callback 超时是否被 Paramiko 包装；
- 真机只覆盖 `run_command` + `upload_text` 两条。

### 5.3 底层 daemon（67%/68%）

- `start_server` 的 accept 主循环、watchdog 对 Virtuoso 的 SIGINT、banner/identity 的真实 IPC 行为只能由真实 CIW 覆盖（本地覆盖率进程无法统计远端子进程）；已用 handler 级假管道覆盖请求处理主体；
- `_read_frame` 的 POSIX `EAGAIN` 分支在 Windows 上不可达。

### 5.4 SKILL（`ramic_bridge.il`）

coverage.py 无法统计 SKILL。用静态断言 + 真机验收：BEGIN→flush→执行→END→flush→path/offset 第二帧的顺序、`ipcBeginProcess` 注入 token、load 打印 token、identity 文件格式。

### 5.5 平台差异

- `runtime_paths` 的 macOS/Linux XDG 默认目录分支：Windows 开发机无法构造 POSIX 路径对象，标为 platform skip；
- daemon Python 2.7 的真实解释器行为：现场有 Cadence 自带 python2.7，但本机只有 Python 3；`daemon_27` 已做双版本 bytes 兼容修复并用 py3 近似执行，真正的 2.7 现场执行列为待验。

### 5.6 尚未实现/待验收的 spec 能力（审查代理指出，需业务决策）

1. **连接期 host key 指纹比对**：注册固化指纹，但连接阶段尚未实时比对（防漂移字段目前是冷启动数据）；
2. **split-host 独立探测**：手动注册单主机完整；`daemon_host ≠ command host` 时对 daemon 主机单独探测与路径可见性检查未实现；
3. SOCKS5/跳板真实拓扑、MaxSessions 临界并发、断线自愈的现场压力测试未执行。

以上三点属于功能缺口而非测试缺口，需要在 spec 评审后补实现，再回到本报告。

## 7. 结论

- 四层测试体系 249 项全绿；语句覆盖 **77%**；
- 所有可离线验证的协议、模型、路由、注册、日志分级、文件原子性、错误分支均已覆盖；
- 未覆盖部分绝大多数是“只能在 POSIX / 真实 Virtuoso / Python 2.7 / 跳板-SOCKS 拓扑中触发的路径”，已在 §5 逐条说明，**不把 77% 当作 100%**；
- 距离更高覆盖率的路径明确：POSIX CI 跑 persistent-shell 分支、现场 python2.7 跑 `daemon_27`、跳板/SOCKS 真机夹具、以及 §5.6 三项功能补完后回归。
