## 二、驳回理由详述

### B7（GUI 跨用户可见）：不是 bridge 的隔离缺陷

- 《路由设计》§1"忠实投送原则"：bridge 只按用户给定目标投送，不判断 role 之间是否同机、同账号、共享路径/display；
- 《多用户与注册》§1：token 只防 Skill 通道误连，不承担 SSH 认证；隔离依赖 OS 账号权限；
- 两个用户都把 `gui` role 指向同一台机器的同一个 `DISPLAY=:99`，在该 display 上就是互相可见——这是站点拓扑（"用户拓扑责任"），不是 bridge 越权；
- 若站点要求隔离：每用户独立 X display / 独立账号，或由上层业务包增加"只操作自己的窗口"过滤（属 10-gui 口径）。

### B9（banner=null 无 warning）：spec 未定义的行为

- 《多用户与注册》§3.2 只定义 `banner hostname / daemon user 与 expected_* 不一致 → WARNING`；
- identity 文件缺失/读不到属于站点侧事实；注册第五步已实际连通（skill 冒烟通过）才可能走到这里；
- 需要"取不到 banner 也提示"的话，应在 spec 增加一句，再实现（属可选项，不阻断）。
