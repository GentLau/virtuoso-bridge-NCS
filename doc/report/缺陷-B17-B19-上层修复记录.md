## 2. B17：错误摘要非空

根因：

`basic.py` 的 command/upload/download/gui/spectre 结果使用
`error=<stderr> or None`；当 rc 非零但 stderr 为空时，顶层会得到
`ok=false, error=null`。

修复：

- 新增统一 `_command_error()`；
- rc != 0 且 stderr 为空时补 `"<operation> failed with rc=<n>"`；
- skill 失败且 errors 为空时补 `"skill execution failed: status=<status>"`。

direct dispatch 验证：

```text
POST basic.command.run {"cmd":"false"}
→ ok=false, error="command failed with rc=1"
```

## 3. B19：严格布尔与 timeout

根因：

- `CommandRequest.parallel` 在 `run_command` 内被 `bool(request.parallel)`；
- `UploadRequest.recursive` / `DownloadRequest.recursive` 同样被 `bool()`；
- `_require_timeout` 未拒绝 bool / 非有限值。

修复：

- `CommandRequest.__post_init__` 要求 `parallel` 必须是 bool；
- `UploadRequest` / `DownloadRequest.__post_init__` 要求 `recursive` 必须是 bool；
- `_require_timeout` 拒绝 bool、NaN、Infinity、非正数；
- 运行期直接传 `request.parallel` / `request.recursive`，不再二次 `bool()`。

direct dispatch 验证：

```text
POST basic.command.run {"cmd":"echo x","parallel":"no"}
→ HTTP-like 400
{"error":"invalid request for operation: parallel must be a boolean"}
```

## 4. B6：`demo.paths.facts` token 校验

修复：

- `demo.paths.facts` 在 `middle` 存在时先 `self.middle.query(token=...)`；
- token 无效时返回 `ok=false, error="invalid token"`，不再返回本机路径；
- `middle=None` 的纯单元测试路径保持原行为。

direct dispatch 验证：

```text
POST demo.paths.facts {"token":"not-a-real-token"}
→ ok=false, error="invalid token"
```
