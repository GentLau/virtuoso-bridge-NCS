## 1. 结论

C06 的根因不是"选错了一个 flush 函数"，而是 **CIW 的输出行提交是行缓冲的**：

- `evalstring()` 绕过 CIW 交互循环，没有"每条命令结束后把输出行补一个换行"的动作；
- `print` / 不带 `\n` 的 `printf` 只把内容留在部分行里，**不提交**到 CIW transcript / `CDS.log`；
- `hiFlushInfo` / `hiFlushCIW` / `hiFlush` / `hiFlushLogFile` / `drain(poport)` 都不会提交部分行（真机单变量探针，见 §2）；只有行终止符（`\n`）会提交。

修复（最小改动）：

1. `ramic_bridge.il`：在 evalstring 之后、`lo_end` 抓取之前补一个 `errset(printf("\n"))`，
   即"交互 CIW 本来就会补的行终止符"；随后 `hiFlushInfo()` 让已提交的行立刻显示。
   两者**无条件执行**（含 `log_level=off`）：换行是模拟人类敲 Enter，off 只意味着不获取/
   不返回日志，`hiFlushLogFile/fileLength/meta frame` 仍 gated by `log_on`。
2. `ramic_bridge_daemon_3.py` / `ramic_bridge_daemon_27.py`：`filter_delta()` 先把终止符在无待刷输出时留下的空 `\o ` 行剥掉，保证返回增量只含用户内容（静默请求仍为空串，用户自己的末尾空行保留）。

真机结果：C06-A…K 全绿；静默请求增量为空；`print("X")` 的输出落在**同一请求**的
`CDSlog` 且不串到下一条；off 请求同样补终止符（不返回、不串场）；load 路径同口径；
P-086 脏门 / 探针恢复全绿。

## 6. errset 评估：error 提取不受影响

**背景**：log 块的 flush 调用（`printf` / `hiFlushInfo` / `hiFlushLogFile` / `fileLength`）
都用 `errset` 包着。SKILL 手册（IC6.1.8 `funcprog_re_errset`）确认：

- `errset` 把表达式放进"**安全环境**"（safe from the error mechanism），出错时控制权
  返回到 errset 之后而不是最近的 toplevel；
- 无论是否打印，错误信息写入**单槽** `errset.errset`；errset **成功时该槽被清空**
  （`errset(1+2) => (3)`，`errset.errset => nil`），失败时被覆盖为本次错误；
- 手册明确警告"**不要分离 errset 与 errset.errset**"（CIW 内部可能执行 errset 改写该槽）。

按此逐句核对 IL 顺序（真机实测复核）：

1. 用户 SKILL 由 `if(errset(result=evalstring(...)))` 求值；失败分支**在同一 form 内立即**
   把 `errset.errset` 用 `sprintf("%L")` 复制进 `frames`；
2. 之后才进入 `when(log_on)` 执行那些 errset 包裹的 flush；
3. 因此 log 块的 errset 无论成功（把 `errset.errset` 清空）还是失败（覆盖为 flush 错误），
   都**不可能改变已经固化进 frames 的错误载荷**。

真机验证（destb1，`round8` 证据；round6 同结论）：

| 用例 | 结果 |
|---|---|
| `progn(print("C06E_...") boom_c06())`，`log_level=all` | `error = ("eval" 0 t nil ("*Error* eval: undefined function" boom_c06))`（原始错误，未变）；`CDSlog = \o "C06E_..."\n`（print 落同请求）；下一条 `1+1` 的 `CDSlog` 为空 |
| 同一 SKILL，`log_level=off` | `error` 同上；`CDSlog=""`（off 只不返回日志，终止符照补） |

新增钉子：

- offline 静态契约 `test_error_frame_is_built_before_the_log_block`
  （`errset.errset → frames` 必须先于 `when(log_on)`，防未来重排）；
- live TB `_check_error_extraction`（上表两条断言）。

已知边界（非本次引入、未改）：

- log 块的 errset 失败会被吞掉（与既有 `errset(hiFlushLogFile())` 同口径）：后果是
  **日志不完整/为空，而不是把 flush 失败当成 SKILL 失败**——这是"日志捕获失败不阻断
  业务返回"的既定契约；
- `errset.errset` 是单槽：本请求之后任何代码若还需读取用户错误，必须在 log 块之前取走
  （当前 IL 已经这样，并有静态钉）。

## 7. load 路径调研（skill 含换行 → 临时 `.il` + `load`）

daemon 在 `"\n" in skill_code` 时走 load 路径：把 skill 写进
`<temp>/vb_eval_*.il`，发送 `load("<tmp>") _vb_eval_result\n`；IL 侧仍是
`evalstring(...)` 执行这条命令。结论：

1. **同类行缓冲问题存在，且已被同一个终止符一并修掉**。
   修复前真机实测（destb1，一次误加载旧 IL 的窗口）：
   `progn(\nprint("LOADQ_A"))` 同请求 CDSlog 为空，`"LOADQ_A"` 串到下一条
   `printf("LOADQ_B\n")` 的行首 → 文件里是 `\o "LOADQ_A"LOADQ_B\n`。
   修复后同一形态：`\o "LOADQ_A"\n` 落同请求；`progn(\nprintf("LOADQ_B\n"))`
   → `\o LOADQ_B\n`（终止符空行被 daemon 剥掉）；`progn(\nprint("LOADQ_C"))`
   + `log_level=off` → 返回空、下一条 all 的 CDSlog 也为空（无串场）。
2. **错误提取形态与 inline 不同（既有行为，非本次引入）**：load 内抛错时，
   NAK 载荷是 load 包装错误
   `("load" 0 t nil ("*Error* load: error while loading file - "<tmp>.il" at line N))`；
   原始错误以 `\e *Error* eval: undefined function - boom_*` 落 CDS.log，
   出现在**同一请求**的增量里。即：失败一定能检出（NAK），但 `errors[]` 是 load 级
   信息，原始错误要去 CDSlog 读；inline 路径的 `errors[]` 则是原始 `("eval" ...)`。
3. 临时 `.il` 在请求结束后被 unlink，load 错误信息里的路径此后不可再读（既有行为）。

是否要把 load 路径的原始错误提升进 `errors[]` 属于协议语义变更，本轮未动。

## 8. spec 口径（设计侧已裁决）

设计侧裁决：这个换行是**模拟人类敲击 Enter**，对每条请求都要有（含
`log_level=off`）；off 只表示"不获取/不返回日志"，不表示"让 CIW 半行停顿"。

落地（本次已实现）：

- `errset(printf("\n"))` + `errset(hiFlushInfo())` 移出 `when(log_on)`，**无条件执行**；
  `hiFlushLogFile/fileLength/meta frame` 仍 gated by `log_on`；
- 因此 off 请求的输出残留消失（真机：off 的 `print` 后下一条 all 的 CDSlog 为空）；
- 物理文件上"静默/已换行结束"的请求仍会多一个空 `\o ` 行（返回增量已被 daemon 剥净）。

建议 spec 两处一句话同步（spec 归设计侧改）：

1. §1 明确：IL 补的"交互等价行终止符"属于执行语义，不是日志 marker/游标；
2. §3 off 步骤改为："不获取日志（不 hiFlushLogFile/fileLength/第二帧），
   但仍补交互等价的行终止符"。

## 9. 遗留

- P-086 本轮补修（真机发现）：daemon 的 `_dirty` 原先是**单向锁存**（只置 True、从不清零），
  所以投递超时后 probe 永远 busy，表现为"必须重启才能恢复"——这违背 1A 约定，是实现缺口
  （TB 也只测了 dirty→busy→重启恢复，漏了自动恢复）。已修：超时记账该请求将来会回几帧
  （`log_level=off` → 1；`all/warn/error` → 2），probe 非阻塞收齐全部迟到帧后清 `_dirty`
  并报 idle；收不齐（旧 SKILL 永不结束，2A）继续 busy，重启仍是兜底。离线新增自动恢复/
  两帧收齐/放行业务三条用例；真机 round10：**不重启** 1.72s 恢复为 4、dirty 清，重启兜底
  同时 PASS。常驻 `vblog/8127` 未触碰（测试侧已撤掉直连用例并恢复常驻）。
- 全量离线里 `registration_server_edges` 的 Windows socket 抖动非本改动引入，建议测试侧单独排期加固。
- load 路径的 `errors[]` 是 load 级包装错误（原始错误在 CDSlog）——既有行为，未动，等口径。
