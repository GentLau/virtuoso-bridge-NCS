## 1. 结论

C06 的根因不是"选错了一个 flush 函数"，而是 **CIW 的输出行提交是行缓冲的**：

- `evalstring()` 绕过 CIW 交互循环，没有"每条命令结束后把输出行补一个换行"的动作；
- `print` / 不带 `\n` 的 `printf` 只把内容留在部分行里，**不提交**到 CIW transcript / `CDS.log`；
- `hiFlushInfo` / `hiFlushCIW` / `hiFlush` / `hiFlushLogFile` / `drain(poport)` 都不会提交部分行（真机单变量探针，见 §2）；只有行终止符（`\n`）会提交。

修复（最小改动）：

1. `ramic_bridge.il`：在 `when(log_on)` 内、`lo_end` 抓取之前补一个 `errset(printf("\n"))`，即"交互 CIW 本来就会补的行终止符"；随后 `hiFlushInfo()` 让已提交的行立刻显示。
2. `ramic_bridge_daemon_3.py` / `ramic_bridge_daemon_27.py`：`filter_delta()` 先把终止符在无待刷输出时留下的空 `\o ` 行剥掉，保证返回增量只含用户内容（静默请求仍为空串，用户自己的末尾空行保留）。

真机结果：C06-A…K 全绿；静默请求增量为空；`print("X")` 的输出落在**同一请求**的 `CDSlog` 且不串到下一条；P-086 脏门 / 探针恢复全绿。

## 6. 提请裁决：spec §1"不向 CDS.log 注入任何输出"

本次修复在物理文件上确实会给"静默 / 已换行结束"的请求追加一个空 `\o ` 行
（待刷的部分行由同一个终止符完成，不产生额外行）；daemon 已把这一行从**返回增量**里剥掉，
返回值与用户内容逐字节一致，且没有 BEGIN/END marker、没有 cursor、没有重复返回。

但《日志返回设计标准》§1 的字面口径是"不得往 CDS.log 写……其他行——日志返回只读文件，
不改文件"。两者存在字面冲突，需要设计侧二选一：

**A（已实现，推荐）**：spec 增补一句，允许 IL 在 `log_on` 时补"交互 CIW 等价的输出行终止符"，
daemon 从增量中剥掉它产生的空 `\o ` 行（返回值仍是纯用户内容）。C06 按现 TB 全绿。

**B**：spec 维持"物理文件零写入"，则 C06-A/F/H/I/J/K 的"同一请求归属"不可实现
（`hiSetFilter` 刷新法会改写用户 CIW 过滤设置，不宜采用），只能把 C06 判据收窄为
"部分行在后续换行时提交"。需要测试侧同步改红钉。
