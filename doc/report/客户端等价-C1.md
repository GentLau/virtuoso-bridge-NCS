# 客户端等价 C1：Windows 与 Linux 客户端

> 日期：2026-09-11
> 代码基线：`68ade2b`
> 执行脚本：`scripts/client_equiv.py`

## 1. 目标与期望

同一份确定性业务序列（同 seed、同用户、同 token、同端口），分别由 Windows 客户端和 wsl-gent（Linux）客户端驱动同一批 vps fake 用户，结果必须等价：op 数一致、错误 0、路由错配 0、sha 0。只测单客户端等价，不做双客户端同时运行。

## 2. 拓扑

| 项 | 值 |
|---|---|
| 用户 | 10 个 fake 用户（`cloud00..cloud09`，vps，端口 6701-6710） |
| Windows 客户端 | 本机，经 SSH 到 vps |
| Linux 客户端 | wsl-gent，先配置 `~/.ssh/config` 的 `Host vps` 与密钥后直连 vps |
| 序列 | seed=777，每用户 6 个操作 |

## 3. 每用户请求构成（相同 seed → 两个客户端完全一致）

- 1 次上传基准文件（2048 字节）；
- 其余 5 次按 seed 随机：约 45% skill（`RBDToken`，期望回显 token）、约 30% command（`echo vb-<seq>`，期望回显）、约 25% download（下载基准文件）；
- 整体 shuffle，上传先于下载。

## 4. 重试与 log

- 业务拒绝与传输瞬时错误重试，统计 `retries`；
- fake 用户 log 恒为 `""`（无真实 CDS.log）。

## 5. 结果

```text
windows: users=10 ops={skill:20,command:14,upload:10,download:16} retries=0 errors=0 elapsed=10.6s seed=777
linux:   users=10 ops={skill:20,command:14,upload:10,download:16} retries=0 errors=0 elapsed=3.8s  seed=777
```

- 两者 op 分布完全一致（同 seed 的确定性序列）；
- 错误 0、错配 0、sha 0；
- 差异只有客户端平台与网络时延，业务语义等价。

## 6. 结论

通过。单 Windows/Linux 客户端对同一远端用户的业务语义等价。
