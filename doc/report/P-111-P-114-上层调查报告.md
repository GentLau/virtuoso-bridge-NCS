## 1. P-111 `maestro.set_parameter` 是什么

`set_parameter` 不是设计变量，也不是仿真选项。它对应 ADE Assembler/Explorer 的
**层次器件参数覆盖**，底层 API 是 `maeSetParameter`。

Cadence 手册（8123 `maeSetParameter`）：

- 名称至少五段非空路径，典型 `library/cell/view/instance/property`；
- 例：`"Two_Stage_Opamp/OpAmp/schematic/R0/r"` 设为 `"8k"`，即把 R0 的 `r` 改成 8k；
- 默认是 test/global 级；`?typeName "corner" ?typeValue '("C0" "C1")` 可只覆盖指定 corner；
- 与 `set_var` 的区别：`set_var` 写 design variable（如 `VDD=1.1`），
  `set_parameter` 写器件实例属性（如 `R0/r`、`M0/w`）。

## 2. P-114 与 P-113 的关系

P-113 修的是**实参位置**：`offSheetP` 本该是 `schCreatePin` 第 5 个必选实参，
旧代码把它又追加到尾部，导致：

- 带 `sig_type` 时参数数 11 > 10；
- `off_sheet` 布尔值被放到 `powerSens` 的字符串位置。

修好位置后，真正的底层语义暴露出来，这就是 P-114，不是 P-113 引入的新回归。

### 2.1 `power_sens` / `ground_sens`

这两个值必须是**目标 cellview 内已存在的 terminal 名**。真机：

- 目标 cell 内没有 `VDD`/`VSS` terminal 时：`schCreatePin` 返回 nil，
  但包当前把“SKILL 未报错”当成功 → 报 ok 但零对象（静默 no-op）；
- 先建出 `VDD`/`VSS` terminal 后，同一个 `power_sens`/`ground_sens` 调用
  能真正建出 pin/terminal。

所以 P-114 的核心不是“参数拼错”，而是：

1. 底层 API 对“引用 terminal 不存在”没有可靠报错；
2. 包没有做创建后的对象存在性校验。

### 2.2 `off_sheet=true`

`schCreatePin(..., offSheetP=t, master=nil)` 在当前 Virtuoso 环境报：

```text
*Error* nth: argument #1 should be an integer (type template = "xl") - nil
```

原因是当前 pin list 没有可用的 off-sheet master。显式传
`dbOpenCellViewByType("basic" "onPageConn" "symbol" "" "r")` 可以建出 connector pin，
但“onPageConn 是否就是业务上正确的 off-sheet master”需要产品确认；
此前未提交的 workaround 已撤回，未作为结论。

### 2.3 建议

按“不静默、不猜”处理：

- `power_sens`/`ground_sens` 指向的 terminal 不存在 → 结构化失败；
- `off_sheet=true` 且无可用 off-sheet master → 结构化失败；
- 每次 `schCreatePin` 后校验 pin/terminal 确实存在，否则不得返回 ok；
- 如果确认 `basic/onPageConn` 是本环境正确的 connector master，再把它写成显式夹具/实现。
