# 控制台三页：后端接口与权限核对

> 日期：2026-09-30
> 范围：注册、个人管理、管理员系统管理
> 结论：控制面 v42 的个人自助查询/修改已经落地；C11 关闭。剩余边界是
> `key/key_dir` 仍为管理员保密字段，DELETE 仍为纯管理员操作。

## 1. 三页职责

| 页面 | 职责 | 主要接口 |
|---|---|---|
| 新用户注册 | 六步申请、校验、探测、部署、连通性、提交写入 | `POST /api/register`、`GET /api/register/<user>` |
| 个人管理 | 用个人 token 查询自己的条目；普通字段直接修改；只读字段用管理员 enhanced_token 修改 | `GET /api/user/<user>`、`POST /api/user/<user>/update` |
| 管理员系统管理 | 全局 `config.json` 和业务进程 status/reload/restart；注册表只读概览 | `/api/config`、`/api/process/*`、`GET /api/users` |

## 2. 个人自助契约（v42）

### 2.1 GET

```http
GET /api/user/<user>
Authorization: Bearer <personal token>
```

规则：

- 管理员 token：可读任意 user，返回普通 `_redacted` 视图；
- 个人 token：只能读本人，否则 403；
- 个人返回使用 `_redacted_self`，移除：

```text
token
ssh.default.key_dir
ssh.default.key
roles.<role>.key_dir
roles.<role>.key
```

### 2.2 POST update

```http
POST /api/user/<user>/update
Authorization: Bearer <personal token>
Content-Type: application/json

{
  "cdslog": {"log_level": "warn"},
  "enhanced_token": "<管理员 token>"
}
```

字段级权限：

| 字段 | 个人 token | personal + enhanced_token | 管理员 |
|---|---:|---:|---:|
| `ssh.default.host/user/jump_host/jump_user/proxy` | 可改 | — | 可改 |
| `role.<name>.host/user/jump_host/jump_user/proxy` | 可改 | — | 可改 |
| `role.<name>.root` | 可改 | — | 可改 |
| 用户组（如 `role.command.calibre`） | 可改 | — | 可改 |
| `cdslog.*` | 可改 | — | 可改 |
| `ssh.backend/control_master/tool_override` | 可改 | — | 可改 |
| `mode.*`、`runtime.*` | 不可改 | 可改 | 可改 |
| `role.<name>.mode/max_sessions` | 不可改 | 可改 | 可改 |
| `daemon_port/local_port/expected_*` | 不可改 | 可改 | 可改 |
| `key_dir` / `key` | 不可读、不可改 | 不可改 | 可改 |
| `token` / `registered_at` | 不可改 | 不可改 | 不可改 |

注意：

- `enhanced_token` **只接受管理员 token**，已登记用户自己的 token 不能当增强凭据；
- `enhanced_token` 只校验、不落盘、不回显；
- 个人 update 返回 `_redacted_self`，因此前端不能再把 `key/key_dir` 作为空字段回传；
- DELETE 未开放个人自助：

```text
DELETE /api/user/<user>  → 仍要求管理员 Authorization
```

对应实现：

```text
src/register/server.py
  _SELF_SECRET_FIELDS
  _SELF_READONLY_FIELDS
  self_patch_blacklist()
  _require_self_or_admin()
  _redacted_self()
  _handle_update(..., personal=True/False)
```

## 3. 前端适配

个人页已经按 v42 调整：

1. GET 使用个人 Token 作为 Authorization；
2. 普通字段可直接保存，不强制 enhanced；
3. `mode`、runtime、端口、max_sessions、expected_* 变更前要求管理员 token；
4. `key/key_dir` 从个人详情和编辑表单移除，只显示“个人视图隐藏”；
5. DELETE 按钮保持禁用，并明确说明“仍仅管理员”；
6. 401/403 在中间主结果区显示错误、原始响应和权限原因，不只留在左栏小字。

## 4. 验证

### 4.1 隔离临时实例

为不干扰原 8124/8127，使用独立 work-dir 副本启动：

```text
control:  8144
business: 8147
user:     demo
mode:     local
```

实测：

```text
GET  personal own                         → 200
GET  personal other                       → 403
POST personal edit cdslog                 → 200
POST personal runtime without enhanced    → 403 enhanced_token required
POST personal runtime + admin enhanced    → 200
POST personal write secret key/key_dir    → 403
GET  admin own                            → 200
```

### 4.2 页面

临时实例页面：

```text
http://127.0.0.1:8144/
```

浏览器实测：

- `demo / demo-self-token` 查询成功，详情可见；
- 详情中显示 `key/key_dir = 个人视图隐藏`；
- 编辑表单不出现 `key/key_dir`；
- 修改 `cdslog.log_level` 后无需 enhanced 即可保存成功；
- 修改 `runtime.thread_pool_size` 但未填管理员 enhanced 时，前端在发送前明确阻止。

## 5. C11 状态

原 C11“个人自助查询/修改缺失”已按以下证据关闭：

```text
后端源码：src/register/server.py 的 self-or-admin / redacted-self / blacklist
隔离实例：8144/8147 全部权限矩阵实测
前端：key/key_dir 不进个人表单；只读字段门槛与后端一致
```

保留边界：

```text
个人不可见、不可写：key_dir / key
个人不可删：DELETE 仍仅管理员
enhanced_token：仅管理员 token
```
