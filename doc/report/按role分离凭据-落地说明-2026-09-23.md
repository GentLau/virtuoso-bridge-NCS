# 按 role 分离 SSH 凭据 —— 代码落地说明（2026-09-23）

> spec：`SPEC-2026-09-23-r22` 系列（r18–r22）
> 《中层配置文档》v44 §2.3/§2.5/§4/§5、[《路由设计》v23 §4](#)、
> [《多用户与注册》v40 §2/§3](#)、[《控制面与业务面》v40 §2/§3](#)。
> 用户口径：**重点是按 role 分离凭据**；enhanced_token 为可选参数，不提供走老路。

## 1. 实现了什么

| 层 | 改动 |
|---|---|
| 配置面 | `role.<name>.key_dir/key`（role 级，remote 使用、local 不得提交）+ `ssh.default.key_dir/key`（全局缺省；`key_dir` 缺省 = 客户端 `~/.ssh`；存在 remote role 时 `key` 必填）；`key` 只允许文件名，带目录成分直接拒绝 |
| 注册面 | 第二步（validate）逐一解析 remote role 凭据：私钥文件必须存在、必须能读到公钥（`<key>.pub` 或 key 本身是公钥）并算出 **OpenSSH 风格 SHA256 指纹**；指纹与他人已登记凭据重复 → 必须有 `enhanced_token`（管理员 token 或任一已登记持有者 token）才放行，否则拒绝且不改状态 |
| 授权面 | `apply`：`enhanced_token` 提供即校验（admin 或任一 holder）；声明 `mode=local`（含任一 role 为 local）需 enhanced_token **或**老路的管理员 `Authorization: Bearer`；凭据复用同理 |
| 运行面 | 每 role 解析后的凭据进入连接决策：`SSHRunner(ssh_key_path=...)` 使用该 role 的私钥；**同一 endpoint 但凭据不同 → 不共用连接**（runner 缓存键 = endpoint + 凭据路径） |
| 管理面 | `DELETE /api/user/<u>` 返回该条目的凭据标识 + 公钥指纹 + `still_used_by`（是否仍被其他条目使用；系统不自动吊销） |
| 前端 | 注册页新增全局 `ssh_key_dir`/`ssh_key`、每 role `key_dir`/`key` 输入与 enhanced_token 输入，payload 映射到后端字段（子代理负责，见 §4） |

## 2. 关键取词

* 凭据位于**客户端侧**：`key_dir/key` 是运行注册/中层的本机路径，不是 role 主机路径；
* 指纹 = `SHA256:` + base64(SHA256(DER/SSH 公钥 blob))（去 padding），与 `ssh-keygen -lf` 一致；
* endpoint canonical key **不含凭据**（跨 role 的 host-key 基准共享以"同 endpoint 且凭据一致"为前提）；
* 连接复用键用**解析后的凭据路径**（`Path.resolve()`），`~/.ssh/k` 与
  `/home/u/.ssh/k` 视为同一份凭据；`credential_identity()` 只用于 `user remove` 的人工回报；
* `key_dir` 省略是 spec 明文允许（《中层配置文档》§2.5：`key_dir` 缺省 = 客户端
  `~/.ssh`），所以"只填 key"= 使用客户端默认钥；remote role 必须显式给出的是 `key`。
  若要禁止这种默认钥形态，属于 spec 变更，需设计侧拍板。
* `enhanced_token` 只作校验：不落盘、不回显、不进日志（`/api/bug` 清洗规则同样覆盖该键名）。

## 4. 尚未做 / 已知边界

1. **key 变更后的 host-key 基准重建**：spec《中层配置文档》§6.5 说"key 变更视为新 endpoint，
   指纹按首信任重建"。当前 `user update` 只做整体形状校验（现在会校验凭据可解析），
   没有重新探测 host-key 首信任；需要在 update 流程补一次 probe（待定优先级）。
2. 注册页的增强凭据输入由前端子代理落地：`enhanced_token`（password 输入、local 声明必填、
   不写草稿、401 回表单）+ key 字段可见性/校验 + payload 映射；单测 27 passed，
   真 Chromium 走查见 `test/artifacts/evidence/enhanced-token-frontend-browser.json`。
3. `live` 注册 TB（`registration_http_six_step_tb.py`）在 local 模式下已带
   `enhanced_token`（管理员 token），remote 模式已带 `ssh.default.key_dir/key`。
