## 4. 代码事实与决策（不是猜测，附行号）

### 4.1 死代码（本轮只记录，不改代码）

| 位置 | 事实 | 结论 |
|---|---|---|
| `src/common/ssh.py:1966-1968` | `for attempt in range(2)` 内每条路径都 `return`/`raise`，循环后 `if last_exc is not None` 不可达 | 防御性死代码；建议后续清理，本版保留以免扰动评审 |
| `src/common/ssh.py:1872` | `_summarize_ssh_transport_error` 对空输入也返回非空串，`describe_ssh_command_failure` 的 rc 兜底分支只在 mock 下可达 | 同上；测试以显式 mock 固化该兜底语义 |

### 4.2 平台分支（不计入本轮缺口）

`supervisor.py` 的 POSIX 分支（`138/146/159/219/278/301-307`）、
`ssh.py` 的 `os.name != "nt"` 分支（`112/359` 等）、
`paramiko_backend.py` 的 POSIX `_windows_no_window_kwargs` 早返，
均由 CI 的 OS 矩阵覆盖（本机 Windows 上不可达）。相关用例已写成
`skipIf(os.name == "nt")`，在 Linux runner 上会实际执行。

### 4.3 观察项：常驻 shell 死亡后的并发命令（有复现，暂不定性为缺陷）

半真机 TB 首轮出现一次 `UnknownEffectError: persistent SSH shell exited
while the command was running`：`exit` 杀掉常驻 shell 后**立刻**发 8 条并发
命令时，其中一条读到了上一代 shell 的 EOF。

- 顺序复现（3/3）显示：shell 死亡后的下一条命令会正常重建，返回 `alive`；
- 该分支语义符合规范"确认未投递才重试，未知一律不重放"（宁可报
  unknown-effect，也不重放非幂等命令）；
- 因此本轮不改代码，仅记录；若评审要求，可后续让读线程在 EOF 时主动
  清空 `_shell_proc` 以消除竞态窗口。

## 6. 复算命令（可直接粘贴）

```powershell
$env:COVERAGE_FILE='test/artifacts/tmp/cov-combined.data'
$env:PYTHONPATH='src'
python -m coverage erase
python -m coverage run --branch --source=src -m pytest `
    test/offline/unit test/offline/integration test/offline/scenario -q
python -m coverage run --branch --source=src --append `
    test/semi/transport/ssh_backend_semi_tb.py `
    --host wsl-gent --out test/artifacts/evidence/ssh-backend-semi.json
python -m coverage report -m --skip-covered
python -m coverage json -o test/artifacts/tmp/cov-combined.json
```

> 注意：`COVERAGE_FILE` 必须与 `coverage json -o` 的输出路径分开，
> 否则会出现 "file is not a database"（本轮踩过一次）。
