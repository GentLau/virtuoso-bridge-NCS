关键真机结论（细节见 `doc/report/calibre-网表导出机制调查报告.md §8/§9/§10`）：

1. auCdl 需要 `checkCAPPERI = nil`（IC618 batch header 的未绑定变量，缺失即 `OSSHNL-411`）——已固定在 `si.env` + `.simrc`；
2. Calibre 的 specification 语句 **first-wins**：`INCLUDE <deck>` + 覆盖行的 control file **不能**改路径/primary；
   参数由 `params`（runset 键 → deck 语句**原位改写**）或 `runset=<远端 .runset 文件>` 带入，**不走 GUI**；
   表外键直接报错并列出支持项；deck 无占位符时 `gds/top/cdl` 可省（判据在参数应用之后算）；
3. 同期修：`run_dir` 不许落在 deck 目录内（否则 `cp -r` 自我递归）；`failure_kind` 不再被日志头的
   "SUBJECT TO LICENSE TERMS"/"(pending licensing)" 带偏成 `license`。

已知限制：不改写 deck 语义（只按白名单占位符替换）；`pex` 仍强制 `lvs_run_dir` 且 `fmt ∈ {none,spice,simple}`
（与官方 `-fmt` 模式表不完全一致，见调查报告 §5.2 G1–G3）；OASIS 不支持。
