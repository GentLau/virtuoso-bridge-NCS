## 2. 场景明细

### S1 单用户五接口 smoke（`test/tb/smoke_user.py`）
- 客户端：Windows；目标：wsl-gent 真实 daemon（用户 vb03，端口 65103，token `vb-vb03`）。
- 请求：skill `RBDToken`、command `echo smoke-ok`、upload 8KB、download 回读。
- 实测：skill 3.49s ok（返回 `vb-vb03`）、command 2.07s rc=0、upload 5.96s、download 4.68s **sha_ok**，FAILURES 0。

### S2 T2 五 role 跨主机（`test/tb/role_split_cross_host.py`）
- 客户端：Windows；`daemon=wsl-gent`、`gui=wsl-gent`、`command=file=spectre=vps`。
- 期望：每个接口落到自己 role 的主机，不因同 token 而串台。
- 实测：skill ok（token 校验通过）；command 返回 `iZz1iwzbaf5hy6Z`（vps）；GUI 命令返回 `GLIS-DESKTOP.localdomain`（wsl）；spectre 命令返回 vps 主机名；文件上传/下载 sha 一致；`errors=[]`。

### S3 T3 local/remote 混合（`test/tb/role_mixed_mode.py`，客户端在 wsl-gent）
- `daemon=command=file=local`，`gui=spectre=remote(vps)`。
- 实测：skill ok（`mix-1`）；command 落在本机（`GLIS-DESKTOP.localdomain`）；GUI/Spectre 命令落在 vps；文件在本地根（`/tmp/.../roots/file/m.bin`）sha 一致；`errors=[]`。

### S4 六步注册 + 单用户压力（`test/tb/stress_live.py`，真实 CIW）
- 客户端：Windows；注册新用户 `stress`，第四步部署后由已运行的 CIW 执行 `RBStop()+load(setup)`，第五步验收。
- 实测：`deployed` → `committed`（token `stress-545e40c1`）；
  - 命令 100 请求：business_rejected=0、http_errors=0、bad_value=0，p50 2.13s / p95 2.74s；容量拒绝重试 **14747 次**后全部成功（`thread pool exceeded` → 重试直到入池，符合“拒绝可重试”语义）；
  - skill 30 请求：全 ok，p50 0.84s / p95 3.19s；
  - 上传/下载各 20：全 ok（上传服务端 sha 校验、下载 sha 校验）。
  - 总墙钟 43.1s。

### S5 CDS.log 增量契约（`test/tb/p1_log_live.py`）
- log_level=all：写日志的 skill → `marker_in_log=True`（len 23）；无输出 skill → `log=""`；
- log_level=off：返回值 `log=""`，且 **IL 零附加操作**（不 flush / 不 fileLength / 不第二帧）；
- CDS.log 中桥注入标记计数 = 0（**只读不改**验证）。

### S6 CDS.log 逐字节校验（`test/tb/log_file_verify.py`，12 请求）
- 每次请求前 `stat` 记 offset，请求后用 `dd` 读真实 `[before, after)` 字节，与 HTTP 返回的 `log` 比较：**12/12 完全一致**（446B/21B 交替，符合写入/空转模式）。

### S7/S9 组合服务压测（`test/tb/composite_stress.py`）
- 每个请求是一个“组合服务”：上传 → skill → 命令 → 下载 → sha 校验（模拟真实业务链）；请求类型在 skill/命令/上传/下载/组合之间**随机乱序**，命令带 0–40ms 随机延时。
- S7 win-mixed（seed 21，60 ops，16 并发，10 用户：6 real@wsl + 4 fake@vps，fake 用户 channel_budget=2）：
  - 238 次容量拒绝、227 次重试、11 条链在 21 次重试上限内仍未拿到名额（全部为 `capacity rejected`，无错误数据）；
  - 延迟 p50 3.23s / p95 11.32s / max 13.23s；总 258.6s。
- S9 wsl-mixed（seed 22，40 ops，12 并发，8 用户：4 local + 4 fake）：
  - 210 次容量拒绝、200 次重试、10 条链重试上限内未完成（同样全是容量拒绝）；
  - 延迟 p50 0.24s / p95 1.65s（本地角色占比高）；总 35.1s。
- 说明：容量拒绝是**设计行为**（`kind=rejected`，返回 `thread pool/channel budget exceeded`，可重试不排队）；上述“未完成”是压测脚手架把重试上限设为 21 次的结果，不是数据错误。

### S8 更激进的 win-mixed（seed 11，80 ops，32 并发，上午轮次）
- 结果：402 次容量拒绝、386 次重试、23 条失败；其中 **6 条 skill 报 `Daemon connection failed (refused/reset)` 全部来自 vb04**——现场检查发现 vb04 的 Virtuoso/daemon 进程已不在（端口 65104 无监听），属**测试环境缺陷**，不是桥缺陷；其余 17 条为组合链容量拒绝。
- 处置：重启 vb04（`/home/Gent/project/vb04`，加载其 `.cdsinit`）后复测，S7 轮次已无任何 daemon 连接失败。
- 教训（写入环境维护）：长跑前先核对 `ss -tlnp | grep 6510x` 与 `pgrep -f ramic_bridge_daemon_3.py`，避免把环境死亡当成桥失败。

### S10 注册端口冲突（新逻辑真机验证）
- 在 wsl-gent 上以 local 模式注册 `lcNN`（daemon_port=6541x）时，旧 lcNN 实例仍在监听 → 第三步直接报 `daemon port 65411 already in use locally`，未进入第四步、未落盘；清理旧实例后重跑通过（S9）。

## 4. 未覆盖 / 本版明确不做

- **split-host 的 CDS.log 增量**：本版不返回增量（`log=""`+warning），既不在 SKILL/CIW 内读日志、也不让远端 daemon 读异地路径；后续方向见《本版范围与明确不支持 §2 第 8 项》，daemon 侧已留 `LocalFileRangeReader`/`_READER` 接缝。
- **X11 显示链路**：`gui` role 只承载 GUI 侧一次性命令；X11 转发/DCV/VNC 由站点负责，bridge 不代理显示。
- **跨机启动 daemon**：本版不实现（daemon 仍是 CIW 的本地 `ipcBeginProcess` 子进程）。
- **调度器集成（LSF/Slurm）**：`spectre` role 只执行一次性命令，提交由上层拼命令。
- 本报告未覆盖：多客户端（两个客户端同时操作同一远端账号）——项目约定“单客户端等价”即视为覆盖，见[客户端等价-C1](客户端等价-C1.md)。
