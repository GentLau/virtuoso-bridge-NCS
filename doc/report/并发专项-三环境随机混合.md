# 并发专项：三环境随机混合（单客户端多用户）

> 日期：2026-09-11
> 代码基线：`68ade2b`
> 执行脚本：`scripts/multienv_random.py`
> 性质：**真实执行结果**，非计划。

## 1. 目标与期望

- 目标：一个 Windows 客户端同时驱动“6 个真实 Virtuoso 用户（wsl-gent）+ 10 个协议级 fake 用户（vps）”，验证混合并发下：
  - 路由零错配（每个 skill 的 `RBDToken` 必须等于请求 token）；
  - 命令返回值正确；
  - 文件上传/下载 sha256 一致；
  - 随机乱序请求、业务拒绝重试、日志表现均符合预期；
  - 无崩溃、无断连不回。
- 期望：`errors=0`、`sha mismatch=0`、`bad route=0`；允许出现并记录业务拒绝与重试。

## 2. 拓扑（客户端在哪、多少个用户）

| 项 | 值 |
|---|---|
| 客户端 | Windows 本机（唯一客户端） |
| 用户总数 | 16 |
| 真实 Virtuoso 用户 | 6（`vb01..vb06`，wsl-gent，daemon 端口 65101-65106） |
| fake 用户 | 10（`cloud00..cloud09`，vps，daemon 端口 6701-6710） |
| SSH | Windows → wsl-gent 与 Windows → vps 各按 endpoint 建连 |
| 并发 | 64 worker |

## 3. 每个用户请求了什么、是否随机乱序

- 每个用户先保证 1 次上传（作为该用户下载的基准文件），其余 7 次按随机数分配：
  - `<0.40`：skill；
  - `<0.70`：command；
  - `<0.85`：upload；
  - 其余：download。
- 生成后整体 `shuffle` 打乱顺序（上传统一排在下载前，保证下载有基准文件可校验）。
- skill 分为两种：
  - 普通 `RBDToken`（期望回显该用户 token）；
  - 每 4 次真实用户 skill 里有一次执行 `progn(hiPrintToLogFile("<随机marker>") RBDToken)`，同时断言 `result.log` 包含该 marker（log 增量校验）。
- command 随机三类：`echo vb-<seq>`（期望回显）、`python3 sum(range(1,101))`（期望 5050）、`sleep 0.2`（期望 rc0）。
- upload 随机大小 1–32768 字节，记录本地 sha256；download 下载对应基准文件并比对 sha256。

## 4. 重试策略与本次实际重试

- 策略：业务拒绝（`thread pool exceeded` / `channel budget exceeded`）立即重试，最多 500 次、每次 10ms；传输瞬时错误（refused/reset/closed/banner/timed out）同样重试。
- 本次实际：`retries = {skill:0, command:0, upload:0, download:0}`（该 seed 未触发业务拒绝；传输瞬时错误未出现）。

## 5. log 表现

- 真实 Virtuoso 用户：随机 marker skill 的 `result.log` 必须只包含本次 `[start,end)` 增量并含 marker；纯 `1+1` 类请求 `log=""`；
- fake 用户：fake daemon 回 `log=""`；
- `log=off` 的“源头零获取”在本专项不重复测，见《log 契约-P1》专报。
