# spec r17 运行环境要求 — 代码落地说明（2026-09-23）

> spec：`SPEC-2026-09-23-r17`，《中层配置文档》v39 §1：
> 客户端 ≥3.9；五个 role 目标机器 **2.7+ 或 3.6.8+**；
> `role.daemon.python` 显式→校验、缺省→探测、失败=注册失败（§3 环境类规则）。

## 1. 逐条判定

| 要求 | 是否改代码 | 依据 |
|---|---|---|
| 客户端 ≥3.9 | **不需要** | 安装入口已由 `requires-python = ">=3.9"` 拒绝低版本；源码直跑 <3.9 在 import 阶段即失败。加运行期版本自检属冗余防御，不加。 |
| role 机器 2.7+ / 3.6.8+ | **需要**（注册探测） | 目标解释器不在我们进程内，唯一的校验时机就是注册第三步（显式→校验 / 缺省→探测）；不校验会"注册假成功、daemon 起不来"。 |
| daemon 两个变体真机可跑 | 已验证，无需改 | py2.7.18 5/5（P-043 cookie）；py3.6.8 5/5（无改动）。 |

## 2. 改动（只动注册探测，最小面）

`src/register/probe.py`

* `remote_python_major` / `local_python_major` → `remote_python_version` /
  `local_python_version`：探测命令由目标解释器直接打印 `major.minor.micro`
  （不再解析 `--version` 文案），返回三元组；
* 新增唯一判定 `python_version_supported(version)`（2.7+ 或 3.6.8+）；
  文本解析为私有 `_parse_python_version()`；
* `detect_remote_python()` 只在窗口内的解释器里选址（3.5/2.6 即使存在也跳过），
  避免把注定起不来的 daemon 部署上去。

`src/register/flow.py`

* 显式 python（local/remote）走同一个 helper `_validated_daemon_python()`：
  拿不到版本 / 版本低于窗口 → `RegistrationProbeError`，错误信息带实际版本与要求；
* 缺省探测失败的提示补上"need Python 2.7+ or 3.6.8+"。

**不做**：客户端不加启动自检；不新增配置字段；不改 daemon 协议与部署形态。

## 3. 证据

* `test/artifacts/evidence/py27-daemon-probe-green.json` → Python 2.7.18，5/5；
* `test/artifacts/evidence/py36-daemon-probe-green.json` → Python 3.6.8，5/5
  （`py27_daemon_probe.py` 同步修 1 行：py3.4+ 的 `-V` 走 stdout，原实现只读 stderr）；
* 边界/负例：`test/offline/unit/test_probe.py::test_python_version_window_r17`、
  `test_register_flow.py::test_local_explicit_python_below_r17_floor_is_rejected`
  与 `::test_remote_explicit_python_below_r17_floor_is_rejected`；
* 离线全绿：`python -m pytest test/offline/unit test/offline/integration test/offline/scenario`。
