# spec r17 运行环境要求 — 代码落地说明（2026-09-23）

> spec：`SPEC-2026-09-23-r17`，《中层配置文档》v39 §1：
> 客户端 ≥3.9；五个 role 目标机器 **2.7+ 或 3.6.8+**；
> `role.daemon.python` 显式→校验、缺省→探测、失败=注册失败（§3 环境类规则）。

## 1. 逐条判定

| 要求 | 是否改代码 | 依据 |
|---|---|---|
| 客户端 ≥3.9 | **需要（只警告）** | 低于 3.9 不拒绝启动：三个客户端入口各打印一条警告，说明版本不满足、后续行为未定义（可能零星位置出错）。安装入口仍由 `requires-python = ">=3.9"` 兜底。 |
| role 机器 2.7+ / 3.6.8+ | **需要**（注册探测） | 目标解释器不在我们进程内，唯一的校验时机就是注册第三步（显式→校验 / 缺省→探测）；不校验会"注册假成功、daemon 起不来"。 |
| daemon 两个变体真机可跑 | 已验证，无需改 | py2.7.18 5/5（P-043 cookie）；py3.6.8 5/5（无改动）。 |

## 2. 改动（只动注册探测，最小面）

`src/register/probe.py`

* `remote_python_major` / `local_python_major` → `remote_python_version` /
  `local_python_version`：探测命令由目标解释器直接打印 `major.minor.micro`
  （不再解析 `--version` 文案），返回三元组；
* 新增唯一判定 `python_version_supported(version)`（2.7+ 或 3.6.8+）；
  文本解析为私有 `_parse_python_version()`；
* `detect_remote_python()` 命中不在窗口内的解释器 → 返回 `None`；注册直接报错并
  提示用户**显式指定 `role.daemon.python`**，显式值再走同一套校验。不做
  "多候选里挑一个"的智能选址。

`src/register/flow.py`

* 显式 python（local/remote）走同一个 helper `_validated_daemon_python()`：
  拿不到版本 / 版本低于窗口 → `RegistrationProbeError`，错误信息带实际版本与要求；
* 缺省探测失败的提示补上"need Python 2.7+ or 3.6.8+"。

`src/common/runtime_env.py`（新，约 25 行）

* `warn_if_client_python_unsupported()`：`sys.version_info[:2] < (3, 9)` 时向
  **stderr** 打印一条警告（每进程只一次），**不抛异常、不拒绝启动**；
  三个客户端入口 `register/server.py:main`、`server/api_server.py:main`、
  `server/supervisor.py:main` 首行调用。走 stderr 是因为业务面 stdout 是
  supervisor 的 VB-EVENT 事件通道。

**不做**：不新增配置字段；不改 daemon 协议与部署形态；低于 3.9 仍然允许启动。
