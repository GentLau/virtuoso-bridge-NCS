隔离与边界：

- 每台一个独立 `labns` 网络命名空间：IP、端口空间、iptables、进程、主机名、文件系统独立；
- 身份 IP 挂在 labns 的 veth 上，共享命名空间用 proxy ARP 代答，Windows 无需新增路由；
- 共享同一 WSL 内核与内存池（CPU / 内存不隔离），压力测试按"一台 VM"的总预算约束。

## 6. 性能与压力边界

- `wsl-gent` 是本轮首选压力靶机（20 vCPU / 约 16GB）。
- VPS 仅用于低并发 fake daemon；禁止把它作为 100 用户高压靶机。
- Windows 本机可以执行 100 用户级远端规模测试，但必须使用隐藏子进程控制台、限制建连并发，并在测试前后核对 `ssh.exe` 基线。
- WSL 实验室四台共享同一内核与内存池；压力预算按"一台 VM"计算。

## 7. 已知故障与恢复

**排查顺序**（远程链路）：先验证中转机 `ssh 100.123.135.71`，再验证 `ssh wsl-gent`。
两者都超时 → 7.2；仅 wsl-gent 超时 → 7.1。

### 7.1 WSL 发行版停止（中转机在线）

**症状**：`ssh wsl-gent` 卡在 banner 超时，但 `ssh 100.123.135.71` 可连接。

**原因**：glis-desktop 重启（如 Windows Update 自动重启）后 WSL 发行版 AlmaLinux-8 停在 `Stopped`，172.18.80.17 消失。

**恢复**：
1. `ssh 100.123.135.71 "wsl.exe -l -v"` —— 确认发行版为 `Stopped`；
2. `ssh 100.123.135.71 "wsl.exe -d AlmaLinux-8"` —— 启动 WSL；
3. 重跑第 5 节健康检查。

### 7.2 glis-desktop 整机离线

**症状**：`ssh wsl-gent` 与 `ssh 100.123.135.71` 同时超时；`tailscale status` 显示 `glis-desktop ... offline`。

**原因**：glis-desktop 关机、休眠或断网。本机与其局域网（192.168.1.3）不同网段，无远程路径可达。

**恢复**：需现场开机；开机后 WSL 不会自启，继续按 7.1 处理。

**预防**：关闭 glis-desktop 自动睡眠（或启用 Wake-on-LAN），并配置 WSL 开机自启。

### 7.3 lab WSL 身份 IP 丢失（本机侧）

**症状**：`ssh w1-gent` ~ `ssh w4-gent` 超时，但本机 `wsl -l -v` 显示发行版在运行。

**原因**：distro 重启后 `labns` / veth / proxy ARP 未就绪（身份 IP 不在 netns 内）。

**恢复**：`wsl-lab-netns.service` 与 `wsl-lab-boot.service`（均已 enabled）会在 distro 启动时重建；先 `wsl -d w1-gent -- true` 触发启动，再按第 5 节复测。

**预防**：保持两个单元 enabled；不要在 distro 内手工删改 `labns`、`br-lab` 或 veth。
