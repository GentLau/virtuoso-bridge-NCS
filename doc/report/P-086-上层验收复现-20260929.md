# P-086 复现记录：多用户窗口后 30–90s 的 daemon 空响应窗口

> 日期：2026-09-29
> 报告人：设计/上层开发
> 归属：**中层/底层**（不是上层业务包）

## 现象

在标准业务面 8127、token `vb-vblog` 上做 P-070 / P-105 真机验收时，
多次出现同一类瞬态：

```text
RuntimeError: SKILL execution timed out
warnings: ["daemon returned an empty response"]
```

特征：

- 同一时刻 `basic.skill.execute("1+2")` 正常返回 `3`；
- `maeRunSimulation`、`geOpen`、`hiGetWindowList()` 等窗口/ADE 相关 SKILL
  在 30–90s 窗口内连续超时；
- 窗口过后无需重启，下一次同类调用直接成功。

## 本次最小复现

```python
# P-105 验收前的纯净性探针
for i in range(8):
    r = call("basic.skill.execute", skill_code="length(hiGetWindowList())")
    print(i, r)
    if r.ok:
        break
    time.sleep(15)
```

实测输出：

```text
0 False SKILL execution timed out
1 False SKILL execution timed out
2 False SKILL execution timed out
3 False SKILL execution timed out
4 True
```

同窗口内的其它现场：

- `virtuoso.symbol.screenshot` 首次 `ensure_window` 返回
  `SKILL execution timed out`；
- `virtuoso.layout.screenshot` 同一阶段的 `maeSetJobControlMode` /
  `geOpen` 也出现相同错误；
- P-070 正例的 `maestro.run` 首次尝试失败，30s 后同一调用成功，
  history 为 `MonteCarlo.0`。

## 上层侧的边界

上层没有把这个瞬态当成业务失败：

- `maestro_mc_e2e_tests.py` 只对“仿真尚未启动”的 pre-start 瞬态做 3 次
  有界重试，并记录 `start_attempts`；
- 截图包的正向链路改为“先单独 `geOpen`，客户端 sleep 1s 后再单独
  `hiWindowSaveImage`”；这解决的是窗口 map/redraw，而非掩盖 P-086。

需要中层/底层修复的方向是：

1. daemon 在请求执行/窗口事件期间的空响应与超时归因；
2. 区分“daemon 忙/无响应”与“SKILL 表达式真实失败”；
3. 保证 `1+2` 成功时，非窗口 CIW 操作不应进入同样的 30–90s 空洞。
