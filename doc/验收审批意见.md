## 二、必须先关闭的阻塞项

1. **参数分类冲突**：`配置一览.md:16` 将 token、`log_level`、`log_max_bytes` 说成不进配置，但同文件和日志标准又规定它们由 registry 配置注入。必须明确“持久化配置”和“每次调用携带字段”的双层语义。
2. **token 与 CIW 生命周期冲突**：架构规定一个 daemon 对应一个 CIW，`多用户设计.md:396` 又允许同 token 被多个 CIW load；固定端口/token 下路由不唯一。
3. **split-host 合同不完整**：架构承诺 skill/command/file/spectre 可分 host，但 file/spectre 用户、endpoint canonical key、指纹来源、逐 endpoint 探测、共享 scratch root 和 channel 作用域没有闭合。
4. **Spectre 范围矛盾**：本版声明不提供 Spectre 业务入口，却把 `spectre.bin` 自动探测/不可用设为注册失败条件。
5. **运行期检查矩阵缺失**：注册第五步、冷启动、断线重连对 host-key、hostname、daemon user、各 role endpoint 的检查范围和失败级别不一致。
6. **deadline/重试/错误合同缺失**：默认 timeout、connect timeout、最多 3 次重试、幂等重发、124/255 保留码与真实命令返回码的区分尚未统一。
7. **registry 生命周期未闭合**：跨进程写锁、token 碰撞、update 后缓存失效，以及“remove 删除本地条目但保留远端 daemon”时是否真正撤销 token 未定义。
8. **日志内部协议未完全冻结**：第二 metadata frame 的字节格式、UTF-8 截断、`log_max_bytes` 说明行豁免、非法配置“拒绝或夹紧”二选一尚未定稿。
9. **注册 schema/输入与跨平台路径合同不完整**：缺少 canonical 注册 API/schema、端口 reservation/TOCTOU、mode×route 矩阵和 Windows 路径碰撞规则。
10. **版本治理未执行到底**：README owner 列表漏列 Normative 的“本版范围”文档；多个冻结文档仍是 Draft 且缺少 `Supersedes`/统一 release manifest。

上述事项均会影响 API、路由、安全边界或测试判据，不能仅作为后续优化。

## 三、重复机制与索引审批意见

以下机制仍在多处以完整规则或默认值重复出现，应按唯一 owner 收口：

- token 生命周期/目视授权/daemon 校验：以《多用户设计》为 owner；架构和配置只保留边界与字段索引；
- per-token × endpoint、ControlMaster、channel budget：以《并发处理设计》为 owner；架构只写原则，配置只写 schema/default；
- `deploy.scratch_root`、文件默认根、非沙箱：以架构 §5.6 定义语义，配置只列字段；
- 六步注册失败/事务行为：以《多用户设计》为 owner，配置只列输入目录，demo 只做非规范演示；
- CDS.log 旧 marker/cursor：移到明确 Historical 附录，demo 目录表必须注明已废弃；
- `TB测试场景验证报告.md`、未提交的 research/07 文件需要加入正确分类和索引，不能隐式成为冻结基线。
