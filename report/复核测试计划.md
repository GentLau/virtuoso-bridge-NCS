# 复核测试计划

> 版本：v1
> 日期：2026-09-11
> 依赖：[复核测试环境](./复核测试环境.md)
> 定位：本文只写**测试计划**（目标、案例、参数、步骤、验收）。环境怎么搭看《复核测试环境》，测试结果不写在这里。

## 1. 目标

在三个环境组合下复核重构后的中层/底层/注册链路，重点验证：

1. 单客户端多用户、多终端多客户端、Windows/Linux 客户端三种拓扑下路由正确；
2. 本地模式（wsl-gent 同机）与远端模式（wsl 真实 Virtuoso / 云 fake daemon）业务三接口等价；
3. 混合并发下“指令一一有回应、拒绝即重试、不串路由、文件不损坏、进程不崩”；
4. 建连失败重试、断线恢复、`log=off` 零获取等新收口行为；
5. 弱机（云）作为远端端点时的边界与背压表现。

## 2. 通用验收口径

- 每条指令必须有结构化回应（200/成功结果），最终无 `thread pool exceeded` / `channel budget exceeded` 残留；
- 路由零错配：`RBDToken`（真实 Virtuoso）或 fake daemon 回显 token，逐请求等于请求 token；
- 上传/下载 sha256 零不一致；
- 允许出现“业务拒绝”与“重试”，禁止出现崩溃、断连不回、HTTP 层错误；
- latency 只记录，不设固定硬指标；硬指标为：完成率 100%、错配 0、损坏 0。

## 4. 案例步骤与验收

### E1 三环境自检
- 执行环境文档 §6 全部 smoke；记录三机 CPU/内存/时延基线。

### R1 单用户 remote（wsl-gent 真实）
- 六步注册 → CIW load → verify commit → `execute_skill("1+1")==2` → `run_command("echo vb-ok")` → 上传/下载 sha256 一致。
- 验收：六步全部成功，注册表落盘一次；`log` 为本次 `[start,end)` 增量。

### R2 单用户 remote（云 fake）
- 同样六步注册到云 fake 端口 → verify → 三接口。
- 验收：token 路由正确、回包解析正确、命令/文件走 SSH 到云机。

### M1 单客户端多用户混合
- 注册 6 个 wsl 真实用户（`vb01..vb06`）+ 10 个云 fake 用户（`cloud01..10`），同一注册表；
- 每用户混合 2 skill + 2 command + 1 upload + 1 download，并发 80；
- 验收：路由零错配、sha 零不一致、全部回应；wsl 实例内存不越界。

### M2 100 用户自动路由
- 100 用户全部云 fake（或 70 云 + 30 本机 fake），并发 200；
- 600 command + 400 skill + 200 upload + 200 download；
- 验收：全部 200、错配 0、sha 0、无 HTTP 错误。

### L1 wsl 本地模式
- 在 wsl-gent 上跑 `test/e2e/test_business_local_live.py`（`VB_LOCAL_USERS=6`）；
- 验收：六步本地注册、无 SSH、常驻命令会话保状态、并发全过。

### L2 wsl 客户端混合
- wsl 客户端注册表含 4 个 local 用户 + 4 个 remote 云 fake 用户；
- 同一 `BusinessServer` 混合三接口并发；
- 验收：local 走 127.0.0.1、remote 走 SSH，互不影响。

### T1 双客户端同一批云 fake
- 本机与 wsl-gent 各自客户端，分别驱动同一批云 fake 用户中的不同 token；
- 两客户端同时并发；
- 验收：无跨客户端串扰、token 各自回应正确。

### T2 双客户端正交
- 本机客户端 → wsl 真实用户；wsl 客户端 → 本地用户；同时并发；
- 验收：两条链路结果独立正确。

### C1 Windows/Linux 客户端等价
- 同一 remote（云 fake）用户，分别在 Windows 与 Linux 客户端跑同一业务序列；
- 验收：结果语义一致；文件内容一致。

### F1 首连突发与重试
- 50 个新用户在弱机上同时首连；触发 banner 断连；
- 验收：瞬时失败被 3 次内重试吸收；无法恢复时返回 `VB-TRANSPORT:`；无崩溃。

### F2 daemon 被杀后重连
- 杀一个云 fake daemon → 重启同端口同 token → 客户端继续调用；
- 验收：隧道/连接自动重建，后续调用成功。

### P1 log 行为（真实 Virtuoso）
- `log=all`：用户 skill 用 `hiPrintToLogFile` 写一行，返回 log 只含该行；
- `log=off`：IL 不 flush/不 fileLength/不第二帧（静态断言 + 真机行为），返回 `log=""`；
- 检查 CDS.log 无 `VB-BEGIN/VB-END` 注入；
- 验收：上述全部成立。

### P2 极限压力到拒绝
- 云 fake 100 用户，并发 400→600 逐步加，直到出现 `thread pool exceeded`/`channel budget exceeded`；
- 客户端立即重试；
- 验收：最终全部成功、无错配、无损坏；记录首次拒绝并发档与重试次数。

## 6. 执行顺序

E1 → R1/R2 → L1 → M1 → M2 → L2 → T1/T2 → C1 → F1/F2 → P1 → P2。

## 7. 不覆盖项

- 不测 Spectre 消费入口（本版不支持）；
- 不测 GUI/deploy 分裂、split-host CDS.log（本版不支持）；
- 不在弱机云上跑真实 Virtuoso（环境无 Virtuoso）；
- 不做 100 个真实 Virtuoso 同机并发（wsl-gent 15G 内存装不下，以“最多可开实例数 + fake 混合”覆盖路由面）。
