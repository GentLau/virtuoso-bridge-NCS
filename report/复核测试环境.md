# 复核测试环境

> 版本：v1
> 日期：2026-09-11
> 定位：本文只描述**测试环境**（有哪些机器、各自角色、如何接入、如何准备与复位）。测试要跑什么、怎么组合，见同目录《复核测试计划.md》，本文不写计划与验收。

## 1. 三台环境总览

| # | 名称 | 系统 | 性能 | Virtuoso | 本项目里的角色 |
|---|---|---|---|---|---|
| 1 | 本机（开发机） | Windows | 强 | 无 | 中层客户端 / 注册客户端 / 压力发起端 / 本地假 daemon 宿主 |
| 2 | wsl-gent | Linux（WSL） | 强 | **有**（IC6.1.8，X11 DISPLAY=:10） | 真实 Virtuoso 目标 / 本地模式运行机 / 也可当客户端 |
| 3 | 114.215.183.227 | Linux（云服务器） | 弱 | 无 | SSH 中转（跳板）/ 远端假 daemon 宿主（协议级模拟 Skill） |

- “性能强/弱”是相对描述；云服务器弱机的准确并发上限在测试中实测，不在此假设。
- 三台都要求：Python 3.8+（测试 venv 内安装 `pydantic`、`paramiko`、`pytest`、`coverage`）、可用的 OpenSSH 客户端。

## 2. 网络拓扑与接入方式

```text
本机（Windows，客户端）
  ├── SSH ──────────────────────────► 114.215.183.227（云，跳板 + 假 daemon 宿主）
  └── SSH(经云中转) ─────────────────► wsl-gent（WSL，Virtuoso + 本地模式运行机）

wsl-gent（客户端场景）
  └── SSH ──────────────────────────► 114.215.183.227（云，假 daemon 宿主）
```

接入约定：

| 目标 | 接入方式 | 说明 |
|---|---|---|
| 114.215.183.227 | 直连 SSH | 本机和 wsl-gent 都可直连；SSH 账号由现场配置提供 |
| wsl-gent | `ssh wsl-gent`（透明入口） | 底层经云中转实现，但**使用方不配置跳板**；对测试而言就是一个普通 SSH 目标。通道不可达时表现为 banner 超时，根因是中转端离线，与测试代码无关 |

## 3. 每台机器的预置组件

### 3.1 本机（Windows）

- 仓库工作副本：`C:\Users\user\Desktop\repos_Github\virtuoso-bridge-NCS`；
- 测试 venv：项目 `.venv`；
- 运行中间层客户端：`src/transport/middle.py` 的 `BusinessServer`，工作目录（注册表）按每轮测试独立建；
- 协议级假 daemon：复用 `scripts/stress_multiuser.py` 中的 `FakeDaemon`（TCP `127.0.0.1:<port>`，STX/NAK + JSON，token 校验，backlog 128），可同时起多个模拟多用户；
- SSH 工具：OpenSSH（`ssh`/`scp`），`~/.ssh/config` 含云服务器与 wsl-gent 两条目标。

### 3.2 wsl-gent（Linux，有 Virtuoso）

- 仓库工作副本（部署运行用）：`/home/Gent/vb-ncs`（src/test 同步方式：`scp -r` 或 git）；
- venv：`/home/Gent/vb-ncs/.venv`；
- Virtuoso：IC6.1.8，`DISPLAY=:10`，登录账号 `Gent`；
- 真实 daemon：每个 CIW 由 `load(.../setup/virtuoso_setup.il)` 拉起一个 `ramic_bridge_daemon_3.py`，绑定 `127.0.0.1:<port>`，token 注入 il；
- 多实例布局：每用户独立目录 `/home/Gent/project/<user>/`（其中 `.cdsinit` load 对应用户 setup），远端桥目录 `/home/Gent/.virtuoso-bridge/<user>/`；
- 工具脚本：`scripts/multi_virtuoso_pilot.py`（批量注册+起 Virtuoso）、`scripts/restart_vb_virtuosos.py`（批量重启）。

### 3.3 114.215.183.227（Linux，无 Virtuoso）

- 只作为：①跳板；②“模拟 Skill 的远端端点”——运行协议级 fake daemon，监听 `0.0.0.0:<port>` 或 `127.0.0.1:<port>`；
- fake daemon 部署：把 `scripts/stress_multiuser.py` 中的 `FakeDaemon`（或单独抽出的 fake-daemon runner）上传到云机运行，每个用户一个端口一个 token；
- 无 Virtuoso：此环境**不做** `execute_skill` 的真实求值，只验证中层“路由到正确远端端口 + token 校验 + 回包解析 + 命令/文件 SSH 通道”；
- 弱机约束：单轮并发、请求超时、SSH 会话数按“弱机”档位设置，具体数字见测试计划。

## 4. 模式与路由约定

| 模式 | 谁当客户端 | Skill 目标 | 命令/文件目标 | SSH |
|---|---|---|---|---|
| remote → wsl-gent | 本机 或 wsl-gent | wsl-gent 内 Virtuoso daemon | wsl-gent | 有 |
| remote → 云 | 本机 或 wsl-gent | 云 fake daemon 端口 | 云服务器 | 有 |
| local（仅 wsl-gent） | wsl-gent | 本机 Virtuoso daemon（127.0.0.1 直连） | wsl-gent 本机 | **无** |

- 端口规划：wsl 真实 daemon 用 `65101+`；wsl 本地模式用 `65401+`；云 fake daemon 用 `67001+`；本机隧道/假 daemon 用 `65081+`；每轮测试从空端口表开始，避免残留冲突。
- 用户命名：`vbNN`（wsl 真实远端）、`lcNN`（wsl 本地）、`cloudNN`（云 fake）；token 与端口一一对应并登记进各轮测试自己的 registry 工作目录。
- 注册表：每轮测试使用独立本地工作目录；本地模式部署目录落在该工作目录下。

## 5. 环境准备步骤（仅环境，不含测试执行）

1. 本机：确认 `.venv`、SSH 到云与 wsl-gent 通；
2. 云机：建测试目录、上传 fake daemon runner、确认监听端口可用；
3. wsl-gent：同步 `src/` 与 `test/`，装 venv 依赖，确认 `virtuoso` 与 `DISPLAY=:10`；
4. wsl-gent：按需要起 Virtuoso 实例（先小批量，边起边看 `free -h`，可用内存低于 2G 停止加实例）；
5. 三台机器统一对时（供 latency 对比）。

## 6. 就绪自检（环境级 smoke）

| 检查 | 命令（示意） | 通过标准 |
|---|---|---|
| 云 SSH | `ssh <cloud> echo ok` | `ok` |
| wsl SSH | `ssh wsl-gent echo ok` | `ok` |
| Virtuoso | `ssh wsl-gent 'pgrep -fc virtuoso'` | ≥ 计划实例数 |
| 真实 daemon | `ssh wsl-gent 'ss -tlnp | grep 651'` | 计划端口全部 LISTEN |
| 云 fake daemon | 本机 `python` 连对应端口发 token 帧 | 收到 `02 {"value":…} 1e` |
| 云弱机资源 | `ssh <cloud> free -h; nproc` | 记录基线 |

## 7. 资源与复位

- 每轮结束：关闭本轮起的 fake daemon、SSH 隧道（本机 `ssh.exe -L 65*`）、临时 Virtuoso 实例、删除本轮 registry 工作目录；
- 不跨轮复用端口/token；复用真实 Virtuoso 时先 `RBStop()`/重启实例，避免旧 daemon 占端口；
- wsl-gent 15G 内存：真实 Virtuoso 实例与并发档位必须遵循计划中的内存预算。
