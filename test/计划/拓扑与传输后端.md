# 测试计划 · 拓扑与传输后端

## 目标
显式 jump/proxy 与 config 跳板的等价与隔离；Windows local role；paramiko `max_sessions` 与后端切换；四节点组合全覆盖。

## 流程（纲领）
1. **jump/proxy**：显式 `jump_host/jump_user`、`ssh.default.proxy`（SOCKS5）与 `~/.ssh/config` ProxyJump 三种路由同目标对照；
2. **Windows local role**：在 glis/本机（Windows）跑 local 命令/文件角色，与 WSL local 对照（E11）；
3. **backend**：openssh/paramiko 切换不改变上层结果；paramiko `max_sessions` 达上限时返回与 openssh 同义的拒绝；
4. **四节点组合**：本机→vps、本机→wsl(经 glis)、glis→wsl(直连)、glis→vps、wsl 本地，逐组合冒烟。

## 预计响应
- 三种路由结果一致；显式 jump 与 config jump 不冲突（显式优先）；
- Windows local 与 WSL local 语义一致（路径/退出码/文件一致）；
- backend 切换结果一致；`max_sessions` 上限表现为可重试拒绝；
- 四节点全组合冒烟通过。

## 环境
本机/glis/wsl/vps 全组合。

配置一览 §2.2/§2.3、§6.5 与多节点 §6 对应证据。
