# 测试计划 · 并发与容量

## 目标
per-token 线程池/channel 预算、单 CIW 串行、命令串行/显式并行、文件并行、拒绝可重试不污染；同 token 多 endpoint 共享一份预算；≥100 用户自动路由；同账号多用户隔离。

## 流程（纲领）
1. **预算隔离**：一个 token 打满，另一个 token 同发零排队；分别打满线程池与 channel，区分两种拒绝文本；
2. **同 token 多 endpoint**：一个 token 的 role 分布两台机，打满验证预算按 token 合计、不按 endpoint 另计；
3. **拒绝→重试**：每 token 高频并发，被拒立即重试至成功；统计拒绝/重试/接受集合；
4. **语义并行性**：同 token 命令 `parallel=True` 时间重叠；不同 token skill 并行；同 token skill 串行；
5. **文件并行**：多路上传/下载并发，sha 全对；验证文件校验子命令不另占 channel 名额；
6. **同账号多用户**：多个 user 共用同一 SSH 账号，命令流/返回/文件不串；
7. **规模**：≥100 用户（真实+fake）随机乱序五接口，逐步加压至 `rejected`，弱机（vps）只允许"拒绝"不允许崩溃/断连；
8. **组合链**：上传→skill→命令→下载→sha 的服务器侧组合服务，并发逐链校验。

## 预计响应
- 被接受调用 100% 成功（HTTP 200 且业务语义正确，零错误值/零 sha 不一致）；
- 超限返回 `kind=rejected`：`thread pool exceeded` 与 `channel budget exceeded` 两种文本各自对应其预算；
- 重试后入池成功；单 CIW 串行、跨用户并行（时间证据）；
- ≥100 用户全路由成功、无跨用户串扰；同账号多用户隔离成立；
- 延迟无硬性 SLA，但必须记录分位；弱机允许高延迟、不允许断连。

## 环境
E2/E8（本机）、E4（wsl 混合）、E9（≥100 用户）。

## 判据
并发处理设计 §11.2 预算矩阵逐行有证据；拒绝/接受/重试计数完整。
