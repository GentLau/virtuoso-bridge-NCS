# 测试计划 · 并发与容量

## 目标
验证 per-token 线程池与 channel 预算、单 CIW 串行、命令默认串行/显式并行、文件天然并行、拒绝可重试且不污染结果；≥100 用户自动路由。

## 流程（纲领）
1. **预算隔离**：一个 token 打满，另一个 token 同发，观察后者零排队；超限请求逐条记录 `kind=rejected`；
2. **拒绝→重试**：对每 token 高频并发，被拒立即重试直至成功，统计重试次数与被接受集合；
3. **语义并行性**：同一 token 内命令 `parallel=True` 的时间区间重叠；不同 token 的 skill 并行、同一 token 的 skill 串行；
4. **文件并行**：多路上传/下载同时进行，sha 全对；
5. **规模**：≥100 用户（真实+fake 混合）随机乱序五接口，逐步加压至出现 `rejected`，保持每用户高频高重试；
6. **组合链**：上传→skill→命令→下载→sha 的服务器侧组合服务，在并发下逐链校验。

## 预计响应
- 被接受的调用 100% 成功（HTTP 200 且业务语义正确，无错误值、无 sha 不一致）；
- 超限返回 `kind=rejected`（`thread pool/channel budget exceeded`），可重试；重试后入池成功；
- 单 CIW 串行（顺序证据）、跨用户并行（时间重叠证据）；
- ≥100 用户全路由成功；弱机（vps）上限表现为"拒绝"而非崩溃或断连；
- 无任何跨用户串扰。

## 环境
E2/E8（本机）、E4（wsl 混合）、E9（≥100 用户 vps 假 daemon）。

## 判据
预算矩阵（并发处理设计 §11.2）逐行有证据；拒绝/接受/重试计数完整。
