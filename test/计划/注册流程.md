# 测试计划 · 注册流程与 reservation

## 目标
验证六步注册状态机、缺省端口分配时序、reservation 的跨进程互斥与回收、失败不留半成品、注册与使用解耦。

## 流程（纲领）
1. **正常链**：申请→本地校验→探测（固化 expected_* 与绝对 role.root）→部署→第五步连通→落盘；
2. **失败注入**：参数错 / 用户重名 / 端口冲突 / ssh 不可达 / 探测不满足 / 部署失败 / 第五步 NAK / 指纹不匹配，逐项验证回退且 registry 无新条目；
3. **端口时序**：显式端口查重；缺省端口在锁内分配（local_port 第二步、远端 daemon_port 第三步），并发两注册不同时选中同一端口；
4. **等待续租**：第四步后长等待（>宽限），验证心跳续租不被误回收；模拟 pid 失效/时间戳超宽限的回收；
5. **解耦**：注册完成后盘点无 ssh 隧道/mux master/控制 socket，仅剩 registry 与远端部署文件。

## 预计响应
- 任一必检失败 → 对应步骤失败，第六步前 registry 零写入；
- 探测后：各 role.root=绝对路径、root.default=null、expected_* 固化；
- 同主机同端口 → 拒绝；异主机同号 → 允许；local daemon 端口作用域=本机；
- 等待期间心跳使 reservation 持续有效；pid 失效且超宽限才回收；
- 注册结束后除文件系统变更外零残留。

## 环境
L2 全流程本地；L3/TB 用 E1/E3；并发注册用 E3/E8。

## 判据
每一步的"预测目标/失败合同"与多用户设计 §3.2 表逐行对应。
