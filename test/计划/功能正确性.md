# 测试计划 · 功能正确性（五接口）

## 目标
验证五接口（Skill / RunCommand / File 上传+下载 / GUI / Spectre）的参数、执行位置与返回语义符合架构 §4；文件语义符合 §4.5 文件执行合同。

## 流程（纲领）
1. **Skill**：函数级解析 → 协议级假 daemon → 真机 `RBDToken`/算术/`printf` 与写日志表达式；核对输出、token 回显、`log`。
2. **RunCommand**：`echo` 冒烟 → 依赖顺序（串行）→ `parallel=True` → 超时 → 非零退出码透传。
3. **File**：单文件往返 sha256 → `recursive` 目录树 → 类型不符/源缺失/目标已存在覆盖 → local 与 remote 对照。
4. **GUI/Spectre**：各自 role 上 `hostname` 类一次性命令；验证两次调用互无状态继承。

## 预计响应
- Skill：正确表达式 `status=success` 且输出符合 SKILL 语义；非零/错误表达式 `status=error` 且不落为 command 类错误；
- 命令：默认串行保持提交顺序；`parallel=True` 两命令执行区间重叠；退出码原样透传；
- 文件：单文件双向 sha256 一致；目录整树一致（跳过逐文件校验）；类型不符/源缺失 → `kind=path`；覆盖后无半成品；local≡remote；
- GUI/Spectre：返回目标 role 主机证据；连续调用无 cwd/env 继承；占用该 token 的 channel 预算（并发下可见 `rejected`）。

## 环境
L0/L1/L2 全环境；L3/TB 用 E1（本机→wsl 真实）、E3（wsl 本地）。
