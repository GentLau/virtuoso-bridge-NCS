# 测试计划 · 运维生命周期（user update/remove、指纹更新、registry 并发写）

## 目标
验证多用户设计 §11：user update 白名单与原子覆盖、remove 本机解绑非远端吊销、机器重装指纹更新、跨进程写锁、load-once。

## 流程（纲领）
1. **user update**：改白名单字段（ssh.*、root.default、role.*、runtime.*、cdslog.*、expected_*）→ 整体校验 → 原子覆盖（文件 0600、tmp+原子替换）；改后关闭该 token 缓存连接、下次重建；非白名单字段拒绝；
2. **user remove**：原子移除条目并关闭缓存/tunnel；远端 daemon 仍接受原 token（本机解绑≠远端吊销），直到 `RBStop()`+删部署；
3. **跨进程写**：两进程并发写 registry，验证 OS 文件锁 + 读改写原子替换不丢更新；
4. **冷启动**：启动只 load 一次；运行期不因 update/remove 自动感知（重启/reload 生效）；
5. **指纹更新**：机器重装后显式 update expected_fingerprint（同 endpoint 多 role 一起更新同一值）；未确认前按不匹配拒绝。

## 预计响应
- update 白名单内成功且旧缓存连接关闭；白名单外拒绝；
- remove 后本机无路由，远端仍可被旧 token 连（符合"本机解绑"）；
- 并发写不丢更新；load-once 语义成立（不频繁文件 IO）；
- 指纹更新后恢复连接；未确认前 ERROR。

## 环境
L2 为主；多进程写锁 L2 本地；真机 E1/E3。

## 判据
多用户设计 §11 生命周期表逐行对应。
