# 测试计划 · 可靠性与资源回收

## 目标
验证连接/隧道/常驻 shell 失效自愈（投递前）、投递后不重发；每轮结束零资源残留；同种子可复现。

## 流程（纲领）
1. **隧道失效**：杀 `ssh -N` 隧道进程 → 后续请求自动重建；
2. **daemon 失效**：杀 daemon → 后续 skill 结构化失败 → 重启 daemon → 重连成功；
3. **shell 失效**：投递前杀 shell → 透明重建；投递后杀 → `unknown-effect` 且不重发；
4. **mux 卡死**：模拟遗留/卡死的 ControlMaster → 探测降级直连恢复；
5. **回收盘点**：注册、压测、异常退出各一轮后，清点 ssh 进程/监听端口/控制 socket/reservation/临时目录；
6. **复现性**：固定种子重跑，结果集与计数一致。

## 预计响应
- 投递前失效全部自愈且调用方无感（上层只看到成功）；
- 投递后失效不重发、不双重副作用；
- 每轮盘点 0 残留（进程/端口/socket/reservation/临时文件）；
- 同种子重跑结果一致。

## 环境
L2 mock + 真机 E1/E3；mux 场景用 Windows 客户端（openssh）。

## 判据
故障注入清单与恢复证据一一对应；盘点表为 0。
