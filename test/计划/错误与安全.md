# 测试计划 · 错误合同与安全

## 目标
验证错误 `kind`/保留码/前缀/固定文本与架构 §4.4 一致；token 与指纹安全边界生效。

## 流程（纲领）
1. **错误注入**：连不上、断连、路径缺失、超时、容量、校验失败、unknown token 逐项触发；
2. **unknown-effect**：命令投递后杀 shell/断连，验证不重发（远端副作用计数=1）；
3. **安全**：错 token、错端口、指纹变更、hostname/user 漂移、部署目录权限、token 是否出现在路径。

## 预计响应
- `kind` 与保留码逐行符合 §4.4：timeout=124、transport=255+`VB-TRANSPORT:`、path+`VB-PATH-NOT-VISIBLE:`、unknown-effect+`VB-UNKNOWN-EFFECT:`、checksum=`sha256 mismatch`、invalid-token 固定文本 `invalid token`；
- 错 token：NAK `invalid token`、SKILL 零接触；
- 指纹不匹配 → ERROR 阻断；hostname/user 漂移 → WARNING 不阻断；
- 用户可读路径只含用户名、不含 token。

## 环境
L0/L1 mock；L2/L3 真机 E1/E3。

## 判据
§4.4 表逐行有"注入→期望→实测"证据。
