# 测试计划 · 错误合同与安全

## 目标
`kind`/保留码/前缀/固定文本与架构 §4.4 一致；token、指纹、部署权限安全边界。

## 流程（纲领）
1. **错误注入**：连不上/断连/路径缺失/超时/容量/校验失败/unknown token；
2. **重试上限**：无副作用阶段（建连/握手/隧道）最多 3 次总尝试，副作用阶段不重试；
3. **unknown-effect**：命令投递后杀 shell/断连 → 不重发（远端副作用计数=1）；
4. **安全**：错 token/错端口/指纹变更/hostname·user 漂移/同 endpoint 多 role 指纹不一致/部署目录 700/banner 不回显 token/load 时打印 token 本身（目视确认，不附加用户名）/token 不进路径。

## 预计响应
- `kind`/保留码逐行符合 §4.4（timeout=124、transport=255+`VB-TRANSPORT:`、path+`VB-PATH-NOT-VISIBLE:`、unknown-effect+`VB-UNKNOWN-EFFECT:`、checksum=`sha256 mismatch`、invalid-token=`invalid token`）；
- 重试只在无副作用阶段且 ≤3 次；
- 错 token NAK `invalid token`、SKILL 零接触；指纹不匹配 ERROR；hostname/user 漂移 WARNING；同 endpoint 指纹不一致拒绝注册；
- 部署目录权限 700；banner 无 token；路径只含用户名。

## 环境
L0/L1 mock；L2/L3 真机 E1/E3。

## 判据
§4.4 表逐行"注入→期望→实测"证据。
