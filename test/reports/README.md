## 0. 去留规则（新增/保留报告前先读）

一份报告只在这三种情况留在本目录，其余（重复的逐轮清单、被取代的覆盖率版本、已完成的一次性分析）**及时删除**——删前先 commit，git 历史可查：

1. **未关闭项的当前证据**——被 [问题登记.md](问题登记.md) 或 [bugs/](bugs/README.md) 引用；
2. **当前口径锚点**——覆盖率/环境/验收的唯一权威数字或判据；
3. **最近一轮报告**——同类轮次报告只保留最近一轮，旧轮随下一轮清理。

命名：`<主题>-<YYYY-MM-DD>.md`，轮次报告 `round<N>-<主题>.md`；同主题复审计用新日期，旧版在下一轮清理（不在目录里堆版本）。

## 3. 审计报告怎么写

命名 `<主题>-<YYYY-MM-DD>.md`；同主题复审计用新日期。
必备六项：范围与口径 / 方法（可复现命令） / 结论表（`编号｜归属｜文件:行｜代码事实｜应写路径｜触发条件｜建议｜级别`） / 反例（合规项）/ 未覆盖与不确定项 / 登记编号。

判定口径（用户 2026-09-22 裁定）：**只认代码事实**——`文件:行` + 触发条件 + 算出的路径；
磁盘上有没有残留文件**不构成证据**。推荐路径的定义见 [`../docs/写TB规范.md`](../docs/写TB规范.md)。

## 4. 规则

- 只审计，不改业务代码；修复另有负责人，审计者不给自己发结论；
- 每条结论要有 `文件:行` 与可复现命令，不接受"我搜过了"；
- 结论逐条登记进 [问题登记.md](问题登记.md)，报告只留证据；
- 中间文件按规范落盘，禁止写共享 `/tmp`。
