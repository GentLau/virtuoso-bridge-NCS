## 1. 真机启动口径（必须遵守）

Cadence 把 `CDS.log` / `CDS.log.cdslck` / `.cadence/` / `.artist_states/` / `*.ahdlSimDB/` 写到**启动时的 cwd**。

规则：

1. 启动 cwd = `~/.virtuoso-bridge/<user>/run/`（不要 `$HOME`，也不要工程目录）；
2. `cds.lib` 放工程目录 `~/project/<user>/`（带工艺库场景直接 `cp ~/project/test/cds.lib`，内含 tsmcN65 PDK 与 TEST_* 设计库）；
3. 运行态文件就留在 run 目录；启动日志写 `~/.virtuoso-bridge/<user>/logs/start.log`；
4. 起之前清目标 run 目录里的**陈旧 `*.cdslck`**；
5. 实例命令：`cd <run> && DISPLAY=:99 nohup virtuoso -cdslib <project>/cds.lib -log <run>/CDS.log > <logs>/start.log 2>&1 < /dev/null &`

历史反例（实测）：`pid=369800 cwd=/home/Gent/project/vblog`；73 个工程目录 68 个含 `CDS.log`、69 个含 `start*.log`；
`$HOME` 根有 `CDS.log`、`.artist_states/`、14 个 `*.ahdlSimDB/` 与若干陈旧锁 —— 就是从这里来的。

### 2.4 分主机 role 的后端选择（2026-09-22 实测，S2 踩到）

**现象**：把 `command`/`file` role 指到 `w1-gent`/`w2-gent` 后，直连 `ssh w1-gent hostname` 正常，
但经 bridge 调用返回 `rc=255, kind=transport`：

```
VB-TRANSPORT: Paramiko backend requires recorded host keys;
StrictHostKeyChecking=accept-new is not supported for host 'w1-gent'
```

**根因**：`~/.ssh/config` 里 `w1-gent`…`w4-gent` 写的是 `StrictHostKeyChecking accept-new`，
而 paramiko 后端按设计**只接受 `yes`/`ask`**（`src/common/paramiko_backend.py` 的
`strict_host_key_checking not in ("yes","ask")` 判定）；`wsl-gent` 没写这一行所以默认通过。

**处置（两种，任选）**：

1. **推荐**：该 profile 的注册表里把 `ssh.backend` 设为 `"openssh"`（本机 ssh 支持 accept-new），
   不改用户 ssh config —— S2 就是这么修的，重跑即 5/5 全绿；
2. 或把这些主机的 host key 预录进 known_hosts，并把 ssh config 该行改成 `StrictHostKeyChecking yes`。

**排查提示**：这类失败在 bridge 侧表现为 `kind="transport"`，**stderr 里有完整原因**；
写角色类 TB 时务必把 stderr 记进证据（本 TB 第一版只记 stdout/returncode，白跑一轮）。

## 3. 内存账（为什么不能 20 个真机）

- 单实例 RSS 实测 **0.9–1.0 GB**（`ps -o rss`：971 MB、820 MB）；
- wsl-gent：总 **15.9 GB**、当前可用 **13.3 GB**；
- 20 真机 ≈ 18–20 GB > 物理内存 → **不可行**；留 2 GB 余量后真机上限 **10–12 个**；
- 需要 20 个真机 → 必须增加一台装 Cadence 的机器（当前没有）。默认给 S4 配"真 4 + fake 16"。

## 4. lab WSL 的实测特性

- **空闲 1–2 分钟自动停机**（实测 18:47 起 → 18:56 已 `Stopped`），身份 IP 与 ssh 一起消失；
  → 起环境必须保活：`wsl.exe -d <host> -- sleep infinity`（`env_up.py` 已内置，`down` 时用 `taskkill /PID /T /F` 释放）。
- fake 实例由 `sudo ip netns exec labns` 拉起（`sudo -n` 免密），**真实监听方是子进程**：
  `ramic_bridge_daemon_3.py 0.0.0.0 <port> <token> <tmp>`；只杀父进程端口不释放。
- `pkill -f` 会匹配到自己的命令行 → 用 `[.]`/`[k]` 之类写法避免自杀（`fake_virtuoso[.]py`、`envchec[k]`）。
- 就绪窗口 30–60 s（建链+首次绑定），判断用 TCP 探测而不是 ssh 返回。
