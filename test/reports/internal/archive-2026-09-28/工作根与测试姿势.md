## 1. 产品口径（别绕开）

`common.paths` 的 work root 是**进程级、一次绑定**的基座：

* 入口（`api_server` / `supervisor` / `register.server`）在启动时调 `init_work_dir(<--work-dir>)`，**一个进程只绑一次**；
* 同一个路径重复调用是幂等的；**不同路径 → `RuntimeError`**（"Tests that need another path must start a new process"）；
* 运行期**不换根**：`registry.json` / `config.json` / `temp/` / `log/` / `artifact/` 都挂在同一个根下。

> 因此测试**不许**为了"干净环境"去换根 —— 真实部署里没有这个动作。

## 2. 测试怎么用（三条规则）

| 场景 | 正确做法 |
|---|---|
| **pytest 用例**（`test/offline/{unit,integration,scenario}/test_*.py`） | 由 `test/conftest.py` 的 **session fixture 绑定唯一一根**（会话私有 temp 下的 `work-root/`）；用例**不调用 `init_work_dir`** |
| 用例需要"干净的注册表" | 靠 `conftest.py` 的 **`_reset_shared_registry`**（每个用例开始前清 `registry.json`）；需要并存多个用户时用**各自的名字** |
| 用例需要"另一个根" | **起子进程**（路径敏感的正确姿势）：见 `test/offline/unit/test_workdir_contract.py`（用 `python -c` 跑一段脚本，子进程自己绑自己的根） |
| **独立脚本/TB/probe**（`test/live/**`、`test/semi/probes/**`、`test/offline/core/*_tb.py`） | 它们是**入口**：在 `main()` 里 `init_work_dir(<--work-dir>)` 绑一次自己的根（合法） |
| 用例写的产物要独占 | 在**共享根内**给目录/文件名加自己的前缀（例如 `work_root()/f"tree-{uuid}"`），或在 `setUp` 里清掉自己那几个子目录 |

## 3. 常见坑（本轮真实踩过，2026-09-24）

1. **每个用例 `init_work_dir(自己的临时目录)`** → 第 2 个用例起全部 `RuntimeError: work dir already initialized`（曾一次打红 518 条）。
2. **跨用例共享根导致的产物残留**：例如 `work_root()/tree/...`、`work_root()/log/bug_reports/*.tmp` —— 用例要**只断言自己新产生的文件**（比较 `mtime`/清目录/用唯一名字），别假设"根里只有我"。
3. **全局打桩 + 计数**：`mock.patch.object(subprocess, "Popen")` 会连**别的用例遗留线程**的调用一起数（P-065 家族）。计数要按**本用例的标识**过滤（端口、远端目录、stage 路径）。
4. **别在 import 期绑根**：模块级 `init_work_dir(...)` 会在 collection 阶段抢先绑定，导致 session fixture 只能"沿用"（`conftest` 会打印一行提示）。把绑定留给 conftest 或脚本 `main()`。
