#### P-048 结论更新（2026-09-24）：**重判为口径/用法问题（非产品缺陷）**

**spec 原文**（我逐条查的）：
- `spec/design-concepts/其他/1-多用户与注册.md:11`：注册表"启动时导入一次到内存快照，运行期**不自动读文件**，管理操作成功后由**业务进程管理端点**触发重新导入或重启"；
- `spec/design-concepts/顶层/add-控制面与业务面.md:87`：`POST /api/process/reload`（**管理权限**）"重新导入 registry.json 与 config.json、关闭旧 token 缓存"；
- 同文件 :114："业务进程启动与 `/api/process/reload` 或 `restart` 各导入一次，运行期不读文件、请求期零文件 IO"。

⇒ **热重载本来就要"手动发命令"**（管理端点显式触发），**不是**产品缺自动热更新。

**代码/测试对账**：`process/status|reload|restart` 只在控制面（`src/register/server.py:211-212,224,290`）暴露，业务面 `api_server.py` 没有任何 process 端点；
离线已有 `test_business_child_supervision.py::test_reload_swaps_registry_snapshot`（spawn 通道语义）与
`test_supervisor_process.py`（HTTP 管理端点协议）；
**本轮我补了端到端语义 TB**：`test_supervisor_process.py::test_http_reload_picks_up_registry_file`（4/4 绿）——
① 改 `registry.json` 但**不** reload → 新 token 仍 `invalid token`（= 不自动读文件）；② `POST /api/process/reload` 后**立即可用**。

**真实差异（归测试侧口径）**：我们的常驻/多跳业务面用 `python -m server.api_server` **standalone** 启动，
而 spec 的标准形态是「控制面 spawn 业务面」的双进程；standalone 没有父进程控制通道 → 拿不到 reload 命令，只能重启进程。
这属于**测试台用法口径**，不是产品缺陷；已写进环境文档。
**产品侧可选增强（不立案）**：若希望 standalone 也支持 reload，需要新增一个受管理权限保护的入口——spec 未要求，随产品决定。

* `:307`「swept 数据支持 delta 压缩：后续 step 缺省信号沿用前值；**首个 step 未出现信号用 `NaN`，不得静默填 0**」
  ⇒ 解析器写 `math.nan` 是**照 spec 做的**；
* `:308`「**对外 `value.data` 必须 JSON-safe**」（`:363` 第 7 条重复）、`:290` CSV「缺失值留空」
  ⇒ 对外不能出现 NaN。
* 实现：`psf_external()`（`:321`）对 float 原样放行 → 实数 trace `[nan, 0.9]`、复数 trace
  `{"re": [nan, 0.0], ...}` ⇒ **违反 :308**，严格客户端 `loads_strict` 整包拒收。

**结论**：内部用 NaN 正确；**错在对外转换**，且 spec 两处需要在"内部 vs 对外"上写清边界。
**修法（设计侧二选一，建议①）**：① `psf_external()` 把非有限 float 映射为 `None`（对外 `null`），
内部 NaN 语义不变；② 坚持对外也用 NaN → 必须改 :308/:363 的 JSON-safe 要求（严格客户端会拒收，不建议）。

**测试侧已做**：`test/offline/unit/test_output_json_safety.py` 用真实 PSF 文本复现该分支（2 条红，预期）
+ 1 条业务面严格兜底负控制（绿）；验收：对外 NaN→`null`/省略，整体可 `dumps_strict`。
