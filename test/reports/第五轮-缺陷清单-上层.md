## A. 待修（8 条）

### A-0　P-059 [P2] `calibre.read_results` 解析真实 Calibre 2025 `DRC.rep` 失效

* **事实**：`src/pyapi/packages/_calibre_util.py:179-196`（`parse_drc_report`）与 `:148-149`（`_DRC_RULES`/`_DRC_RESULTS`）只认旧格式：
  * 逐规则计数正则 `^(RESULT|CHECK) <name> <n>` —— 真报告是 `RULECHECK <name> …… TOTAL Result Count = N` ⇒ **`by_rule={}`**（本例 36 条违规、27 条命中规则全丢）；
  * 总数只认 `TOTAL RULECHECKS EXECUTED =` —— 真报告写 `TOTAL DRC RuleChecks Executed:` ⇒ `None`（线上只能靠 log counters 兜底，两处口径不一致）；
  * `first_offenders` 把头部 `RUNTIME WARNINGS` 段（`Cell name parameter … for INSIDE CELL operation not located.`）当违规，产出 `rule="Cell"/cell="operation"` 垃圾。
* **复现/验收**：`python -m pytest test/offline/unit/test_calibre_parsers.py -q`（当前 **6 红**：DRC 4 + LVS 2）
* **实机复现**：`test/semi/probes/calibre_package_http_probe.py --kind drc …`（run completed、`read_results.ok=true` 但 `summary` 是垃圾），证据 `round5-main/calibre-drc.json`；真报告裁剪样本 `test/shared/fixtures/calibre_drc_rep_sample.txt`
* **影响**：spec《12-calibre》§3 承诺的"分类计数 + 前 N 条违规"对用户不可读。
* **修复建议**：按 `RULECHECK … TOTAL Result Count =` 聚合；总数同时接受新旧两种写法；剔除头部告警段（坐标级明细在 `DRC_RES.db`，报告本身不含）。
* **验收**：上述 TB 的 4 条 DRC 用例转绿；`calibre-drc.json` 的 `by_rule` 非空、无 `Cell/operation` 垃圾条目。

### A-1　P-062 [P2] `calibre.read_results` 把 LVS 结论截成半个词、计数读不出

* **事实**：`_calibre_util.py:151` `_LVS_STATUS = r"LVS completed\.\s*(\w+)"` —— 真结论是 `LVS completed. NOT COMPARED.` ⇒ 只吃到 `NOT` → `status="not"`；`:152` `_LVS_COUNT` 只认 `name = n`，而真报告计数是**表格**（` Ports:  1  4  *`）⇒ `counts={}`。
* **复现/验收**：`pytest test/offline/unit/test_calibre_parsers.py -q -k lvs`（2 红）
* **实机证据**：`round5-main/calibre-lvs.json`（`status="not"`、`counts={}`）；样本 `test/shared/fixtures/calibre_lvs_rep_sample.txt`
* **影响**：用户无法区分 CORRECT / INCORRECT / NOT COMPARED。
* **修复建议**：verdict 支持多词（`NOT COMPARED` → `not_compared`）；计数解析覆盖 `INITIAL NUMBERS OF OBJECTS` 表格（layout/source 两列）。
* **验收**：2 条 LVS 用例转绿。

### A-2　P-061 [P2] calibre 阻塞轮询对"工具已死 + 日志终止性 ERROR"不快退

* **事实**：`_calibre_util.py:104-111` `_FAIL_MARKERS` 不含通用 `ERROR:` 形态，`:133-145 job_state` 只在这些标记下判 failed。实测 LVS 因输入错误 2 秒退出（`lvs.log:21115 ERROR: Can not open source netlist file …`），但 `calibre.status` = `unknown / failure_kind=null / process_alive=false`，blocking 调用**轮询到超时**（实测 >9 分钟，包内 timeout=1800s）。
* **复现/验收**：`pytest test/offline/unit/test_calibre_job_state.py -q`（2 红：通用 ERROR→input、许可字样→license；另有 2 条负控制绿）；证据 `round5-main/calibre-lvs-fastfail.json`
* **修复建议**：把"进程已死 + 日志终止性 ERROR"纳入失败判据（至少 `ERROR:` / `Can not open` / `FAILED`），并区分 license/input。
* **验收**：2 条转绿；用同一探针复跑应在秒级返回 `failed`。

### A-3　P-053 [P1/P2] Spectre AC 结果链路两处断

* **事实**：① `_spectre_util.py:384 parse_psf_directory` 的候选名只有 `("ac.ac","ac.ac.ac","*.ac.ac")`（`:406`），而 spectre 按**分析名**落盘 —— 分析名非字面 `ac`（默认 `ac1`）时整个 AC 数据集丢失（`status=partial/analyses=[]`）；② 解析出的键带 `ac_` 前缀，而 `spectre.measure` 的 AC 默认 `x="freq"`（`_spectre_util.py:1039` 优先级表），按 spec 形状调用报 `ValueError: signal 'freq' is missing`。
* **复现**：`python test/semi/probes/spectre_ac_pipeline_probe.py`（verdict=both）→ `round4-probes/round4-spectre-ac-pipeline.json`；场景侧 `round4-scenario/serdes/serdes-sim.json`
* **修复建议**：解析候选加 `*.ac`（或按 netlist 分析名推导）；measure 默认 x 与解析前缀对齐（或在 spec 明确要求 `x="ac_freq"`）。
* **验收**：探针 verdict=clean；SerDes 场景 AC 指标不再依赖显式前缀。

### A-4　P-054 [P2] 层次化 `symbol.generate` 残留子单元 symbol view → 同会话二次生成必失败

* **事实**：为顶层生成 symbol 时，叶子 symbol cellview 生成后仍处于打开状态；之后再对叶子 `symbol.generate` 撞守卫 `_symbol_generate.py:144 error("target symbol is open")`。SerDes 场景连跑两次即复现（第 1 次 9/9 绿但留下 3 个打开视图，第 2 次立刻失败）。
* **复现**：`python test/semi/probes/symbol_generate_hierarchy_handle_probe.py`（verdict=child-symbol-left-open）→ `round4-probes/round4-symbol-hierarchy-handle.json`
* **修复建议**：生成收尾关闭本次打开的子单元视图（或先探测/自动处理再报错）。
* **验收**：探针转绿 + SerDes 场景连续两次全绿。

### A-5　P-052 [P2] `schematic.set_instance_params` 改的是母单元 cell 级 CDF 默认值

* **事实**：`src/pyapi/packages/schematic.py:488` 取 `cdfGetCellCDF(ddGetObj(inst~>libName inst~>cellName))` 后直接写 `~>value`，随后才 `cdfUpdateInstParam(inst)` ⇒ 给实例设参会改写**共享库单元**的默认值（实测 `analogLib/res.r` 1K→777、`tsmcN65/nch_25.w` 400n→3u，会话内可见、跨会话不可见）。
* **复现**：`python test/semi/probes/shared_cdf_pollution_probe.py`（verdict=same-session-only）→ `round4-probes/round4-shared-cdf-pollution.json`
* **修复建议**：只写实例层（`cdfGetInstCDF` / `dbSetInstParamValue`），不触碰 cell CDF；或写前备份并在结束时还原。
* **验收**：探针 verdict=clean，且 SerDes/ADC 场景在共享库上重复运行不再污染默认值。

### A-6　P-069 [P2·功能不可用] Calibre LVS 全链跑不通：auCdl 对 PDK 器件导出 CDL 失败

* **事实**：含 PDK 器件的 cell 走 CDL 导出时 `si -batch`（auCdl）失败，报 `hnlCDLParamList` / `hnlCDLFormatInst` 缺失 ⇒ **没有可用源网表** ⇒ `calibre.lvs` 只能给出 `NOT COMPARED`（再叠加 P-062 会被截成 `not`）。**DRC 侧正常**（completed，1737 rulechecks / 36 结果），所以这是 LVS 这一段业务链本身跑不通，不是"环境噪声"。
  **用户 2026-09-24 判定**："这不就是业务包本身跑不通？" ⇒ 从"环境/配方口径问题"**改判为产品缺陷**。
* **复现**：在 wsl-gent 上对含 PDK 器件的 cell 做 CDL 导出（`si -batch`）→ 跑 `calibre.lvs`；或 `python test/semi/probes/calibre_package_http_probe.py --kind lvs`（专用环境 `test/artifacts/env/s11-calibre` + 业务面 8128）→ 真机 `round5-main/s11-flow2.log`（lvs FAIL）、`round5-main/calibre-lvs.json`（`status=NOT COMPARED`、`counts={}`）。
* **修复建议**：① 明确"CDL 导出能力 vs PDK 侧属性模板（`hnlCDLParamList` 由 PDK 提供）"的归属；② 让 `si -batch`/auCdl 对 PDK 器件可用，或提供等价的 CDL 生成路径（例如直接生成 Calibre 可读的 source netlist）。
* **验收**：含 PDK 器件的 cell 能导出可用 CDL，`calibre.lvs` 给出 **CORRECT / INCORRECT** 的确定结论（不再是 NOT COMPARED）；S11 `lvs` 阶段 PASS；两项目全链（SerDes RX / ADC SAR）的 LVS 段 PASS。

### A-7　P-070 [P2·能力缺失] 蒙特卡洛：只能读回 MC 结果，不能驱动 MC 仿真

* **事实**：全 `src/` 搜 `monte\|carlo`（忽略大小写）**只命中 1 行**（`_maestro_util.py:141` 的历史目录正则 `^(?:Interactive|MonteCarlo|ExplorerRun)\.\d+$`）；**没有任何配置/启动 MC 分析的代码**；`spectre` 侧分析枚举只有 `tran/dc/ac/info/noise`。spec 里 MC 只出现在 `6-maestro.md:130` 的锁语义（"被引用锁（reference / MC reuse）"）。
  现状 = **只能读回别人跑完的 MC 结果**（`parse_overall_yield` 解 yield/mean/sigma、`natural_sort_histories` 认 `MonteCarlo.N` 目录），**不能驱动 MC 仿真**。用户 2026-09-24 判定：能力缺失要提 bug。

* **修复建议（先定口径，二选一）**：① **支持驱动 MC** —— 允许配置 montecarlo 分析并启动，跑完能读回 yield/mean/sigma；② **不支持** —— 在 spec 明确写"只读 MC 结果、不驱动"，标为明确不做。
* **验收**：① 真机跑一次 MC 且与 ADE GUI 的 yield/mean/sigma 对数一致；或 ② spec 有不支持声明（测试侧改为"不覆盖声明"）。
