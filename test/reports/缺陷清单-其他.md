## A. 仍待修（源码类，按优先级）

### A-0　P-050 [P1・**CI 现在是红的**] daemon 模块在伪 stdin 下不可导入（Linux 客户端 / CI 口径）

* **事实**：两个 daemon 都在**模块级**做 `sys.stdin.fileno()` + `fcntl(F_SETFL, O_NONBLOCK)`：
  `src/bridge/resources/ramic_bridge_daemon_3.py:87-89`、`ramic_bridge_daemon_27.py:97-99`。
  pytest 会把 stdin 换成伪文件（`DontReadFromInput`，其 `fileno()` 抛 `io.UnsupportedOperation`），
  于是 Linux 上**采集期**直接炸：`pytest`（CI 同口径，testpaths 三个离线目录）→
  **6 个 collection error**（`test_log_off.py` / `test_daemon_parity.py` /
  `test_daemon_runtime_contracts.py` / `test_new_core.py` / `test_daemon_handler.py` …）。
* **为什么之前没被发现**：验收只在 **Windows** 上量过 3.9（`venv39/Scripts/python.exe`）——
  Windows 下 `_fcntl is None`，这段根本不执行；而 CI 的 linux 作业（ubuntu-latest，矩阵 3.9/3.13）
  就是 Linux 口径，**当前应为红**。
* **影响**：Linux 客户端（spec 要求客户端 ≥3.9；S6 还要 Windows/Linux 一致性）无法导入这两个模块；
  CI linux 作业拿不到任何离线结论。
* **复现（已固化为 TB）**：`test/offline/unit/test_daemon_import_contract.py`
  （Linux 红 / Windows skip），或在 Linux 上直接 `python -m pytest -q`。
  证据：`test/artifacts/evidence/round3-daemon-import-red.txt`、`round3-linux-collect-red.txt`。
* **建议修法**：把这段包进 `try/except (io.UnsupportedOperation, OSError, ValueError)`（拿不到 fd 就跳过设非阻塞），
  或推迟到 `main()/start_server()` 执行；**不要**依赖"stdin 一定是真文件"。
* **验收**：Linux 上 `python -m pytest -q` 能采集并跑完三个离线目录；该 TB 由红转绿。

### A-3　P-048 [P2 新] 运行中的 business API **不会重载 registry**：已注册 token 被判 `invalid token`

* 复现（本机 8127，work-dir=`test/artifacts/env/log-vblog`）：

```
$ python test/shared/runners/skill_eval.py --token vb-s11 "1+2"
  status=error errors=['invalid token']
$ python test/shared/runners/skill_eval.py --token vbs11 "1+2"
  status=error errors=['invalid token']
$ (registry.json 里 "vbs11" → "token": "vb-s11"，daemon_port 65200 都在)
```

* 机制：`src/transport/middle.py:463` 只在 `BusinessServer.__init__` 里 `load_registry(registry_path())` 一次；热更新只有 supervisor 的 stdin 控制命令 `{"cmd":"reload"}`（`src/server/api_server.py:430`）。本机 8127 是**独立启动**的（`python -m server.api_server --port 8127 --work-dir …`，pid 11932），**没有 stdin 控制通道** → registry 变更永不生效。
* 影响：先起 API 再注册/改 registry，就永远是 `invalid token`；测试环境里表现得像"实例挂了"，实为控制面快照过期。（这一症状此前被并入 P-045，后者已撤回，故单列。）
* 建议：① 业务面提供 HTTP reload（或按 registry mtime 自动重载）；② 独立启动时在 `/health` 暴露 registry 快照时间，便于判定"是否需要重启"。

> **2026-09-23 裁决回执（我复核后同意）**：设计侧**驳回**建议①②，理由与 spec 一致 ——
> 《控制面与业务面》§4 规定业务端口只做 operation 调度（不开注册/管理/配置端点），
> §5 规定 config/registry 运行期不读文件、请求期零文件 IO。
> **规范路径**：用 `python -m server.supervisor` 起控制面+业务面双进程，改注册表后走控制面
> `POST /api/process/reload`；**standalone**（`python -m server.api_server`）变更后必须重启进程。
> 我已独立复跑：`test/offline/integration/test_business_child_supervision.py` **5 passed**（含 `test_reload_swaps_registry_snapshot`）。
> 测试侧动作：环境文档补"改注册表后重启 8127 / 或走 supervisor reload"（已写入 `docs/环境与场景.md`）。
