# 测试计划 · 总览与执行约定

> 版本：Draft v2 · 日期：2026-09-16
> 依据：`spec/README.md`（当前 Release 哈希以 README 记录为准；`tools/check_spec.py` 可复算）
> 本目录是一组**按方面拆分**的测试计划；本文定义共用的环境、分层、判据与报告格式，各分册只写本方面的目标/流程/预计响应。

## 1. 被测范围
中层（transport）五接口、注册流程（register）、底层 daemon、上层对五接口的消费路径。上层业务内部实现不在范围内。

## 2. 测试节点

| 节点 | 系统 | 角色 | 可用性 |
|---|---|---|---|
| 本机 | Windows（性能强） | 客户端 1 / 控制端 | 常备 |
| wsl-gent | Linux WSL2（AlmaLinux-8，真实 Virtuoso/Spectre） | 真机靶机 | 常备；首选压力靶机 |
| glis | Windows（wsl-gent 宿主机，Tailscale） | **仅中转点** | 不承担测试负载 |
| w1~w4-gent | 本机 4 个 WSL 发行版（lab 网 172.20.170.21~24） | 本地靶机 / 备选客户端 | 默认 `Stopped`，用前启动；w1 为 fake Virtuoso 宿主 |
| vps | Linux 云服务器（低性能，无 Virtuoso） | 低并发 fake daemon | **可选**——本地 lab 可用时不必使用 |

连通：本机↔vps 直连；本机→wsl-gent 经 glis（ProxyJump）；glis↔wsl-gent 同机直连；
本机↔w1~w4-gent 走 lab 网直连（w3 另有 socks 入口与跳板角色）。
环境事实、健康检查与实测记录见 `test/docs/环境说明.md`（IT 权威源：`doc/report/环境支持.md`）。

## 3. 分层
L0 函数级（`test/offline/unit`）→ L1 集成（`test/offline/integration`）→ L2 场景（`test/offline/scenario`）→ 真机轮（`test/live/`：真机 pytest `test/live/e2e`、压测与覆盖率 TB）。
L0–L2 进常规 CI；真机轮与手工 TB 一律显式运行。

## 4. 统一执行约定
- 各分册按**测试项**组织：每个测试项包含 测试目标 / 测试流程 / 预计响应 三要素，并由对应 TB **完整执行一次**，产出“输入→期望→实测”证据；
- 每轮前跑环境健康检查（ssh 可达、daemon 端口监听、目标进程存活）；环境死亡记为**环境缺陷**，不计为被测系统失败；
- 每轮固定随机种子；请求允许随机乱序与随机延时；
- **压测位置与靶机**：压测靶机优先使用 wsl-gent（20 核/16GB）；vps 是弱目标，禁止当高并发靶机。Windows 客户端可执行 100 用户级规模测试，但必须隐藏子进程控制台、限制建连并发并做压测前后进程盘点；本地模式 100 用户可在 WSL 内完成。lab 四台 WSL 共享同一内核与内存池，预算按“一台 VM”计算，不得同时开多台高压。
- 每轮结束做**资源盘点（远端 + 客户端）**：远端无隧道/mux master、无端口占用残留、无临时文件增长；内存 reservation 不产生 `registry.reservation`；客户端 SSH 进程数不得随请求数单调增长，压测后应回到基线，且无 `conhost` 累积。
- 所有容量拒绝只允许以 `kind=rejected` 出现；被接受的调用**零数据错误**；
- 每份报告必须含：环境、客户端、用户构成（几 local/几 remote）、请求分布、重试次数、延迟分位、期望 vs 实际、失败归因。

## 5. 分册索引
功能正确性 / 路由与多节点 / 注册流程 / 注册页与HTTP层 / 并发与容量 / 等价性 / 日志返回 / 错误与安全 / 可靠性与资源回收 / 输入安全与首信任 / 运维生命周期 / 拓扑与传输后端。

## 6. 准出标准
1. 各分册"预计响应"全部有对应证据；2. L0–L2 全绿；3. 容量行为符合 §4；4. 每轮资源盘点为 0 残留；5. `tools/check_spec.py` 通过；6. 未覆盖项显式标注 PENDING/豁免。

## 7. 本版明确豁免（不测 / 不支持）
- split-host 的 CDS.log 增量（本版不返回，见范围文档 §2.8）；
- 跨机启动 daemon（daemon 为 CIW 本地 `ipcBeginProcess` 子进程）；
- X11 显示链路与显示代理（`gui` role 只承载一次性命令）；
- 文件系统安全沙箱（root 只是工作目录约定）；
- 非对称签名 / HMAC、`request_id`、argv/无 shell 模式、异步 command handle；
- 多客户端同时操作同一远端账号：以"单客户端等价"原则覆盖（见等价性分册 E7）；
- paramiko 经 ProxyJump 的等价性：jump 链路验证通过前标注 PENDING，不参与准出。
