# 用例分层与归口

> 新用例放哪一层，按本页判；审核按本页查"该有的层有没有"。
> v1.2（2026-09-23）：改用三级口径（离线/半真机/真机）；v1.1 补的"密闭本地资源例外"归入离线级（见 §3）。

## 1. 判据：先问"需不需要真机"

**需要真机吗？** 不需要 → **离线**；需要但只跑局部/单点 → **半真机**；需要且覆盖用户的完整动作序列 → **真机**。

| 级别 | 目录 / 资产 | 判据 | 进 CI |
|---|---|---|---|
| **离线** | `test/offline/unit/` | 进程内可判定；参数、分支、错误路径 | ✅ |
| **离线** | `test/offline/integration/` | 真实 socket / 真实子进程，但不要 Virtuoso | ✅ |
| **离线** | `test/offline/scenario/` | 跨组件流程（六步注册、隔离、local 链） | ✅ |
| **离线** | `test/offline/core/`、`test/offline/frontend/` | 本地夹具即可判定（协议/语义/故障注入；注册页 mock） | ❌（属离线级，但按 TB 习惯显式跑） |
| **半真机** | `test/semi/probes/`、`registration/cov_registration_real.py`、`transport/{log_matrix_real_tb,one_shot_burst_tb}.py`、`fakevirt/` | 需真机，但只跑局部/单点，用于过程调试与确认 | ❌ |
| **真机** | `test/{e2e,packages,stress,flows}/`、`registration/registration_http_six_step_tb.py`、`transport/cov_remote_real.py` | 全真环境，按用户完整动作序列 | ❌ |

- 用了 `mock`/纯夹具就不该算半真机或真机证据；
- 同一行为可以跨级覆盖，但结论只认与场景匹配的级别。

## 2. 命名

- 文件：`test_<被测主题>.py`；TB：`<主题>_tb.py` 或 `<包>_e2e_tests.py`；
- 用例：`test_<行为>_<期望>`，不要 `test_1`、`test_tmp`。

## 3. 硬规则

- **离线级**（`unit/integration/scenario`）不得在仓库内落文件（含 `test/artifacts/`）；
- `unit/` 不得起服务、不占固定端口；
- **离线级例外（v1.1）——密闭本地资源允许**：`127.0.0.1:0` 临时端口短连接、本机解释器子进程、
  `tempfile` 临时目录可以用在 `unit/`（离线级），前提是三条同时满足：① 不访问外部网络/远端；
  ② 不 bind 固定端口（`8124`/`8127`/`651xx` 只能作为数据出现）；③ 用完即释放（`finally` 或 fixture）。
  理由：这类用例验证的仍是进程内契约，loopback 只是让被测对象拿到真实 fd。
  现属此类的 9 个文件：`test_daemon_parity.py`、`test_models_paths.py`、`test_probe.py`、`test_process_lifetime.py`、
  `test_register_flow.py`、`test_registry_decoupling.py`、`test_registration_server.py`、`test_registry_more.py`、`test_stress_server.py`。
  新写用例绑 `127.0.0.1:0`，不得用 `0.0.0.0`。
- `integration/`、`scenario/` 用固定端口必须探测占用并在 `finally` 释放；
- 新增 TB 要登记到 `test/shared/runners/` 或所在子目录 README。

## 4. 红→绿

1. 先写能复现的用例并留红灯证据；
2. 修复后同一用例转绿，红绿证据成对保留；
3. 只有绿灯没有红灯的"修复"不予采信；
4. 环境问题（靶机离线、端口被占）不算红灯。
