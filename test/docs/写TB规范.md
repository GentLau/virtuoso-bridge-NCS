# 写 TB / 探针 / 压测的规范

> **读者**：写 `test/semi/**`、`test/live/**` 脚本的人（`test/offline/**` 的用例同样按本页 AAA 与状态还原要求写）。
> **读完能做什么**：按六步流程写出一份"结论可复核"的 TB —— 有前置构建、有读回比对、有证据、有还原规则。
> **不覆盖**：测试侧内部流程（谁负责哪块、历次轮次）见 `../reports/internal/`。

## 0. TB 注释头（**定死的规矩**：3 栏，固定顺序）

每份 TB / 探针把下面 4 行放在文件最上方（模块 docstring 之前），逐字照抄键名与顺序：

```python
# === TB 注释头（规范见 test/docs/写TB规范.md §0）=========================
# 作者: 设计/<名字>
# 最后改动: 2026-09-28 15:04
# 依赖: 无
# =======================================================================
```

**硬性规则**（检查器按这些判，违反即"不合格"）：

| 栏 | 允许值 | 说明 |
|---|---|---|
| 作者 | `测试/<名字>` 或 `设计/<名字>` | **本人填**，机器不代填 |
| 最后改动 | `YYYY-MM-DD HH:MM` | **必须精确到分钟**，严格这个格式（后面不要跟说明文字） |
| 依赖 | 其它 TB 的路径（多份用英文逗号 `,` 分隔）或 `无` | 只写"这份 TB 要跑起来还依赖谁"；没有就写 `无`，不得留空 |

> **注释头里只放这 3 栏**：不写六步流程、不写被测对象/判据/证据（那些放 TB 的 docstring）。
> 有的 TB 在注释头下面另贴了一块 `# §1–§6` 自述——那是**可选**写法，不是规范要求（见 §1 末尾）。


## 1. 六步流程（顺序固定；每步用不上时写一行注释说明即可）

| # | 步骤 | 做什么 | 不通过怎么办 |
|---|---|---|---|
| 1 | **检查环境是否为所需环境** | **需要真机时**在 TB 里调一次现成脚本：<br>① Python 一行（推荐）：<br>`sys.path.insert(0, str(ROOT / "test" / "shared" / "runners")); from env_check import require_environment`<br>`require_environment(base=<业务面>, token=<token>, expect_host=…, expect_user=…, require_lib=["…"])`<br>② 命令行（外部脚本 / 手工复跑）：<br>`PYTHONPATH=src python test/shared/runners/env_check.py --base <业务面> --token <token> [--expect-host/--expect-user/--require-lib/--require-calibre/--require-spectre/--expect-python] --json <path>`<br>检查内容：宿主、用户、token+command role、SKILL 通道（`1+2`）、库/工艺可见性、calibre/spectre、解释器版本；进程内 TB 用 `--work-dir` 代替 `--base`。<br>**不需要真机的（如离线用例）**：写一行注释说明即可，例如 `# 第 1 步：离线用例，不需要真机环境检查` | 需要真机却不对 → **TB 直接失败**（`require_environment` 抛 `RuntimeError` / CLI 退出码非 0；不 skip、不换环境凑合）。日常环境优先，非日常需求写好 TB 后找测试侧准备 |
| 2 | **构建测试环境** | 要读就准备一张**要被读**的图；要写就造出**要被写**的对象，并**还原到未写基线** | 构建失败 = 用例失败（不许吞掉再继续） |
| 3 | **最终检查环境** | 确认对象 / 视图 / 前置状态都就位且干净（数量、命名、参数、锁、打开句柄）。<br>**没有前置可构建的**（例如只算 `1+1` 的 skill TB）：写一行注释跳过即可，例如 `# 第 3 步：无前置对象，跳过构建检查` | 不干净 → 失败并打印现场（`ls` / `read` 摘要） |
| 4 | **执行操作** | 只做被测动作 | 报错按 §4 判归属 |
| 5 | **比对结果并记录（理想 vs 实际）** | **必须**读回 / 查询 / 测量被写对象，把期望值与实测值都写进证据 | 只有 `ok:true` 没有比对 = 不合格，视同未测 |
| 6 | **重复 4、5 到完结** | **跑完不清理现场**（干净由第 2、3 步负责），但要把现场状态记进证据 | — |

**六步只要求按顺序过一遍，不强制每一步都真做**：某一步用不上时，在 TB 里写一行注释说明为什么不需要即可
（离线用例几乎不需要第 1 步的真实环境检查 → 写注释；只算 `1+1` 的 skill TB 不需要第 3 步构建前置环境 → 写注释跳过）。

> **要不要把六步逐条写成 `# §1…` 注释块？可选**：规范只强制"**跳过的步骤**留一行注释"；
> 若你选择逐条自述，请放在注释头之后（不要混进注释头里）。

## 2. 最小判据（判据强度不得低于这个）

| 被测对象 | 最低要求 |
|---|---|
| 原理图写操作 | `schematic.read` 回读实例 / 网络 / pin 列表，逐项比对 |
| 版图写操作 | `layout.read`（形状数 / 层 / 属性）或窗口查询；GDS 另加 `stat` / sha256 |
| symbol 生成 | `symbol.read` 的端口集合 / `pin_order`（"top 实例化成功"只算**间接**证据，必须在证据里标注） |
| Calibre DRC / LVS | `calibre.read_results` 的结论（rulecheck 计数 / `CORRECT|INCORRECT`），不是接口 `ok` |
| Spectre | `spectre.measure` 的数值 + 物理合理性判据 |
| 文件传输 | 目标存在 + sha256 / 内容比对 |
| 句柄 / 锁 / 资源 | 运行前后查询（打开句柄、`*.cdslck`、端口、临时目录）并给差异 |

## 3. 状态还原规则（cellview 是持久对象，不是无状态函数）

| 场景 | 规则 |
|---|---|
| 需要"空起点" | 用 `init_work_dir` 绑定的场景目录 + 专属 lib / cell（名字带 runid），不要在共享库上直接跑 |
| 需要"已有对象"（delete / rename / set 类） | 第 2 步**先造**该对象，第 3 步校验它存在且参数符合预期，第 4 步才改，第 5 步读回确认 |
| 共享库（`/project/libs/*` 等） | **只读**优先；必须写时用专属 cell 名（带 runid），并在证据里登记"我动了哪个对象" |
| 跑完 | 不清理现场（便于复核与复跑定位），但把现场状态写进证据；下一次运行靠第 2、3 步自己还原基线 |

> **不强制连续跑两次**：跑一次即可；但第 2、3 步必须让下一次运行能自己还原基线
> （造对象 / 改属性都基于显式前置，而不是"上次恰好没留下东西"）。

**work root 口径**（产品规则，不许绕开）：`common.paths` 的 work root 是**进程级、一次绑定**的——
入口在启动时绑一次，同路径重复调用幂等，**换路径直接报错**；运行期不换根。

| 场景 | 正确做法 |
|---|---|
| pytest 用例 | 由 `test/conftest.py` 的 session fixture 绑唯一一根；用例**不要**调 `init_work_dir` |
| 用例需要"另一个根" | **起子进程**（子进程自己绑），见 `test/offline/unit/test_workdir_contract.py` |
| 独立脚本 / TB / 探针 | 在 `main()` 里 `init_work_dir(<--work-dir>)` 绑一次（合法） |
| 产物要独占 | 在共享根内给目录 / 文件名加自己的前缀（如 `work_root()/f"tree-{uuid}"`） |

## 4. 结果归属（红 / 绿怎么算）

1. 先写能复现的红灯用例并留证据；修好后**同一用例**转绿，红绿证据成对保留；
2. 只有绿灯没有红灯的"修复"不予采信；
3. 环境问题（靶机离线、端口被占）**不算**被测系统红灯，记为环境缺陷；
4. 结论只有 **PASS / FAIL / PENDING**，没有"基本通过"；不用历史绿灯冒充当前结论。

## 5. 证据（放哪、怎么命名、写什么）

| 类型 | 位置 | 命名 |
|---|---|---|
| 机器可读证据 | `test/artifacts/evidence/<run-id>/` | `<主题>-green.json` / `<主题>-red.json` |
| 日志 | 同上 | `<套件>.log` |
| 可复用环境（work-dir / 注册表 / fake 群） | `test/artifacts/env/<name>/` | `registry.json` 等 |
| 零时产物（可随时删） | `test/artifacts/tmp/` | `.coverage*`、调试 dump |
| 远端工程产物 | `~/project/<user>/tb-out/<run-id>/` | 按产物名 |

一条 TB 的证据里必须能看出：**环境指纹**（宿主 / 用户 / 实例端口 / token 或 work-dir+user / 库 / 工艺 / 解释器）、
**前置现场**（造了什么、还原成什么基线）、**动作清单**、**比对表**（期望 / 实际 / 判定）、**后置现场**
（对象 / 锁 / 句柄 / 端口 / 临时目录状态）、**判据说明**（为什么这算通过）。
`test/artifacts/` 默认 gitignore；要入库的关键证据 `git add -f`，并在提交说明写明它支撑哪条结论。
历史证据只增不改：新一轮用新 `<run-id>`；**不得**把 token / 口令 / 私钥写进证据或报告。

## 6. 文件与路径纪律（尽可能只使用这三处）

**尽可能只使用这三处**（推荐路径就这些；不要为了省事另造第二套路径）：

| 位置 | 放什么 | 怎么取 |
|---|---|---|
| 客户端 work root | 运行时产物、临时文件、日志 | 入口 `init_work_dir()`；用 `work_root()/temp_dir()/log_dir()/artifact_dir()` |
| 远端 role root | 部署产物、远端临时文件 | 注册表 `roles.<role>.root`（默认 `~/.virtuoso-bridge/<user>/`） |
| 个人工程目录 | Cadence 工程产物、导出 | `~/project/<user>/`（证据另可放 `test/artifacts/evidence/<run-id>/`） |

**不要**：共享 `/tmp`（例外：设计内的 `/tmp/virtuoso_bridge_<user>/<client_id>/` 部署目录）、`$HOME` 根下新建任何东西、
字面量 `~` 目录、把绝对路径拍平成 `homeGent.xxx` 这类名字、脚本放 `$HOME` 或桌面、跨用户共享 scratch、
用户名含空格 / `/` / `~`、依赖进程 cwd 落盘、离线级用例在仓库里落文件。

自检（远端）：`find ~ -maxdepth 1 -mmin -60 -printf '%TY-%Tm-%Td %TH:%TM  %p\n' | sort`
—— 60 分钟内 `$HOME` 根应只出现 `project/` 与 `.virtuoso-bridge/`。
系统 / Cadence / X11 自己写的 `~/.Xauthority`、`~/.cdsinit`、`~/.cadence`、`~/CDS.log` 不算违规，但测试不得制造新的同类文件。

## 7. 分层硬规则（离线级额外约束）

- 离线级（`unit` / `integration` / `scenario`）不得在仓库内落文件（含 `test/artifacts/`）；
- `unit/` 不得起服务、不得占固定端口；**密闭本地资源例外**：`127.0.0.1:0` 临时端口短连接、本机解释器子进程、
  `tempfile` 临时目录可用，但必须同时满足：不访问外部网络 / 远端、不 bind 固定端口、用完即释放（`finally` 或 fixture）；
- `integration/` / `scenario/` 用固定端口必须探测占用并在 `finally` 释放；
- 新增 TB 要登记到所在子目录 README 或 `test/shared/runners/README.md`。

## 8. 覆盖度要求（原子级，不只是"包测没测"）

一个包里十几个原子，测过 `place_*` **不代表** delete / rename / set 也被测过。因此：

1. 报告里说"某包已覆盖"时，必须给**原子级**依据；
2. 每个写原子在**半真机或真机**至少有一条符合本页 §1 六步 + §2 强度的用例；
3. 原子清单与缺口用机器核账：`python test/shared/runners/audit_atom_coverage.py`
   （输出 `test/artifacts/evidence/atom-coverage-<date>.json`，含"证据树里有没有被执行过"的第二来源）；
4. 新增 / 修改原子（`src/pyapi/packages/*.py`）后**必须**重跑该核账。

## 9. 提交前逐条打勾

- [ ] 六步齐全；步骤 1 跑过 `env_check.py`（退出码 0）；步骤 2–3 有可复查的"构建 + 还原基线"记录；
- [ ] 文件顶部的 **TB 注释头**齐全（3 栏：作者 / 最后改动到分钟 / 依赖）；
- [ ] 每条断言都有期望 / 实际 / 判定，没有"只判 ok"；间接 / 弱判据已显式标注；
- [ ] 证据含环境指纹与后置现场；
- [ ] 涉及写操作时，报告里给出该操作的原子级覆盖状态（有证据 or 缺口）；
- [ ] 层与目录符合 §7，文件只落 §6 的三处，无仓库内落盘、无残留临时目录。
