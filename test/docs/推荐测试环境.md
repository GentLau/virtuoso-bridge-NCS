### 能力边界（选场景前先看）

- **协议级 fake daemon**（`test/shared/fixtures/fake_daemon_host.py`，S4 用）：只实现 STX/NAK/JSON/日志元数据协议。
  → 能测：并发、预算、准入拒绝、token 隔离；**不能测**：file / command / gui / spectre 的真实语义。
- **fake Virtuoso**（`test/semi/fakevirt/`，S2/S3/S5 用）：CIW 替身 + 真 daemon + 真 middle，支持 18 类 SKILL 操作
  （字面量、四则、`strcat`、`printf`、`fileLength`、`list`、错误结构…）；
  **不支持**多语句/赋值、`printf` 格式指令、符号入参、其它 SKILL 内建（详见 `test/semi/fakevirt/README.md` §3）。
- **真实例**（S1/S2/S3/S5–S10）：五接口全量；S1 额外带工艺库与 Calibre；S10 覆盖 middle+bottom 真链路。

> 真机数量有硬上限：单实例约 1 GB，wsl-gent 共 16 GB → 真机 **≤10–12 个**。
> 需要"20 个真机"必须再加一台装 Cadence 的机器（当前没有）；**规模档请用 S4**（协议级 100 fake）。

## 3. 你会用到的参数

- **客户端**：默认本机 Windows；需要 Linux 客户端时用 `w1`（S6 一致性场景）。
- **启动目录**：见 §1 表；注册表 `registry.json` 就在启动目录里，服务与 TB 都用它。
- **当前已就绪实例**（2026-09-22 21:0x 实测）：

| 实例 | 主机 | 端口 | token | 用途 |
|---|---|---:|---|---|
| vblog | wsl-gent | 65121 | `vb-vblog` | 通用真机（S8/S9 与 S10 引导源） |
| calprobe | wsl-gent | 65122 | `d6af595b342647b58ec63ca6` | 带 tsmcN65 工艺库（S1/S11）；**不要拿它当 S10 引导源** |
| vbs11 | wsl-gent | 65200 | `vb-s11` | S11 工程流专用（按 §0 起，run 目录 + `.cdsinit` 自动 load） |
| vbe2e | wsl-gent | 65130 | `vb-e2e-bootstrap` | S10 专用引导源（每跑完一轮会被重配，见下） |
| vbtest | wsl-gent | 65081 | `vb-vbtest` | fake 实例（仅 skill/日志），不参与 S10 引导 |

- **S10 的 CIW 必须专用**：`test_e2e_live.py` 会在引导源里执行 `RBStop() + load(<新 setup>)`，把该 CIW 的 daemon 换成新用户的。起专用实例：`test/shared/runners/start_real_virtuoso.sh <run-dir> <cds.lib> :99 <既有-virtuoso-pid>`，并在 run 目录放 `.cdsinit`（内容 `load("<setup>/virtuoso_setup.il")`）→ daemon 自动就绪；跑测用 `VB_E2E_BOOTSTRAP_TOKEN/PORT` 指定它。
- TB 命令一律显式带 `--work-dir` 和 `--token`；同一个场景的 TB 用同一个 `--work-dir`。
