# 环境与场景

> **读者**：要真机/半真机跑测、或要挑一个现成场景做验证的开发工程师。
> **读完能做什么**：知道有哪些实例与 token 可直接用、哪个场景适合你的需求、怎么自检、怎么申请非日常环境。
> **不覆盖**：靶机运维（密钥、回滚、故障恢复）、历次环境变更 —— 见
> [`../reports/internal/环境Runbook-内部.md`](../reports/internal/环境Runbook-内部.md)。

## 1. 拓扑（一句话）

客户端（本机 Windows `.venv`，也可在 w1 的 Linux 侧）→ 业务面 `127.0.0.1:8127`（HTTP）→ 注册表里的 role
（GUI/daemon/command/file/spectre）→ 远端实例：**wsl-gent 真 Virtuoso**（含 PDK/Calibre）与 **w1-gent lab fake**。

> **DISPLAY 纪律（2026-09-28 修过一次漂移）**：多用户实例的 X 显示号必须与注册表 `role.gui.display` 一致，
> 否则 `virtuoso.gui.*` 全部报 `no CIW window found`（当时 vbuser1/vbuser2 实际跑在 `:110`/`:103`，
> 注册表却写 `:100`/`:101` —— 已把注册表改到实际值，不要用 `xvfb-run -a` 起实例，它会随机挑显示号）。
> 自检：`virtuoso.gui.list_windows` 能枚举到 CIW；不一致就先把实例按注册表 DISPLAY 重启，再改注册表。

用法：TB 直接 `--work-dir test/artifacts/env/log-vblog --token <上表 token>`（或 `--base http://127.0.0.1:8127`）。

## 3. 能力边界（挑场景前先看）

- **协议级 fake**（`vbtest`、`vb-lab*`、`cloud*`）：只实现 STX/NAK/JSON/日志元数据协议 → 能测并发、预算、
  准入拒绝、token 隔离；**不能测** file/command/gui/spectre 的真实语义。
- **fake Virtuoso**（`test/semi/fakevirt/`）：CIW 替身 + 真 daemon + 真 middle，支持十余类 SKILL 操作 → 能测路由与句柄，
  但没有真实 Cadence 语义。
- **真机**（`vblog`/`vbs11`/`vbuser*`）：真实 CIW / 库 / PDK；`calprobe` 另带 Calibre 与 tsmcN65 工艺库
  → DRC / LVS / 前仿必须用真机实例。

## 6. 跑测前 30 秒自检

1. `resident_env_check.py` → `remote 实例 8/8 通`；
2. `curl http://127.0.0.1:8127/health`（或 `Invoke-RestMethod`）→ `status: ok`；控制面 `GET http://127.0.0.1:8124/api/process/status`（带 admin token）→ `state: ready`；
3. 在目标 CIW 里：`ddGetObj("<你要用的库>")` 返回 `dd:0x…`（否则库没挂上，先别跑）。

## 7. 申请非日常环境（S1 / S4 / S5 / S6 / S11 / S15 等）

**注册专项（按需切换，不占常驻业务面 8127/8131）**

| 需求 | 现成能力 | 入口 |
|---|---|---|

| host-key A/B 轮换端点（必须 22 端口） | `w4-gent`（172.20.170.24:22，用户 dev，脚本已就位） | `ssh w4-gent 'sudo -n /usr/local/sbin/w4_hostkey_cycle.sh status\|use-a\|use-b\|restore'`（每次输出 `SET=` + `FINGERPRINT=`）；测试期间独占 w4，**finally 必须 restore**；w4 空闲会自动停机，跑前 `wsl.exe -d w4-gent -- sleep infinity` 保活 |

| **Linux 客户端真机链路**（客户侧全栈都在 Linux：api_server + middle + 包层） | wsl-gent：仓库副本 `~/project/vblog/tb-sandbox/linux-client/repo`、注册表 `.../env-live`（token `vb-vbuser2`）、业务面 `127.0.0.1:8127`（Linux 侧独立进程，不占 Windows 的 8127）、日志 `.../logs/` | `ssh wsl-gent` → `cd ~/project/vblog/tb-sandbox/linux-client/repo` → `PYTHONPATH=src /usr/bin/python3.9 test/live/packages/infra_e2e_tests.py --transport http --api http://127.0.0.1:8127/api/operation --token vb-vbuser2 --work-dir ~/project/vblog/tb-sandbox/linux-client/env-live --out ~/project/vblog/tb-sandbox/linux-client/evidence/linux-client-infra.json`（**2026-09-28 实测 6/6**） |

py2.7 注册 TB（`registration_py27_tb.py`）的环境已就绪，现成可用。

把这几项发给测试侧即可（不用自己动靶机）：**① 场景编号或"我要测什么"；② 客户端在哪（本机 / w1）；
③ 需要几个真机实例、几个 fake；④ 需要哪些库 / 工艺（PDK、共享库名）；⑤ 期望什么时候用、用多久。**

## 8. 三条硬规则

1. **别自己换靶机或改注册表**：换实例 / 换端口 / 换解释器一律找测试侧（我用独立 work-dir 准备，不动常驻）；
2. **别在仓库或靶机家目录乱落文件**：尽可能只用三处 —— work root、role root、`~/project/<user>/`（详见 [写TB规范.md](写TB规范.md) §6）；
3. **改完注册表要重启业务面**（standalone 只在启动时导入注册表），否则会误判成"实例挂了"。
