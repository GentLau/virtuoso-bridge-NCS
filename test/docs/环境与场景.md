## 3. 能力边界（挑场景前先看）

- **协议级 fake**（`vbtest`、`vb-lab*`、`cloud*`）：只实现 STX/NAK/JSON/日志元数据协议 → 能测并发、预算、
  准入拒绝、token 隔离；**不能测** file/command/gui/spectre 的真实语义。
- **fake Virtuoso**（`test/semi/fakevirt/`）：CIW 替身 + 真 daemon + 真 middle，支持十余类 SKILL 操作 → 能测路由与句柄，
  但没有真实 Cadence 语义。
- **真机**（`vblog`/`vbs11`/`vbuser*`）：真实 CIW / 库 / PDK；`calprobe` 另带 Calibre 与 tsmcN65 工艺库
  → DRC / LVS / 前仿必须用真机实例。

## 8. 三条硬规则

1. **别自己换靶机或改注册表**：换实例 / 换端口 / 换解释器一律找测试侧（我用独立 work-dir 准备，不动常驻）；
2. **别在仓库或靶机家目录乱落文件**：尽可能只用三处 —— work root、role root、`~/project/<user>/`（详见 [写TB规范.md](写TB规范.md) §6）；
3. **改完注册表要重启业务面**（standalone 只在启动时导入注册表），否则会误判成"实例挂了"。

## 9. 可丢弃 CIW（disposable，P-086 / C06 专项）—— 现已常备，可直接独占使用

**不碰常驻 vblog / 8127**；谁用谁独占（同一个 name 同时只允许一个使用者）。

### 9.2 起停与自检（都在 wsl-gent 上跑）

```bash
# 起（name 自己取；port 从 64600–64699 里挑；重复跑会先停掉同名实例）
VB_RESOURCES=$HOME/.virtuoso-bridge/disposable/ramic \
  bash ~/.virtuoso-bridge/disposable/bin/start_disposable_ciw.sh <name> <port>
#   → NAME=.. TOKEN=vb-<name> PORT=.. ROOT=.. RUN=..

# 探活（不依赖 Windows 隧道）
python3 ~/.virtuoso-bridge/disposable/bin/daemon_ping.py <port> vb-<name> "1+1"
#   → OK '2'

# 停
bash ~/.virtuoso-bridge/disposable/bin/stop_disposable_ciw.sh <name> <port> vb-<name>
#   → STOPPED name=.. port=..
```

**自重启已验证**：`stop → start → ping` 一轮后 `3*4` 返回 `12`（2026-09-30 实测）。
TB 里可以随便多次 `stop/start`，不需要测试侧人工介入。

### 9.4 需要新实例/新端口时

自己 `start_disposable_ciw.sh <你的name> <64600–64699 里的空闲端口>` 即可；
**用之前先确认端口空闲**：`ssh wsl-gent 'ss -ltn | grep :<port> || echo FREE'`。
测试侧不锁定具体 name/port，只保证：资源是新版、段内端口可用、每台互不干扰。

## 10. 多账号隔离与分配（2026-10-08 生效）

**分配**：Gent = 测试侧；vbuser1 = 上层开发；vbuser2 = 其他开发（中+底层，同一人）；
vbuser3 / vbuser4 = 测试侧跨用户场景（S13/S14）。每个账号 **≥2 个万能实例**：
主实例 `6540N` + 副实例 `6541N`（N=1..4），Xvfb 固定 `:110/:112`、`:103/:113`、`:114/:115`、`:116/:117`。

**规则**

1. **一人一实例**：一个 CIW/daemon 同一时间只服务一个使用者；多人共用一个 token/CIW 不算隔离
   （请求交错、模态框互卡、CDS.log 互相污染、重启互相打断）。能力去中心化（人人有万能实例）+
   入口去中心化（按账号拆日常环境）必须同时做，否则大家还是会挤向 vblog。
2. **只动自己的**：只能重启自己账号/自己 name 的实例；禁止 `pkill virtuoso` 通杀、禁止动别人的端口/root/token。
3. **停实例：两条路 + 两个坑**。`RBStop()` 是正路（只停 daemon、放端口，CIW 留着）；直接杀 CIW
   也会连带清理 IPC 子进程树（实测 SIGTERM ~1.2s、SIGKILL ~0.2s，wrapper ≤5s，端口随之释放）。
   两个坑：① kill/停实例必须**用目标账号身份**执行（跨账号 kill 被 EPERM 拒绝且会静默失败）；
   ② kill 后要**轮询等端口真正释放**再继续（毫秒级就查会撞 teardown 窗口，误判成"daemon 还在占端口"）。
   实测与依据：[CIW-daemon 停止语义调查](../reports/internal/CIW-daemon停止语义-调查-2026-10-08.md)。
4. **一个实例一个文件夹**：独立 root + 独立 `run/cds.lib` 拷贝 + 独立 `CDS.log`；多个 Virtuoso
   绝不共用同一 cds.lib/run 目录（cds.lib 允许复制，不允许共享同一份）。
5. **新实例标准流程**：`bringup_instance.sh <name> <port> <display>`（准备 root/cds.lib/初始 daemon）
   → `register_instance.py`（标准六步：apply → validate → probe → deploy → 写 `run/.cdsinit` 自动 load
   → verify → commit）→ `env_check` + 五接口冒烟。2026-10-08 六个新实例（vbuser1b / vbuser2b /
   vbuser3 / vbuser3b / vbuser4 / vbuser4b）全部按此流程注册通过。
6. **端口段**：`64600–64699` 可丢弃 CIW；`65081` fake；`65121/65122/65200` 常驻测试侧；
   `65401–65409` 主实例；`65411–65419` 副实例；`644xx` 客户端隧道口（注册表 `local_port`，按实例一一对应）；
   `65500+` 保留给 local 模式 TB。
7. **资源**：真实例并发 ≤10–12（15 GiB RAM / 20 核）；Calibre/Spectre 大任务错峰。
8. **验收证据**：`test/artifacts/evidence/env-2026-10-08/`（六步注册证据 ×6 + env_check ×6 + 五接口冒烟 ×4 + 跨用户 TB 17/17）。
