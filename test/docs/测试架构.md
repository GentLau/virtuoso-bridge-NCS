# 测试架构（`test/`）

> 维护者：测试工程师 ｜ 版本：v1.0 ｜ 2026-09-22
> 本文定义**测试怎么组织**（分层、职责、覆盖模型、门禁、证据链），不写具体用例。
> 具体规则见 [文件使用规范.md](文件使用规范.md)、[用例分层与归口.md](用例分层与归口.md)、[证据与报告.md](证据与报告.md)。

## 1. 被测对象与边界

四层实现：`bridge`（底层 IL/SKILL daemon）→ `transport`（中层运行时，五接口）→ `server`（顶层 HTTP）/`register`（独立注册）→ `pyapi`（上层业务包）。

测试只回答**行为契约**：接口形状、错误语义、并发与预算、日志返回、资源回收、真机一致性。

| 在范围内 | 不在范围内（spec 豁免） |
|---|---|
| 五接口与其失败分支、注册六步、CDS.log 增量、容量拒绝、token 隔离、崩溃安全 | split-host CDS.log、跨机启动 daemon、X11 显示链路、文件系统沙箱 |
| 上层业务包**对五接口的消费路径**与其**纯逻辑工具**（解析/改写/文本处理） | 上层业务的内部实现深度（不重复设计工程师的单测目标） |
| 路径与文件纪律（写哪、不写哪） | 系统/Cadence/X11 自身写出的文件 |

## 2. 三级测试架构（唯一分类口径）

**判据只有一个问题：这条用例需不需要真实环境？**

| 级别 | 定义 | 需要什么环境 | 目的 | 进默认 CI |
|---|---|---|---|---|
| **离线测试** | 不需要真实环境，纯 Python；允许 mock/stub/fake 夹具 | 无 | 契约、协议、语义、回归；每次提交都跑 | ✅ |
| **半真机测试** | **需要真机环境，但不一定完整运行**：单阶段/局部链路/探针，通常用于过程调试与确认 | 真实 daemon/靶机（可只用其中一环） | 定位问题、确认环境、验证单点行为 | ❌ 显式 |
| **真机测试** | **全真环境**：所有操作严格按用户实际能产生的操作 | 完整真实环境 | 验收——能不能真的干活 | ❌ 显式 |

判定细则（先看能不能离线判定，再看完整度）：

1. **不接真机也能判定 → 一律算离线**，哪怕它住在 `test/` 下（如 `test/offline/core/`）；
2. 接了真机但只跑**局部/单阶段**（探针、注册 1–4 步、单段日志矩阵、专项 LVS）→ **半真机**；
3. 接了真机且对应**用户的完整动作序列**（六步注册、五接口全量、包 E2E、工程链、并发压力）→ **真机**。

## 3. 覆盖度模型（能力域 × 层）

判定"测够了"不靠行覆盖率，而靠**同一能力域在离线级与（半）真机级都有对应证据**：

| 能力域 | 离线级应有 | 半真机 / 真机级应有 | 现状 |
|---|---|---|---|
| 五接口（skill/command/file/gui/spectre） | `unit` 契约 + `integration` 协议 | `test/live/transport/cov_remote_real.py` | 齐 |
| 日志返回（off/分级/增量/轮转/降级） | `test/offline/core/daemon_log_protocol_tb.py` | `test/semi/transport/log_matrix_real_tb.py` | 齐 |
| 注册六步 | `unit`/`scenario` + `test/semi/registration/cov_registration_real.py`（1–4 步） | `test/live/registration/registration_http_six_step_tb.py`（完整六步） | 齐 |
| 并发与预算（capacity/deadline/拒绝） | `unit` + `test/offline/core/semantics_tb.py` | `test/live/stress/*` | 齐 |
| 资源回收（隧道/端口/临时目录/进程） | `unit` | 压测前后盘点 | 齐 |
| 上层业务包（cellview/schematic/symbol/layout/verilog/veriloga/maestro/spectre/skillref） | — | `test/live/packages/*`（HTTP E2E） | **缺口**：纯逻辑工具缺离线契约 |
| 上层业务包 calibre | `test/offline/unit/test_calibre_package.py`、`test_calibre_argv_contracts.py` | `test/semi/probes/calibre_env_probe.py`、`test/live/flows/lvs_from_schematic_tb.py`（无包级 HTTP E2E） | 半真机级为主 |
| 底层 daemon（py3/py2.7 parity） | `unit` + `test/offline/core` 双跑 | 真机 daemon | 齐（py2.7 真解释器 PENDING） |
| 路径与文件纪律 | 本目录规范 | 路径专项审计 | 见 [../reports/问题登记.md](../reports/问题登记.md) |

> 能力域表的**模块级下钻**（哪些 `src/` 模块在离线层零引用、按什么层归口）见 [../reports/覆盖度缺口.md](../reports/覆盖度缺口.md)。

## 4. 一条结论的证据链

```text
红灯用例（可复现失败） → 修复 → 同一用例转绿 → artifact 落盘 → 报告引用 → 覆盖率复算
```

任一环缺失，该结论在审核中视为**未完成**。缺环境（靶机离线、端口被占）先记为环境缺陷，不计被测系统失败。

## 5. 运行入口与门禁

| 级别 | 怎么跑（由测试工程师执行；不设一键脚本） |
|---|---|
| **离线** | `python -m pytest test/offline/unit test/offline/integration test/offline/scenario`（CI 同口径）+ `test/offline/core/{api_server,semantics,fault_injection,daemon_log_protocol}_tb.py` |
| **半真机** | 需真机、单点确认：`test/semi/probes/*`（如 `calibre_env_probe.py --facts`）、`test/semi/registration/cov_registration_real.py`（1–4 步）、`test/semi/transport/log_matrix_real_tb.py`、`test/semi/transport/one_shot_burst_tb.py` |
| **真机** | 全真验收：`test/live/registration/registration_http_six_step_tb.py`、`test/live/transport/cov_remote_real.py`、`test/live/packages/*`（经 `test/shared/runners/run_all_http.py`）、`test/live/e2e/`（pytest）、`test/live/stress/*`、`test/live/flows/*` |
| （兼容）准出全量 | `powershell -File test/shared/runners/run_coverage.ps1 -IncludeExtended`：原 fail-fast 门禁（离线 + 半真机 + 真机合并集合与覆盖率） |

> 三个级别是**分类口径**，不是"哪个更高级"：离线级负责每次提交都跑，半真机级负责定位与确认，
> 真机级负责验收。级别之间允许重叠（同一能力域可以三级都有用例），但结论只认对应级别。

> 当前口径（2026-09-22 17:52 实测 `--collect-only`）：默认三层 **765**（unit 720 / integration 29 / scenario 16），
> `test/live/e2e` 另 10 个（显式 opt-in）。数字随用例增删变化，报告引用时以当轮实测为准。

## 6. 责任与变更

- **设计工程师**：改实现、跑自测、提供可复现的红灯路径；提交前保证三层绿。
- **测试工程师（本目录主人）**：分层归口、补齐缺失层、审覆盖度、维护规范与问题登记、把关证据链。
- **规范变更**：只改 `test/docs/`；口径变化时，旧证据必须标注"按旧规范采集"，不得混用。
- **新增/调整目录**：同时更新本文 §2、[test/README.md](../README.md) 与三级 README
  （[offline](../offline/README.md) / [semi](../semi/README.md) / [live](../live/README.md)）。
