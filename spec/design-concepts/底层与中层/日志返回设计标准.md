# 日志返回设计标准

> 版本：Draft v3
> 日期：2026-09-10
> 状态：已冻结（log 返回唯一口径）
> 关联：[核心修改设计](../总览/核心修改.md)、[改动报告](../总览/改动报告.md)、[三层整体架构设计](../总览/三层整体架构设计.md) 第 4 节

## 1. 目标

每次 `execute_skill()` 的返回值上多一个 **`log` 字段**，内容是本次指令产生的 `CDS.log` 增量。

- 增量返回：只取本次指令这一段，不下载整个 `CDS.log`；
- 分级：能按级别过滤（off / all / warn / error）；
- 限长：超长时自动降级，只回关键级别（如 error）；
- 不引入复杂事件流、artifact、多级 cursor 等体系。

## 2. 实现点：放 daemon.py（评估结论）

**不在中层裁剪**：如果底层把完整原始增量传到中层再裁剪，等于把大日志走一遍 TCP，浪费带宽，中层还得管 cursor。

**放在 daemon.py 最合适**：

1. daemon 由 `ipcBeginProcess` 在 Virtuoso/CIW 旁边拉起，与 `CDS.log` 同主机，读文件是本地操作；
2. 级别过滤和限长在 daemon 完成，**只有裁好的 `log` 文本发回中层**；
3. cursor 常驻 daemon 内存，中层无状态；
4. 中层只需要把 `log` 挂到返回值上，代码最少。

分工：

| 职责 | 实现位置 |
|---|---|
| BEGIN/END marker、`hiFlushLogFile()`、返回 `path + end_offset` | 底层 `ramic_bridge.il`（只有 CIW 能调这些 API） |
| 读 `[cursor, end_offset)`、级别过滤、限长降级、推进 cursor、组装回包 | **`ramic_bridge_daemon_*.py`** |
| 解析回包，把 `log` 挂到 `VirtuosoResult` | 中层 `bridge.py` + `models.py` |

本版假设 `CDS.log` 与 daemon 同主机，不考虑 split-host 场景。

## 3. 增量机制（最小）

daemon 内存只保存两个数：`log_path`、`cursor`。

```text
每次请求：
  1. start = cursor
  2. il 执行用户 SKILL，回传 end_offset
  3. daemon 读文件 [start, end_offset)
  4. cursor = end_offset
```

`ramic_bridge.il` 侧：

```text
1. hiGetLogFileName()
2. hiFlushLogFile()
3. hiPrintToLogFile("VB-BEGIN")
4. 执行用户 SKILL
5. hiPrintToLogFile("VB-END")
6. hiFlushLogFile()
7. fileLength(path) → end_offset
```

- 不需要 `request_id`：本次增量范围由 daemon 的 `[cursor, end_offset)` 决定，marker 只作人读边界；daemon 同一时刻只有一个 in-flight 请求。
- `hiFlush()` ≠ `hiFlushLogFile()`；
- 文件比 cursor 短（轮转/被清空）→ `cursor = 0`，本次从 0 重读。

## 4. 分级

`CDS.log` 行前缀做简单 `startswith` 解析：

| 前缀 | 级别 |
|---|---|
| `\e` | `error` |
| `\w` | `warning` |
| 其他（`\o`/`\i`/`\p`/无前缀） | `info` |

- 解析不了的行归 `info`，不丢行；
- `VB-BEGIN/END` marker 行永远保留；
- 配置 `log_level`：`off`（不返回）、`all`（全回）、`warn`（warning+error）、`error`（只 error）。

## 5. 限长与自动降级

配置 `log_max_bytes`（默认 64 KB）。顺序：

```text
先按 log_level 过滤
  → 总字节 ≤ max：全部返回
  → 总字节 > max：降级只保留 error 行
      → 仍超限：只留 error 行的头尾各 100 行，并按 `log_max_bytes` 做字节级最终裁剪（含截断提示）
```

即使配置了 `all`，增量太大也只回 error，`log` 末尾追加一行说明：

```text
... [log truncated: error-only, 5123 bytes dropped]
```

原始全文不通过返回值传递；需要时用现有文件接口去读 `CDS.log`。

## 6. 协议与数据结构

### 6.1 请求（中层 → daemon）

在现有 `{"skill", "timeout", "token"}` 上增加两个可选字段：

```json
{
  "skill": "getVersion()",
  "timeout": 30.0,
  "token": "a3f9c2…",
  "log_level": "all",
  "log_max_bytes": 65536
}
```

两个字段由中层从会话配置填充，**上层接口不新增参数**。

### 6.2 回包（daemon → 中层）

保持 `STX/NAK + payload + RS` 帧，payload 从单值改为 JSON：

```json
{"value": "3", "log": "\\e ...本次错误行...\\n"}
```

- 成功：`02 + {"value": ..., "log": ...} + 1e`
- 失败：`15 + {"error": ..., "log": ...} + 1e`
- 旧格式单值 payload：中层按旧路径解析，`log=""`。

### 6.3 返回值

`VirtuosoResult` 只加一个字段：

```python
class VirtuosoResult(BaseModel):
    ...
    log: str = ""      # 本次 CDS.log 增量（已过滤、限长）
```

## 7. 验收标准

1. `execute_skill()` 返回的 `result.log` 只包含本次指令增量；
2. `log_level=error` 只回 error，`warn` 回 warning+error；
3. 配置 `all` 且超长 → 自动只剩 error，末尾有截断说明；
4. 文件轮转/清空 → cursor 重置，不报错；
5. 旧 daemon / 旧 payload 仍可解析，`log=""`。

## 8. 最小实现顺序

```text
1. il：写 marker、hiFlushLogFile、回传 path + end_offset
2. daemon：读文件、过滤、限长、cursor、组装 JSON payload
3. bridge.py / models.py：解析 JSON payload，VirtuosoResult 加 log 字段
4. 请求增加 log_level / log_max_bytes，接会话配置
```
