# 日志返回设计标准

> 版本：Draft v14
> 日期：2026-09-14
> 状态：已冻结（CDS.log 返回唯一口径）
> Supersedes：Draft v13（log 参数支持业务接口显式覆盖注册表默认）

## 1. 目标与硬性边界

每次 `execute_skill()` 的返回值多一个 `log` 字段，内容是本次指令产生的 `CDS.log` 增量：

- 增量返回：只取本次指令这一段，不下载整个 `CDS.log`；
- 分级：按级别过滤（off / all / warn / error）；
- 限长：超长自动降级只回关键级别；
- **不向 CDS.log 注入任何输出**：不得因为“要返回日志”就往 CDS.log 写 BEGIN/END marker 或其他行——日志返回只读文件，不改文件；
- **`off` 是“根本不获取日志”**，不是“获取了但不输出”：`off` 时 IL 不做 flush/fileLength、daemon 不读文件、不回第二帧，执行路径与旧版无日志代码等价。

## 2. 实现点：daemon.py + IL 分工

| 职责 | 实现位置 |
|---|---|
| 执行用户 SKILL；当 log 开启时，请求前后各一次 `hiFlushLogFile()`+`fileLength()`，回传 `path + start_offset + end_offset` | 底层 `ramic_bridge.il` |
| 读 `[start,end)`、级别过滤、限长降级、组装 JSON 回包；`off` 时完全不读 | `ramic_bridge_daemon_*.py` |
| 解析回包，把 `log` 挂到 `VirtuosoResult` | 中层 `SkillClient` / models |

本版**不保证** split-host（`CDS.log` 与 daemon 同机是常态假设）：daemon 能读到 IL 回传的 `path`，就按普通路径读 `[start,end)`；读不到 → `log=""` + 固定 warning（见 §7）。**后续方向（本版不做）**：契约仍由 IL 给出 `path + [start,end)`；若 daemon 跨机，读取锚定 CIW 主机并在文件所在端过滤/限长。

## 3. 增量机制（offset 定界，无 marker、无 cursor）

不需要 `request_id`，也不需要 daemon 常驻 cursor：**每次请求 IL 直接回传 `[start,end)`**。

```text
log 开启（all/warn/error）时：
  1. il: hiFlushLogFile()                       ← 只 flush 已缓冲内容，不写新行
  2. il: start = fileLength(log_path)
  3. il: 执行用户 SKILL
  4. il: hiFlushLogFile()
  5. il: end = fileLength(log_path)
  6. il: 第二帧返回 log_path + start + end
  7. daemon: 读文件字节区间 [start, end)
  8. daemon: 过滤 + 限长 → 组装 {"value"/"error", "log"}

log=off 时：
  1. il: 直接执行用户 SKILL（不 flush、不 fileLength、不第二帧）
  2. daemon: 不读文件
  3. 回包 log=""
```

- `hiFlush()` ≠ `hiFlushLogFile()`；使用后者。
- 文件轮转/清空导致 `size < start` 或 `end < start` → `start = 0`，本次读 `[0, end)`（可读多少算多少，不报错）。
- `[start,end)` 之外的并发输出不属于本次增量；等待请求留在中层投递前队列，daemon 同一时刻只接收/执行一个由闸门放行的 Skill 请求。

## 4. 分级

`CDS.log` 行前缀做 `startswith` 解析；`\e` / `\w` 表示**两个 ASCII 字符**（反斜杠 + `e`/`w`），不是控制转义：

| 前缀 | 级别 |
|---|---|
| `\e` | error |
| `\w` | warning |
| 其他（`\o`/`\i`/`\p`/无前缀） | info |

- 解析不了的行归 info，不丢行；
- `off`：不获取（见 §3），`log=""`；
- `all`：全回；`warn`：warning+error；`error`：只 error。

## 5. 限长与自动降级

`log_max_bytes`（默认 64KB）：

```text
先按 log_level 过滤
  → 总字节 ≤ max：全部返回
  → 总字节 > max：降级只保留 error 行，并在末尾附加一行“已自动降级”说明
      → error 仍超限：返回本次 error 增量靠前的 max 字节，并在末尾附加一行“未完整返回”说明
```

- 两行说明均**不受 `log_max_bytes` 限制**，语义分别是：
  - 降级说明：`[log auto-degraded: error-only due to log_max_bytes]`；
  - 未完整返回说明：`[log truncated: increment not fully returned due to log_max_bytes]`；
- 最后一步按**字节截断、只取靠前部分**：例如上限 100 字节、本次增量起于 offset 10、error 增量到 200，则返回 10–110，之后内容本次不补发；
- 字节截断允许落在多字节 UTF-8 字符中间；若截断后尾部是半个多字节字符，则丢弃该半个字符——最终内容始终是合法 UTF-8，不输出半个字符，也不做替换字符；
- 本次日志区间照常推进（下次请求从新的 `[start,end)` 继续），不会重复返回已被丢弃的旧内容；
- 原始全文不通过返回值传递；需要时用文件接口读 `CDS.log`。

## 6. 协议

### 6.1 请求（中层 → daemon）

在 `{"skill","timeout","token"}` 上增加两个**非必填**字段：

```json
{"skill": "getVersion()", "timeout": 30.0, "token": "a3f9c2…", "log_level": "all", "log_max_bytes": 65536}
```

取值优先级（逐字段）：**上层显式参数 > 该用户注册表 `cdslog.*` > 协议缺省**。示例：注册表 `error/1024`，调用显式 `log_level=warning`、未显式 `log_max_bytes` → 发往 daemon 为 `warning/1024`。上层接口签名见[四层整体架构与接口 §4.1](../总览/1-四层整体架构与接口.md)；请求不携带 `log_level` 且注册表无值时按 `off` 处理（防御性回退），`log_max_bytes` 仅在非 `off` 时生效。

### 6.2 回包（daemon → 中层，唯一当前格式）

保持 `STX/NAK + JSON payload + RS`：

```json
{"value": "3", "log": "\\e ...本次错误行...\\n"}
```

- 成功：`02 + {"value":…, "log":…} + 1e`
- 失败：`15 + {"error":…, "log":…} + 1e`
- **本版只解析 JSON payload**；旧 daemon（无 token）不在支持范围，收到非法帧按协议错误处理。

### 6.3 内部 metadata frame（IL → daemon，冻结）

第二帧字节格式固定为：

```text
STX + path(UTF-8，不回显引号) + US(0x1f) + start(十进制 ASCII) + US + end(十进制 ASCII) + RS
```

- `path` 不包含 `US` 字符，无需转义；
- `start/end` 是字节偏移、十进制整数；
- 帧顺序固定：第一帧 `value/error`，第二帧 `meta`；两帧必须由 IL 合并为**一次 `ipcWriteProcess`** 写入，避免重排；
- `log=off` 不产生第二帧；
- `log_max_bytes` 只约束**原始日志字节**；降级/截断说明追加在该限额之外，作为说明文本，不是日志内容。
- 两帧与 Skill 执行共享同一请求 deadline（请求字段 `timeout`）；`log` 开启时若 deadline 内未读齐第二帧，**Skill 第一帧结果优先返回**：`log=""`，`warnings` 追加固定文本 `CDS.log unavailable: <reason>`，不 NAK、不判 Skill 失败。

## 7. 边界与错误语义

- `log_level=off`：IL 不 flush/不 fileLength/不第二帧，daemon 不读文件，`log=""`——**最源头掐断**。
- `CDS.log` 不存在/不可读/路径变化且读取失败，或第二帧缺失/超时：**本次 log=""，Skill 结果照常返回**，`VirtuosoResult.warnings` 追加固定文本 `CDS.log unavailable: <reason>`（`<reason>` 仅作诊断，不回退为请求失败）；`log_level=off` 刻意不产生第二帧，**不追加该 warning**。
- 无 token / token 不匹配：NAK `invalid token`，log=""，SKILL 零接触。
- `log_max_bytes`/`log_level` 非法值：NAK `invalid log_level` / `invalid log_max_bytes`，不夹紧、不静默降级。

## 8. 验收标准

1. `log=off` 请求在 IL 侧**没有任何 flush/fileLength/文件读**，与无日志旧代码等价（可用 IL 静态断言 + 真机行为验证）；
2. CDS.log 中**不出现任何 VB-BEGIN/VB-END 或桥注入行**；
3. `result.log` 只含本次 `[start,end)` 增量；
4. `all` 超长 → 自动只剩 error，并附“已自动降级”说明；error 仍超长 → 只回本次增量靠前字节，并附“未完整返回”说明，两行说明不受 `log_max_bytes` 限制；区间照常推进；`warn`/`error` 过滤正确；
5. 文件轮转/清空 → start 归零，不报错；
6. `off` 时回包 `log=""`。
7. 非法 `log_level`/`log_max_bytes` 直接拒绝报错；`CDS.log` 不可读时 `log=""` 且 `warnings` 含固定文本 `CDS.log unavailable: <reason>`；截断后尾部不输出半个 UTF-8 字符。

## 9. 最小实现顺序

1. IL：log 开启时两处 flush + 两处 fileLength，第二帧回传 `path + start + end`；off 时零附加操作；
2. daemon ×2：按 `log_level` 决定是否等待第二帧；读 `[start,end)`；过滤/限长；off 直接 `log=""`；
3. 中层 SkillClient 不变（回包仍是单 JSON 帧）；
4. 请求字段接注册表 `cdslog.*` 配置。
