## 1. 总述

本次重构只做五项核心修改：

| # | 修改 | 现状 | 目标 |
|---|---|---|---|
| 1 | 并行机制 | `run_command` 全部串行（persistent shell） | 新增 `parallel` 参数：`False` 串行，`True` 独立 channel 并行 |
| 2 | token 机制 | 无 token，靠 `daemon_guard` 事后查证 | 每次调用传 token；中层路由；daemon 校验，不匹配时 SKILL 零接触 |
| 3 | 注册流程 | `profile` = `VB_*_<profile>` 环境变量 + 每 profile 一份 `state.json` | 本地 `registry.json` 注册表，注册→部署→load→连接 |
| 4 | 脱离环境变量 | 远端靠 `setShellEnvVar` 注入 `RB_*`、靠远端 shell source cshrc | 远端尽量不用环境变量：配置写成 il 常量 / daemon 参数，把对远端机器的影响降到最小 |
| 5 | CDSlog 增量返回 | 每次调用只返回 SKILL 结果，日志靠人工 tail/下载 | 每次 `execute_skill` 自动返回本次指令对应的 `CDS.log` 增量（marker 定界 + byte cursor） |

五项修改共同服务一个目标：**多用户、可并行、配置可控、上层只面对一个逻辑业务服务器。**

## 2. 并行机制

接口签名以[三层整体架构设计 §4](三层整体架构设计.md)为唯一基线，本文件不再重复；`run_command` 相对旧接口新增的是**可选参数 `parallel=False`**。

| 参数值 | 行为 | 顺序保证 |
|---|---|---|
| `parallel=False`（默认） | 该 token 的 persistent shell 串行执行 | 保证先后顺序，命令依赖安全 |
| `parallel=True` | 中层开独立 exec channel 并行执行 | 不保证完成顺序，仅用于互相独立的命令 |

并发模型：

- 每 token 独立线程池（默认 32）：一次未完成的调用占用一个线程，结果返回后线程回池；超限直接返回错误，不排队等线程。
- 线程等待期间被内核挂起（`recv()` / `waitpid()`），占线程名额但不占 CPU。
- 每 token 独立 SSH 连接和 channel 预算（默认 `MaxSessions=10`），超限拒绝。
- Skill 通道串行（Virtuoso CIW 单线程语义，不可改变）；File 通道天然并行（每路独立 SCP/SFTP 进程）。

`parallel` 只是 `run_command` 的参数，**不是第四个接口**。

## 3. token 机制

- `token` 是每次调用**必填**的普通关键字参数（不是 `bind()` 绑定对象），缺失直接报错。
- 中层按 token 查注册表得到 route，再把 token 原样放入 daemon 请求（请求/回包格式见[三层整体架构设计 §4.2](三层整体架构设计.md)，本文件不重复）。

- daemon 校验 token：
  - 匹配 → 投送 Skill；
  - 不匹配 → 回 `0x15 + "invalid token"`，**不写 Virtuoso stdin（SKILL 零接触）**。
- token 不进入 daemon ↔ Virtuoso 这一层，也不回显到 response。
- token 不用于 SSH 认证；命令和文件只按 token 对应的 route 寻址，SSH 侧仍走 host key + 账号权限。
- 生命周期：**生成 ≠ 授权**。生成 → 部署时注入 il → 用户 load 时目视确认（授权）→ 尝试连接校验。
- 一次生成终生有效、不轮换、不过期；删除用户并重新注册时才更换。

## 4. 注册流程改造：profile → 注册表

### 4.1 现状问题

| 现状机制 | 问题 |
|---|---|
| `profile`（`VB_*_<profile>`） | 配置散在环境变量，路由靠全局状态，上层按 profile 分支即违反分层 |
| `state.json`（每 profile 一份） | 事实上的注册表雏形，但没有 token 键和统一查询入口 |
| 端口分配（用户名哈希） | 哈希碰撞靠人工改 `VB_REMOTE_PORT`，多用户不可扩展 |
| `daemon_guard` | 事后查证“连没连错”，拦截点太晚 |

### 4.2 目标：registry.json

- 本地一份 `registry.json`，`user` 为键，冷启动只读。
- 每个条目保存 token、route、expected；部署路径由固定目录结构派生，不落注册表：

```json
{
  "users": {
    "alice": {
      "token": "a3f9c2…",
      "mode": "remote",
      "route": {
        "skill":   {"local_port": 65082, "daemon_host": "compute-host-b", "daemon_port": 65081},
        "command": {"host": "server-a", "user": "jtliu"},
        "file":    {"host": "server-a", "root": "/home/jtliu/.virtuoso-bridge/alice"}
      },
      "expected": {
        "ssh_host_key_fingerprint": "SHA256:7aX…",
        "daemon_endpoint_hostname": "compute-host-b",
        "daemon_user": "jtliu",
        "remote_python": "python3"
      },
                }
  }
}
```

- 连接建立时只读一次，之后用内存中的 `token → 端口/SSH` 映射路由；注册表不写运行态字段（`status`/`authorized` 不落盘）。

### 4.3 使用流程（索引，不重复定义）

正式流程以 [多用户设计 §3.2 六步注册](../底层与中层/多用户设计.md) 为准：**①申请 → ②本地校验 → ③探测 → ④部署 → ⑤连通性测试 → ⑥写入注册表**；所谓“注册/部署/load/连接”四阶段只是这六步的**分组描述**，不是另一套正式口径。

### 4.4 关键口径

- 端口分配从“用户名哈希”升级为**注册表分配**：注册时探测远端端口空闲，冲突显式报错。
- `user register` 注册即探测；`user remove` 才销毁 token；`stop` 不改变注册表。
- `profile` **彻底删除，不保留任何兼容入口**；新代码一律用 `token`（`user` 仅作人类可读索引与路径名）。

## 5. 脱离环境变量依赖（重点是远端）

现代码的远端有两处环境变量依赖：

1. 生成 `virtuoso_setup.il` 时用 `setShellEnvVar("RB_DAEMON_PATH"/"RB_PYTHON_PATH"/"RB_PORT"/"RB_IDENTITY_PATH")` 写入 Virtuoso 进程环境，`ramic_bridge.il` 再用 `getShellEnvVar` 读取；
2. Spectre 等命令行工具依赖远端 shell 预先 source `VB_CADENCE_CSHRC` 设置 PATH / license 等环境。

目标是把**远端机器的影响降到最小**，远端尽量不用环境变量：

- 配置直接写进生成的 il 常量，或作为 daemon 启动参数，**不再调用 `setShellEnvVar` / `getShellEnvVar`**；
- token 也作为 il 常量（或 daemon 参数）注入，daemon 直接持有，**不依赖 Virtuoso 进程环境继承**；
- 命令执行不要求远端登录 shell 预先 source cshrc 或设置 PATH，必要路径由中层显式传入；
- 远端只留下部署文件（daemon、il、setup、identity），不修改 shell 配置，不污染 Virtuoso 进程环境，卸载/切换只删文件。

本地侧同样摆脱环境变量：上层不读 `VB_*`、`.env`、`state.json`；不提供旧 `.env` 迁移适配器，新用户只按新注册流程创建条目。

## 6. CDSlog 增量返回机制

目标：每次 `execute_skill()` 返回值多一个 **`log` 字段**，内容是本次指令产生的 `CDS.log` 增量（已按级别过滤、限长）。

- 实现点在 **daemon.py**：与 `CDS.log` 同主机，本地读 `[cursor, end_offset)`，过滤和限长都在 daemon 完成，只把裁好的 `log` 发回中层，避免大日志走 TCP；
- 底层 `ramic_bridge.il` 只写 `VB-BEGIN/END` marker、`hiFlushLogFile()`、回传 `path + end_offset`；
- 中层把 `log` 挂到 `VirtuosoResult.log`，不引入 cursor / 事件 / artifact 体系；
- 分级：`\e`→error、`\w`→warning、其他→info；配置 `log_level=off|all|warn|error`；
- 限长：`log_max_bytes`（默认 64KB），超限自动降级 error。

协议细节和验收见 [日志返回设计标准](../底层与中层/日志返回设计标准.md)。

## 7. 与现有代码对照

| 项目 | 现代码 | v1 |
|---|---|---|
| 命令并发 | 单一 persistent shell 全串行 | `parallel=False` 串行 / `True` 独立 channel 并行 |
| 用户身份 | 无 token，事后 `daemon_guard` 查证 | 每次调用带 token，daemon 前置校验 |
| 路由来源 | `.env` 环境变量 + `state.json` | `registry.json` 注册表，token 寻址 |
| 上层依赖 | 读 `VB_*`、判 local/SSH | 只依赖三接口 + token，零环境变量 |
| 远端配置注入 | `setShellEnvVar("RB_*")` + il `getShellEnvVar` | il 常量 / daemon 参数，不碰 Virtuoso 进程环境 |
| 端口分配 | 用户名哈希 | 注册表分配，冲突显式报错 |
| 接口本身 | 现代码三接口 | 只加 `token`，`run_command` 另加 `parallel` |
| 日志返回 | 只回 SKILL 结果，`CDS.log` 人工 tail | 返回值增加 `log` 字段（daemon 侧过滤/限长） |

## 8. 验收要点

1. 上层可用 fake middle 做单测，不需要 `.env`、SSH 或 Virtuoso。
2. local 与 SSH 两种部署下，上层代码、参数和结果语义不变。
3. token 不匹配时 daemon 不写 Virtuoso stdin，SKILL 零接触。
4. 两条独立命令 `parallel=True` 并行执行；默认 `parallel=False` 保持串行顺序。
5. 新代码不依赖 profile 环境变量。
6. 上层代码无 `VB_*`、`.env`、socket、subprocess 引用。
7. 每次 `execute_skill` 返回 `result.log`（本次 CDS.log 增量，已过滤/限长）；超长自动降级 error。

## 9. 非目标

- 不改 daemon ↔ Virtuoso 的内部机制（仍然“收到什么 SKILL 就写进去”）。
- 不改现有返回类型 `VirtuosoResult` / `CommandResult`。
- 不新增第四个接口；`parallel` 只是 `run_command` 的参数。
- 不在本版引入非对称签名 / HMAC；token 生命周期由注册表管理。
- 第一版不做全量 `CDS.log` parser、push stream 或日志数据库，只做同步增量返回。
