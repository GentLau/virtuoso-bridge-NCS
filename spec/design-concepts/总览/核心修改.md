# 核心修改设计

> 版本：Draft v3
> 日期：2026-09-11
> 状态：Informative（只索引，不重复定义）
> 规则：本文件只说明“要改什么”；任何机制、数值、schema、流程的**唯一定义**都在 Normative 文档，本文件不复制，避免第二套口径。

## 1. 五项修改

| # | 修改 | 现状 | 目标 |
|---|---|---|---|
| 1 | 并行机制 | `run_command` 全部串行 | `parallel=False` 串行 / `True` 显式并行；签名见[三层架构 §4.1](三层整体架构设计.md)，机制见[并发处理设计](../底层与中层/并发处理设计.md) |
| 2 | token 机制 | 无 token，事后 guard | 每次调用必传 token；路由/校验/生命周期见[多用户设计](../底层与中层/多用户设计.md) |
| 3 | 注册流程 | `profile`+`.env`+`state.json` | 六步注册 + `registry.json`；流程见[多用户设计 §3.2](../底层与中层/多用户设计.md)，配置见[配置一览](配置一览.md) |
| 4 | 脱离环境变量 | 远端 `setShellEnvVar`/cshrc | 配置写成 il 常量/daemon 参数，远端影响最小；见[多用户设计 §5](../底层与中层/多用户设计.md) |
| 5 | CDSlog 增量返回 | 只回 SKILL 结果 | `VirtuosoResult.log`；offset 定界、分级、限长、`off` 源头掐断见[日志返回设计标准](../底层与中层/日志返回设计标准.md) |

五项修改共同服务：多用户、可并行、配置可控、上层只面对一个逻辑业务服务器。

## 3. 验收要点（索引自各 Normative 文档）

1. 上层可用 fake middle 单测，不依赖 `.env`/SSH/Virtuoso；
2. local/SSH 两种部署下，上层代码、参数、结果语义不变；
3. token 缺失/null/不匹配 → NAK，SKILL 零接触；
4. `parallel=True` 并行、默认串行（含 local 模式，见并发设计 §11.2.0）；
5. 新代码无 `profile`/`VB_*`/`.env` 引用；
6. `execute_skill` 返回 `result.log`；`log=off` 时 IL 不 flush/不读文件/不注入 CDS.log 输出。
