# 顶层：HTTP 入口与业务调度

> 版本：Draft v15
> 日期：2026-09-17
> 状态：Normative（顶层调度与响应壳唯一口径）
> Supersedes：Draft v14（import 白名单收窄为 common.paths）
> 定位：顶层只做入口与调度。业务包与业务操作契约见[上层 §2/§4](../上层/1-上层.md)；分层职责与依赖见[四层整体架构与接口 §3](../总览/1-四层整体架构与接口.md)；五业务接口与错误总则见[四层整体架构与接口 §4](../总览/1-四层整体架构与接口.md)。

## 1. 总述

- 顶层 = HTTPServer：接收请求、每任务一线程（池大小见[顶层补充 §5](add-控制面与业务面.md)）、按注册表选业务包与业务操作、把结果装进响应壳。
- 顶层不做业务：不判断业务语义、不做领域校验（结构校验见 §3）、不编排步骤、不解释结果、不保存状态。
- 顶层与上层的机制契约只有两条：**显式注册表（§2.1）+ 每业务操作一个方法（§2.2）**。
- 限流不是顶层职责：预算由中层按 token 计账（见[并发设计 §2/§3](../中层/2-并发设计.md)），顶层不因预算拒绝请求。

## 2. 注册表与调度

### 2.1 显式注册表

```python
PACKAGES = {
    "virtuoso.schematic.create": (SchematicPackage, "create", SchematicCreateRequest),
    "virtuoso.schematic.read":   (SchematicPackage, "read",   SchematicReadRequest),
    "virtuoso.netlist.import":   (NetlistPackage,   "import_netlist", ImportNetlistRequest),
}
```

- 键 = 业务操作名（命名规则见[上层 §4.2](../上层/1-上层.md)）；值 = `(业务包类, 方法名, Request 模型)`；
- 一个业务包可以出现在多行（每个业务操作一行）；**单操作业务包只登记一行，同样成立**；同一业务操作名重复登记是启动错误；
- 启动时构建一次；**不扫描目录、不用 entry-point**：登记是人的动作；
- 包加载失败即视为**未加载**：其业务操作不进入注册表，调用按未知 `operation` 处理，失败信息写日志；其余包不受影响。

### 2.2 调度顺序

1. 解析请求体，取 `operation` 与 `token`；
2. 未知 `operation`、token 缺失/为空/类型错 → 4xx（§3）；
3. 用登记的 Request 模型构造请求，实例化业务包并调用对应方法；
4. 把结果装进响应壳（§3）。

### 2.3 token

- token 是调用中层的授权凭证：顶层**原样透传**（取出 → 传给业务包 → 传给中层业务接口），不解析、不缓存、不回显；
- 顶层不建"当前用户"概念；合法性与路由由中层判定（见[多用户与注册 §1](../其他/1-多用户与注册.md)）。

### 2.4 中层对象注入

- 业务包构造只接受一个 `Middle`；该对象在**进程装配处**创建并注入，HTTP 处理与调度链路上不创建、不直接调用中层；
- 可测试约束：处理/调度模块只允许标准库、`common.paths`（共享路径基座）、`server.*`、`pyapi.*`；不得出现 `transport.*`、`socket`、`subprocess`、`paramiko`。

## 3. 响应壳与错误分界

```json
{ "ok": true, "data": {}, "error": null }
```

- `ok` 取自业务操作结果；`data` 为业务结果，顶层不解释；`error` 为失败摘要，成功为 `null`。

| 情形 | HTTP | 响应体 |
|---|---|---|
| 非法 JSON、缺 `operation`/`token`、token 类型错 | 4xx | `ok=false`、`error` |
| 未知 `operation` | 4xx | `ok=false`、`error` |
| Request 构造失败（类型/必填/范围） | 4xx | `ok=false`、`error` |
| 业务运行期失败 | 2xx | `ok=false`、`error`、`data` 含步骤痕迹 |
| 业务操作未预期异常 | 5xx | `ok=false`、`error`；不带调用栈 |

- **状态码只表达请求能否被受理**，不表达业务成败；业务失败是结构化结果；失败行（2xx 业务失败除外）`data` 均为 `null`；
- 校验分界：顶层/Request 只做结构校验（JSON、`operation`、`token`、字段类型/必填/范围），失败 → 4xx；上层领域校验失败 → 业务 Result（2xx、`ok=false`），不映射为 5xx；
- 未预期异常必须被顶层捕获：单请求失败不影响其它请求，不终止服务。

## 4. 本层不做

1. 直接访问中层/底层，或自行编排业务步骤；
2. 读 `VB_*`、`.env`、注册表文件；
3. 建立 SSH/TCP/socket/隧道、调用 `subprocess`；
4. 缓存 token 或业务结果、在响应中回显 token；
5. 在请求处理链路上 import 传输实现（见 §2.4）。
