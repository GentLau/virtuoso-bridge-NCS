# 上层：业务包与插件化

> 版本：Draft v7
> 日期：2026-09-16
> 状态：Normative（业务包契约与插件注册唯一口径）
> Supersedes：Draft v6（重试策略由业务包自行决断）
> 定位：五业务接口签名与错误总则见[四层整体架构与接口 §4](../总览/1-四层整体架构与接口.md)；顶层调度见[顶层 §2](../顶层/1-顶层.md)；role 与并发见[路由设计](../中层/3-路由设计.md)、[并发设计](../中层/2-并发设计.md)。

## 1. 总述

- 上层 = 一组业务包。一个业务包 = **一个操作名 + 一个 `run(request) -> Result`**，把一次业务动作拆成若干步骤，业务步骤只调中层五个业务接口（参数准备可调用只读查询 `query`）。
- 以导入网表为例：调用方只发起一个动作，包内执行 `上传网表 → Skill 导入 → Skill 建 symbol`。
- 三个不变量：**同步、无状态、token 原样透传**。

## 2. 业务包契约

### 2.1 形态

```python
@dataclass(frozen=True)
class ImportNetlistRequest:
    token: str
    local_netlist: str
    library: str
    cell: str
    job: str

@dataclass
class ImportNetlistResult:
    ok: bool
    steps: list[dict] = field(default_factory=list)
    error: str | None = None

class ImportNetlistPackage:
    def __init__(self, middle: Middle) -> None:
        self.middle = middle

    def run(self, request: ImportNetlistRequest) -> ImportNetlistResult: ...
```

### 2.2 方法契约

| 项 | 约定 |
|---|---|
| 入口 | 只有 `run(request) -> Result`；返回时业务已结束（成功或已失败） |
| 同步 | 不用协程；不返回任务句柄 |
| 无状态 | 实例每次请求新建；中间数据不在实例属性里 |
| 注入 | 构造只接受 `Middle`；不创建连接/进程/隧道 |

### 2.3 Request / Result

| 字段 | 类型 | 约定 |
|---|---|---|
| `token` | `str` | 必填；每次中层调用原样透传 |
| 业务字段 | 包自定义 | 必须可序列化 |
| `ok` | `bool` | 业务是否成功 |
| `steps` | `list[dict]` | 步骤痕迹（§2.4） |
| `error` | `str` 或 `None` | 失败摘要；成功为 `None` |

### 2.4 步骤痕迹

- 每步记 `{"step": 名, "ok": 布尔, "detail": 中层结果}`；
- 任一步失败**立即停止**，保留全部痕迹；失败不得伪装成成功，也不得只留一句 `error` 丢弃步骤。

## 3. 数据纪律

### 3.1 token 与路径

- `token` 是调用中层接口的授权凭证：业务包每次调用都带上并原样透传，不缓存、不解析；合法性与路由由中层判定；
- 文件路径按业务需要给定，由中层按对应 role 根解析；**同一动作内前后要操作同一个文件时，用同一路径**；
- 需要本 token 的参数事实（`root`/`bin`）时，用[四层整体架构与接口 §4.2](../总览/1-四层整体架构与接口.md)的只读查询 `query`。

### 3.2 状态与长任务

- 不持有跨请求状态：没有内存任务表、缓存或"上次进度"；
- 需要跨请求看见的东西写到业务服务器文件，且可由请求参数确定性定位；
- 长动作拆成多次独立调用：先发起，再按调用方给的参数（如 `job`）发起查询；进度、取消、重试属调用方与顶层；
- 多步 deadline 由业务包内部自行调度：单次中层调用遵循接口 deadline（见[四层整体架构与接口 §5.8](../总览/1-四层整体架构与接口.md)）。

### 3.3 校验与错误

- 调业务接口前完成校验：token 非空、必填、类型、范围；失败抛 `TypeError`/`ValueError`，由顶层按 Request 构造失败映射为 4xx（见[顶层 §3](../顶层/1-顶层.md)）；
- 下层结构化失败按错误总则处置：校验和不一致不忽略；重试策略由业务包自行决断；中层只做传输层透明重试（见[并发设计 §4](../中层/2-并发设计.md)）；
- 失败类别枚举的唯一 owner 见[四层整体架构与接口 §4.5](../总览/1-四层整体架构与接口.md)，本文不复制。

## 4. 插件注册

### 4.1 显式注册

- 注册表结构、构建时机与重复登记错误由[顶层 §2.1](../顶层/1-顶层.md)唯一 owner；
- 加一个包 = 加一个文件 + 加一行登记，不改既有包。

### 4.2 命名与自描述

| 项 | 约定 |
|---|---|
| 操作名 | 点分英文分段（领域.对象.动作）；发布后不改名 |
| 自描述 | 每包导出四个名字：操作名、`Request`、`Result`、`Package` |

### 4.3 失败隔离

- 加载失败只影响该包；运行期未预期异常只影响该次请求；观测形态由顶层 §3 规定。

## 5. 本层不做

1. 导入/接触 `transport.*`、`socket`、`subprocess`、`paramiko`、隧道、端口、注册表、daemon 协议；
2. 读 `VB_*`/`.env`，判断 local/remote；
3. 生成随机且事后无法重建的路径。

## 6. 检查清单

- [ ] import 只有标准库与 `pyapi.*`；
- [ ] 只有 `run(request) -> Result`，同步无状态；
- [ ] Result 含 `ok/steps/error`；失败保留步骤痕迹；
- [ ] 每次中层调用带 Request 里的 token；步骤间 deadline 由包内自行调度；
- [ ] 同一动作内同一文件复用同一路径；
- [ ] 已显式登记，未与既有操作名冲突。
