## 0. 一句话方向

**把 Calibre 包收缩成"官方入口的发起器 + 官方产物的结果分析器"。**
凡是需要理解 Calibre 参数语义、拼引擎命令、翻译 runset 的事情，一律不做或改走官方入口。

## 1. P0：恢复开发必须先做的三件（做完才算"可用"）

### P0-1 `pex` 重做为官方链路（当前是错的，禁止使用）

现状：`_argv_for()` 的 pex 分支自拼 `-xrc -phdb` / `-xrc -pdb -rc` / `-xrc -fmt {spice|simple}`，
与官方不一致；官方对照实验证明**修饰符决定结果**（`-fmt -rcc` vs `-fmt -all -xcell hcells`：
电容 702/0 vs 912/540，RVE 模板行也不同）。

要做的：

1. 有 set → `calibre -gui -pex -runset <set> -batch`（**已实现的官方批处理分支直接复用**）；
2. 无 set → **只允许两种形态**：
   a. 调用方给现成控制文件 + `runset` 之外的显式命令（整条照抄，含 `-xcell <file>`）；
   b. 不支持——宁可明确失败，也不要自拼 argv；
3. 删除 `fmt ∈ {none,spice,simple}`、`-rc` 硬编码、`-phdb` 自拼等一切自创修饰符。

验收：与 GUI/CI 产出的 `.pex.netlist` **逐字节一致（允许仅 DATE 行不同）**；
对照口径直接沿用 04 报告 §4 的器件计数表（总电容 912 / 耦合 540 / MOS 192 / 电阻 15103）。

### P0-2 结果分析改吃"官方产物"（我们唯一该做的部分）

现状 `read_results(pex)` 解析 `pex.stage*.log` 文本；官方链路的真实产物是：

| 产物 | 用途 |
|---|---|
| `<cell>.pex.netlist` | 最终寄生网表（大小/行数/是否存在） |
| `svdb/<cell>.pdb/` | 寄生库分块（pdb1.dat…pdb64.dat、PDB.opened/closed） |
| `.pexf` | `pex_PexParam LAYOUT_PRIMARY / TOOL / CORNER_PDBS` |
| `.lvsf` | LVS 侧元数据：结论、power/ground、报告名、来源网表、规则文件 |
| `<cell>.lvs.report` / `.ext` | LVS 报告 / 器件提取报告 |
| transcript（batch 时=stdout） | `*** xRC run finished with exit code X ***`、`Calibre Interactive Error: …` |

要做的：

1. `read_results` 增加"官方产物"分支：给 `pex.netlist` 路径/大小、pdb 分块数、`.pexf`/`.lvsf` 关键字段；
2. **失败判据换成 transcript 的 exit code 行 + `Calibre Interactive Error:`**，不再靠日志关键字猜；
3. `export` 的 items 增加 `pex_netlist` / `pdb` / `lvsf`（大文件单独点名，不默认全下）。

验收：同一 run 上，`read_results` 报出的计数与 `svdb/*.lvsf`、`.pexf` 内容一致；失败注入（删 hcells）能命中 transcript 错误。

### P0-3 发起前的输入预检（只查存在性，不解释参数）

官方 batch 不建默认文件，缺 hcell/xcell 时 CI 只报一句
`Calibre Interactive Error: : x-Cells File: hcells is not a file`（04 报告 §9 踩坑 1）。

要做的：发起前对 set 里**声明的文件型输入**（layout/source/hcell/xcell/extra source）做远端存在性检查，
缺就结构化失败并列出缺哪个——**这属于"输入检查"，不是参数解释**；预检开关放请求里，默认开。

## 2. P1：稳定性与工程化

| # | 事项 | 说明 |
|---|---|---|
| P1-1 | 许可与并发 | CI batch 占 **1 个 calinteractive license**（04 §2.4）；PEX 不能像 DRC 一样随便并发，需要排队/串行策略与明确报错 |
| P1-2 | TVF 编译预算 | 每个步骤都重新编译 TVF（每段 5–6 s）；超时预算与"Save TVF Rules to SVRF"开关要在文档里写清 |
| P1-3 | set 里的陈旧行 | 别的 cell 的 hcell/xcell/def 必须**删行**（置空无效）——恢复开发时写进排错清单 |
| P1-4 | 日志落盘 | run 目录没有 `calibre.log`；我们的 launcher 抓 stdout 到 `<kind>.log` 正是对一个 CI transcript，保持并文档化 |

## 3. P2：可以以后再做

1. `-nowait` / `-wait n`（许可排队语义）作为请求字段暴露；
2. `-runset_options_display` 审计落盘（"我们实际用了哪些选项"）；
3. 多 runset（后者覆盖前者）与 `-custom` / `-customgui`；
4. PEX standalone（无 set）：等真有需求再评估，**默认不做**；
5. `.calibre.db`（实为 GDSII）与 `layout.gds` 的等价性说明——两者都能填 `xrc.layout.layoutFile.value`，需要一份书面确认。

## 4. 验收计划（恢复开发后按此跑）

1. **离线**：`test/offline/unit/test_calibre_*.py` 全绿（现有 68 用例 + P0 新增契约）；
2. **真机 LVS/DRC 回归**：`python test/live/packages/calibre_e2e_tests.py --transport direct`
   现有 **8/8**（`VB_CALIBRE_REQUIRE_LVS_VERDICT=1`）必须保持；
3. **PEX 对齐（新增 SET-02）**：同一份 set + 输入，`-gui -pex -batch` 跑一遍，与 GUI/CI 基线

4. 证据落 `test/artifacts/evidence/calibre-<主题>-<run-id>/`，报告进 `test/reports/`。
