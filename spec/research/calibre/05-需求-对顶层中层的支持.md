## 3. 明确**不要求**改的

1. **不新增 role / 不新增接口**：calibre 走 command role 的 C/D/U 已够（实测三件套全部跑通）；
2. **不改 `run_command` 的 rc/kind 语义**：包侧用"启动器 + 三重校验"消化不确定性，
   不要求中层为长任务引入 job 句柄（真要做，是另一个独立议题）；
3. **不动 config.json**：calibre 不需要新配置段（§R1–R3 走注册表事实，或继续用 PATH 兜底）。

## 4. 证据（为什么提这几条）

| 现象 | 证据 |
|---|---|
| `query()` 只对 spectre 暴露 `bin` | `src/transport/middle.py:905`；本轮实测 `query()` 对 command role 返回 `bin=None` |
| 启动器 rc/kind 不可信 | 实测启动返回 `rc=1 kind="path"`（子进程日志尚未创建时 `wc` 抢跑）；`cp -r` 超时返回 `kind=unknown-effect` |
| 长任务需要后台 | Calibre DRC 单跑可达数十分钟；前台跑会占满每 token 的串行 command 槽 |
| 需要 job.json/job.pid | 状态判据依赖它们；本包启动器负责写，包只读（无状态） |
| 相关已提交缺陷 | `bug-20260922T092220Z-vblog-5a9d4863`（多进程共用 work-dir 时 commands.log 轮转冲突） |

## 5. 验收建议（改完后怎么测）

1. 注册一个新用户 → `GET /api/...` 或 `query(token=<新 token>)` 能读到 `roles.command.bin`（或 `calibre_bin`）；
2. 把该字段清空 → calibre 包 `check_env` 仍能回退到 PATH 上的 `calibre`（不得因缺字段而失败）；
3. `calibre.drc` 用"非阻塞 + status 轮询"跑一遍，`read_results` 计数与手工基线一致
   （baseline：`rules_checked=1737`、`total_results=36`）。
