## 0. 一句话结论

**Calibre Interactive (GUI) 不是引擎，只是"runset→SVRF 翻译器 + 启动器"。点 Run 的瞬间：①检查源网表完整性 ②（交互式时）从 Virtuoso 导出 GDS/网表 ③把 runset 翻译成 SVRF 控制文件 ④依次 spawn 三条 `calibre` 引擎命令 ⑤引擎 stdout 流回 Transcript pane。引擎从头到尾只认控制文件，不知道 runset 存在。**

GUI 点 Run 后 PEX 实际执行的完整命令（212 batch transcript 第 22–24 行原文，逐字节照录）：

```
$MGC_HOME/bin/calibre -lvs -hier -spice svdb/xz_demux1to8_rvt_tia0.sp -turbo -nowait _SMIC_CalPEX_40ULP_AG1_091125_V1.0_REV1_0.lvs_
$MGC_HOME/bin/calibre -xrc -pdb -rcc -turbo -xcell hcells -nowait _SMIC_CalPEX_40ULP_AG1_091125_V1.0_REV1_0.lvs_
$MGC_HOME/bin/calibre -xrc -fmt -all -xcell hcells -nowait _SMIC_CalPEX_40ULP_AG1_091125_V1.0_REV1_0.lvs_
```

最后一个参数 `_SMIC_CalPEX_40ULP_AG1_091125_V1.0_REV1_0.lvs_` 就是 runset 翻译出的控制文件（注意结尾多一个下划线 `_`）。GUI 交互模式生成完全相同的东西到 run 目录。

**不跑也能看命令**：GUI 里按住 **Ctrl 点 Run** = 只生成控制文件不跑，且官方文档原话："the calibre command line for the run is written to the Transcript pane"。

## 3. GUI 点 Run 的完整事件序列（PEX 为例；nmLVS/nmDRC 同构）

### 第 0 步：GUI 本体的来源（进程链）
```
Virtuoso 版图窗口菜单 Calibre > Run PEX        ← SKILL: queryskl/mgc_calibre_menu.skl（明文，user menu trigger 挂到 maskLayout 窗口）
  → 启动 `calibre -gui -pex`                    ← bin/calibre（明文 shell wrapper, 1715 行）
```

SKILL 侧同时在本机开**服务端 socket 等待 CI 反向连入**。skillREADME §4 原文：
> "The Calibre Skill Interface uses a TCP socket to communicate with Calibre RVE and Calibre Interactive. When you select Run DRC (or LVS) or Start RVE, the code attempts to initialize a server socket at port 9189. If that port is being used, the code searches for a free socket port in the range 5000-9999."
> 可用环境变量 `MGC_CALIBRE_LAYOUT_SERVER=[<host>:]<port>` 控制（host 被忽略，仅为兼容 RVE）。

### 第 3 步：runset → SVRF 控制文件（runset 的"倒入"点，核心）
CI 把 GUI 全部设置翻译成控制文件写进 run 目录。**CI 在每次运行时重新生成**（batch run 里生成的版本时间戳 18:01:49，与 GUI 9/22 版本内容仅差路径/时间戳）。全文见 §6。要点：

## 4. 三条引擎命令逐段解析

### 阶段 1 —— LVS + 布局提取（产出 PHDB）
```
calibre -lvs -hier -spice svdb/<cell>.sp -turbo -nowait <控制文件>
```
| 片段 | 含义 |
|---|---|
| `-lvs` | LVS 引擎模式。控制文件里有 `MASK SVDB DIRECTORY "svdb" QUERY XRC CCI NOPINLOC`，故此 run 是"LVS 比对 + 为 xRC 准备数据库"，非纯 signoff LVS |
| `-hier` | 层次化处理 |
| `-spice svdb/<cell>.sp` | 把提取的版图 SPICE 网表写入 svdb（xRC 后续阶段的输入；LVS 报告里 LAYOUT NAME 就是它） |
| `-turbo` | 多线程层次处理；来自 runset `cmn.turboCommand.runHow = "all"` |
| `-nowait` | license 不可得时不排队等待 |
| 控制文件 | `#!tvf` TVF 包装（VERBATIM + source PDK deck） |

产物：LVS 结果（实测 `LVS completed. CORRECT. See report file: ...`）+ `svdb/` 下 `<cell>.sp`、`<cell>.phdb/`、`<cell>.xdb`、`<cell>.dv/.extf/.hc/.hcells/.lvsf/.pdsp` 等内部库文件。

### 阶段 2 —— 寄生数据库 PDB
```
calibre -xrc -pdb -rcc -turbo -xcell hcells -nowait <控制文件>
```
| 片段 | 含义 |
|---|---|
| `-xrc` | 寄生提取引擎模式 |
| `-pdb` | 建 Parasitic Database（读 PHDB + svdb，计算寄生） |
| `-rcc` | **提取类型修饰符：电阻 + 电容 + 耦合电容（coupling caps）**。由 runset `xrc.pexExtractionType.level = "G"` 翻译而来 |
| `-xcell hcells` | xcell 清单文件（默认名 `hcells`；列出不参与版图寄生提取、按原理图处理的 cell；**空文件时 CI 也照样带上该 flag**） |

产物：`svdb/<cell>.pdb/`（pdb1.dat…pdb64.dat + pdb.seg + PDB.opened/PDB.closed 等分块文件）。

### 阶段 3 —— 格式化最终网表
```
calibre -xrc -fmt -all -xcell hcells -nowait <控制文件>
```
| 片段 | 含义 |
|---|---|
| `-fmt` | 从 PDB 格式化输出网表；格式与文件名由控制文件 `PEX NETLIST "<file>" CALIBREVIEW SOURCENAMES GROUND "avss"` 决定 |
| `-all` | 输出全部寄生器件类型（含耦合电容；netlist 头部 RVE 模板行因此完整：`mgc_rve_parasitic_template "c" "r" "l" "k" "h"`） |

产物：`<cell>.pex.netlist`（本例 1,375,331 字节，17,212 行）。

### 修饰符对照实验（同一控制文件，212 实测器件计数）
| 运行方式 | 总电容 | 耦合电容 | MOS | 电阻 |
|---|---|---|---|---|
| 2026-09-22 用户 GUI run | 912 | 540 | 192 | 15103 |
| 手跑 `-xrc -pdb` + `-xrc -fmt`（无修饰符） | 702 | **0** | 192 | 15103 |
| 手跑 `-pdb -rcc` + `-fmt -rcc` | 912 | 540 | 192 | 15103（但 RVE 模板行少 l/k/h 与部分 device template） |
| **CI 原版** `-pdb -rcc` + `-fmt -all -xcell hcells` | **912** | **540** | 192 | 15103（与 GUI **逐字节一致**） |

**结论：命令行修饰符是"运行内容"的一部分，控制文件本身不完全决定结果。脱离 GUI 复现必须整条命令照抄。**

### nmLVS / nmDRC 对应命令（单阶段；语法来自官方 Command 文档）
```
calibre -lvs [-hier] [-spice 输出.sp] [-turbo] <控制文件或规则文件>   # GUI 点 Run LVS 生成一条
calibre -drc [-hier] [-turbo] <控制文件或规则文件>                    # GUI 点 Run DRC 生成一条
```

## 5. CI（calibre -gui）完整命令语法（官方文档 Command_CalibreGui_idcd0cc803.html）

```
calibre -gui [-drc | -dfm | -lvs | -pex | -perc | -3dstack]
            [-batch]
            (runset | -runset runset | -runset_options_display runset)...
            [-custom filename | -customgui filename]
            [-nowait | -wait n]
```
要点（文档原文要点编译）：
- `-gui` 单独给 → 打开 Calibre Interactive Palette，再从 palette 开具体工具
- `-batch`：不弹窗跑完整流程；**必须给 runset**；不做 Virtuoso 导出，布局/网表须为现成文件；占用 1 个 calinteractive license
- runset 可多个（空格分隔加引号或多次 `-runset`），**后者覆盖前者**；`-runset_options_display <runset>` 额外把该 runset 的变量回显到 transcript（被后续覆盖的项不回显）
- `-custom`：定制文件在 batch 下直接应用；`-customgui`：batch 开头弹定制窗再继续
- `-wait n`：等 license n 分钟；`-nowait` 不等
- 新式 beta 命令行另有 `calibre -gui -n` 系（Command_CalibreInteractiveBetaCommandLine 文档，本次未深入）

## 11. 实用配方（沉淀）

```bash
# 环境（一次性）
export CALIBRE_HOME=/tools/mentor/aoj_2023/aoj_cal_2023.2_16.9
export MGC_HOME=$CALIBRE_HOME PATH=$CALIBRE_HOME/bin:$PATH
export MGLS_LICENSE_FILE=/tools/license/license2.dat:/tools/license/mentor.dat

# 路线 1（推荐，与 GUI 逐字节一致）：GUI 留下的控制文件 + 原版命令
cd <run目录>   # 备齐 .calibre.db + .src.net + empty_subckt.sp + _SMIC_*.lvs_ + 空的 hcells
calibre -lvs -hier -spice svdb/<cell>.sp -turbo <_SMIC_*.lvs_>
calibre -xrc -pdb -rcc -xcell hcells <_SMIC_*.lvs_>
calibre -xrc -fmt -all -xcell hcells <_SMIC_*.lvs_>

# 路线 2（有 runset 想全自动）：batch，transcript 头三行就是命令
calibre -gui -pex -batch -runset <改好的runset> > transcript.log 2>&1

# 想看"GUI 会发什么"而不跑：GUI 里 Ctrl+点 Run（Transcript pane 显示控制文件+命令行）
```

## 12. 残留边界（未竟事项）

1. runset→控制文件的**翻译逻辑代码**在 CALENC 加密 Tcl 内，未逐行审计（试图解 base64+zlib 未成，字符表非标准序）。但"翻译产物（控制文件实物）+ 命令原文 + 结果逐字节一致"三点互证，机制结论不受影响。
2. GUI 交互模式下引擎 argv 拼装顺序（`-turbo`/`-lmtoken`/`-lvs_comm` 位置）可能随版本微调；以引擎自报 `CALIBRE_CMD_LINE=` 为准。
3. DRC/LVS 的单阶段命令未单独 batch 实测（语法来自官方 Command 文档与引擎 usage；与 PEX 共用同一分发逻辑，可信度高）。
4. `-runset_options_display`、`-custom`/`-customgui`、PERC/xACT/3DSTACK 分支未实测。
5. wrapper 的 `run_columbia()`（-xrc -xact SOC 流程，PEX_SOC_COUPLING 等）是 xACT SOC 特殊分支，本次 PEX 流程不经过它。
